Version 1.1.x

Übersicht​

Version 1.1.x ist eine Minor-Release, die kritische Probleme mit der Erkennung überfälliger Backups behebt, die Kompatibilität mit Podman-Containern verbessert und Architekturverbesserungen für Container einführt. Diese Version konzentriert sich auf die Behebung der Genauigkeit bei der Erkennung überfälliger Backups und die Lösung von Netzwerkproblemen in Podman-Umgebungen.

Neue Funktionen​

Benutzeroberflächenverbesserungen​

  • Kontextmenü per Rechtsklick auf den Auto-Aktualisierungsbutton - Ein Rechtsklick auf den Auto-Aktualisierungsbutton in der Anwendungssymbolleiste öffnet die Seite mit den Anzeigeeinstellungen für schnellen Zugriff auf Anzeigeeinstellungen
  • Verbessertes Modal zum Sammeln von Backups - Die Bezeichnung des Passwortfelds zeigt jetzt klar an "(nur ausfüllen, wenn Passwort geändert wurde)", wenn ein Server ausgewählt ist, wodurch klarer wird, wann das Feld benötigt wird

Dokumentationsverbesserungen​

  • Migration der Dokumentation - Die Dokumentation wurde vom Docker-Container-Image zu GitHub Pages unter https://wsj-br.github.io/duplistatus/user-guide/overview verschoben, um die Zugänglichkeit zu verbessern und Aktualisierungen zu vereinfachen
  • Der Link zum Benutzerhandbuch in der App-Kopfzeile verweist nun auf die externe Dokumentationsseite

🐛 Fehlerbehebungen​

Kritisch: Erkennung überfälliger Backups - Vollständige Neuentwicklung​

  • Behobene Erkennung überfälliger Backups - Das System zur Erkennung überfälliger Backups wurde vollständig neu implementiert mit einem neuen Algorithmus, der erwartete Backup-Daten korrekt verfolgt:
    • Der Algorithmus stellt sicher, dass manuelle Backups die geplanten Backup-Zeiten nicht ändern (z.B. ändert ein manuelles Backup um 22 Uhr den 14-Uhr-Plan nicht)
    • Behoben: Spalte "Nächste Ausführung" in den Einstellungen zur Backup-Überwachung zeigt jetzt korrekte Daten an
    • Backup-Einstellungen werden jetzt unmittelbar aktualisiert, nachdem Backups über /api/upload oder /api/backups/collect empfangen wurden
    • Für neue Server ohne Duplicati-Synchronisation wird die Tageszeit des ersten Backups als Plan-Referenz verwendet
    • Weitere Details finden Sie in der Dokumentation zum Algorithmus zur Überfälligkeits-Erkennung

Podman-Container-Fehlerbehebungen​

  • Behobenes Podman-Pod-Netzwerk - Problem behoben, das externen Zugriff auf die Anwendung beim Betrieb in Podman-Pods verhinderte. Der Server bindet sich jetzt korrekt an alle Schnittstellen (0.0.0.0:9666) sowohl im Podman-Pod- als auch im eigenständigen Container-Modus
  • Behobene DNS-Auflösung für Tailscale-Hostnamen - DNS-Auflösungsprobleme in Podman-Containern behoben, die Verbindungen zu Tailscale-Hostnamen oder benutzerdefinierten DNS-Servern verhinderten. Installationsdokumentation wurde mit Anweisungen aktualisiert.

E-Mail-Konfigurationskorrekturen​

  • Behandlung leerer SMTP-Benutzernamen/Passwörter behoben - Problem behoben, bei dem das Leeren der Benutzernamen- oder Passwortfelder in der E-Mail-Konfiguration weiterhin verschlüsselte Werte in der Datenbank speicherte. Leere Felder werden jetzt ordnungsgemäß als leere Zeichenketten gespeichert und können korrekt geleert werden

Systemverbesserungen​

  • Reduziertes Konsolen-Logging - AuditLogger protokolliert jetzt nur noch fehlgeschlagene Anmeldeversuche in der Konsole; alle anderen Audit-Einträge werden nur in die Datenbank geschrieben

🚀 Migrationshinweise​

Von Version 1.0.x​

Beim Upgrade auf Version 1.1.0:

  1. Änderung des Dokumentationsortes - Die Dokumentation wird jetzt auf GitHub Pages gehostet, statt im Docker-Container enthalten zu sein. Der Link zum Benutzerhandbuch in der App-Kopfzeile verweist nun auf die externe Dokumentationsseite

  2. Podman-Container-Konfiguration - Wenn Podman-Pods verwendet werden, stellen Sie sicher, dass die DNS-Konfiguration auf Pod-Ebene mit den Flags --dns und --dns-search festgelegt ist. Die Anwendung funktioniert jetzt korrekt sowohl in Podman-Pods als auch in eigenständigen Containern

  3. Erkennung überfälliger Backups - Das System zur Erkennung überfälliger Backups wurde vollständig neu implementiert mit einem neuen Algorithmus, der die Tageszeit des Plans beibehält. Bestehende Konfigurationen zur Backup-Überwachung funktionieren weiterhin, aber Sie bemerken möglicherweise genauere "Nächste Ausführung"-Daten in den Einstellungen zur Backup-Überwachung. Der neue Algorithmus stellt sicher, dass manuelle Backups die geplanten Backup-Zeiten nicht verschieben

  4. Keine Datenbankmigration erforderlich - Diese Version erfordert keine Änderungen am Datenbankschema

API-Endpunkte​

In dieser Version wurden keine neuen API-Endpunkte hinzugefügt. Alle bestehenden Endpunkte bleiben unverändert.

Fehler melden​

Beim Melden von Fehlern bitten wir Sie Folgendes anzugeben:

  • Version: 1.1.x (genaue Version angeben, z.B. 1.1.0)
  • Betriebssystem und Version
  • Docker/podman-Version
  • Containertyp (Docker oder podman/Pod)
  • Fehlermeldungen und Protokolle
  • Schritte zur Reproduktion
  • Podman-Konfigurationsdetails (falls in podman/Pod ausgeführt)

Änderungsprotokoll​

Änderungen in Version 1.1.0​

  • Hinzugefügt: Rechtsklick-Kontextmenü auf der Schaltfläche zum automatischen Aktualisieren, um die Anzeigeeinstellungen zu öffnen
  • Hinzugefügt: Verbesserte Kennwortfeldbezeichnung im Modal zum Sammeln von Backups
  • Geändert: Dokumentation aus dem Docker-Container-Image entfernt (jetzt auf GitHub Pages gehostet)
  • Geändert: App-Header-Benutzerhandbuch-Link aktualisiert, um auf die GitHub Pages-Dokumentation zu verweisen
  • Geändert: Konsolenprotokollierung von AuditLogger reduziert (nur fehlgeschlagene Anmeldeversuche werden in der Konsole protokolliert)
  • Behoben: Kritische Erkennung überfälliger Backups durch ordnungsgemäße Implementierung der erwarteten Backup-Datumsverfolgung (siehe Algorithmus zur Überfälligkeitserkennung für Details)
  • Behoben: Netzwerkprobleme bei Podman-Pods, die externen Zugriff verhinderten
  • Behoben: DNS-Auflösung für Tailscale-Hostnamen in Podman-Containern
  • Behoben: SMTP-Konfiguration speichert verschlüsselte Werte für leere Benutzernamen- und Passwortfelder
  • Behoben: Spalte "Nächste Ausführung" in den Backup-Überwachungseinstellungen zeigt falsche Daten an
