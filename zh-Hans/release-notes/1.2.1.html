版本 1.2.1

概述​

版本 1.2.1 是一个次要发布版本，引入了对备份通知管理的重大增强，改进了审计日志功能，修复了边缘情况下的下次运行/超时检测，并添加了数据库备份和恢复功能。此版本专注于改善通知设置的用户体验。

新功能​

增强的备份通知管理​

  • 服务器级默认值和继承系统：在服务器级别配置所有备份自动继承的默认其他目标（通知事件、电子邮件和 NTFY 主题）。备份可以根据需要覆盖这些默认值，并有清晰的视觉指示器显示继承状态。
  • 改进的视觉层次：备份现在按服务器分组，具有明显的服务器标题行。继承的值用链接图标清楚标记，覆盖的值可以轻松还原为继承。
  • 批量操作："同步所有"按钮清除所有备份覆盖，使所有备份都从服务器默认值继承。"清除所有"按钮清除所有其他目标，同时保持继承结构。
  • 测试功能：在备份通知设置页面中直接添加了测试电子邮件和测试通知按钮。测试按钮适用于单个备份设置和批量编辑操作，允许您在应用更改之前验证通知传递。
  • 二维码支持：为 NTFY 主题添加了二维码按钮，便于与移动设备共享通知主题。

通知模板增强​

  • 新增 {log_text} 变量：在通知模板中添加了 {log_text} 变量，提供对日志文本消息的访问以用于通知消息。该变量包含警告和错误的完整文本，格式化为纯文本，每行一项。
  • 自动模板迁移：系统包含延迟升级机制，可在升级后首次读取时自动检测并更新旧的默认模板。自定义模板保持不变。

数据库管理​

  • 数据库备份功能：管理员现在可以从数据库维护设置页面创建整个数据库的备份。支持二进制（.db）和 SQL 文本（.sql）格式以提供灵活性。
  • 数据库恢复功能：从先前创建的备份文件恢复数据库，具有自动安全备份创建、完整性验证和失败回滚功能。恢复后清除所有会话以确保安全。

主密钥检测​

  • 自动主密钥变更检测：登录后，系统会自动检查 .duplistatus.key 文件是否已更改。如果检测到，所有加密密码将被清除，并弹出模态窗口告知用户需要重新配置密码。这可防止在从备份恢复或迁移到新系统时出现错误。

备份监控改进​

  • 增强的 CSV 导出：在备份监控设置中的"下载 CSV"按钮生成的 CSV 文件中添加了"最后备份时间戳（数据库）"列。这允许用户比较数据库中的实际最后备份时间戳与配置的"最后备份"时间戳。
  • 下次运行工具提示：悬停在每行的"下次运行"值上现在会显示一个工具提示，显示来自数据库的最后备份时间戳，格式与"下次运行"显示相同。

审计日志增强​

  • 独立通知审计条目：现在每个发送的通知和电子邮件都会生成一个单独的审计日志条目，包含有关通道、配置和结果（成功或失败）的详细信息。这包括测试通知，为通知传递提供更好的可追溯性。
  • 强大的故障日志记录：现在所有通知故障的审计日志操作都包装在 try-catch 块中，以防止审计日志错误中断通知流程。系统会在记录电子邮件故障时尝试获取 SMTP 配置（如果无法立即获得）。
  • 改进的配置更新审计日志：email_config_updated 和 ntfy_config_updated 审计日志条目现在仅在配置实际发生更改时才进行记录。检测到更改时，审计日志会包含每个修改字段的旧值和新值，便于跟踪具体更改内容。

文档改进​

  • 文档样式已更新，以与应用程序的外观保持一致。侧边栏也进行了修订，以提高可见性并使导航更加便捷。

🐛 错误修复​

  • 修复了审计日志时间戳：审计日志查看器中的时间戳现在正确显示在用户的浏览器时区中，而不是 GMT。SQLite 时间戳（存储在 UTC 中）现在被正确解析为 UTC 并转换为浏览器的本地时区进行显示。
  • 修正了"下次运行"计算和逾期检测：备份监控设置中的"下次运行"列现在准确计算并显示下次预期备份日期，同时考虑备份计划和最后备份时间戳。这适用于计划运行和手动运行的备份作业，从而实现更可靠的逾期检测。

🚀 迁移说明​

从版本 1.1.x​

升级到版本 1.2.1 时：

  1. 通知模板：系统将在升级后首次访问时自动更新默认通知模板，以包含新的 {log_text} 变量。自定义模板将保持不变。如果您希望在自己的模板中使用新的 {log_text} 变量，则需要手动更新它们或恢复默认模板。

  2. 主密钥更改：如果您从备份恢复或迁移到具有不同 .duplistatus.key 文件的新系统，系统将自动检测此情况并提示您重新配置加密密码（SMTP 密码和 duplicati 服务器密码）。

  3. 数据库备份/恢复：数据库维护设置页面中提供了新的数据库备份和恢复功能。建议在升级前创建备份，尽管此版本不需要任何数据库架构更改。

  4. 无需数据库迁移：此版本不需要任何数据库架构更改。

API 端点​

以下 API 端点在此版本中引入。

身份验证和安全端点​

  • GET /api/auth/admin-must-change-password - 检查管理员用户是否必须更改密码

数据库管理端点​

  • GET /api/database/backup - 创建数据库备份（二进制或 SQL 格式）
  • POST /api/database/restore - 从备份文件恢复数据库

备份管理端点​

  • GET /api/backups/last-timestamps - 获取所有服务器-备份组合的最后备份时间戳

更新日志​

版本 1.2.1 变更​

  • 新增：备份通知的服务器级默认设置和继承系统
  • 新增：备份通知设置中的测试邮件和测试通知功能
  • 新增：NTFY 主题的二维码按钮
  • 新增：备份监控 CSV 导出中的"最后备份时间戳（数据库）"列
  • 新增：备份监控设置中"下次运行"文本的工具提示
  • 新增：每次发送的通知和邮件的单独审计日志条目
  • 新增：通知失败的增强审计日志健壮性
  • 新增：通知模板中的 {log_text} 变量及自动模板迁移
  • 新增：主密钥文件更改的自动检测
  • 新增：数据库备份功能（二进制和 SQL 格式）
  • 新增：数据库恢复功能，包含安全备份和完整性验证
  • 新增：API 端点 GET /api/auth/admin-must-change-password 用于检查管理员密码更改要求
  • 新增：API 端点 GET /api/database/backup 用于创建数据库备份
  • 新增：API 端点 POST /api/database/restore 用于从备份恢复数据库
  • 新增：API 端点 GET /api/backups/last-timestamps 用于检索最后备份时间戳
  • 变更：改进了邮件和 NTFY 配置更新的审计日志（仅记录实际更改）
  • 变更：显示未掩码密码时，密码更改表单不再需要确认。
  • 变更：关闭密码更改表单时，密码会从内存中安全清除。
  • 变更：在收集备份表单中包含了密码查看切换功能。
  • 变更：{server_alias} 变量现在在括号中显示服务器名称
  • 变更：文档已更新，样式与应用程序对齐且侧边栏已重构。
  • 修复：审计日志时间戳显示为 GMT 而不是浏览器时区
  • 修复：邮件和 NTFY 失败审计日志
  • 修复：备份监控设置中"下次运行"显示不正确日期
