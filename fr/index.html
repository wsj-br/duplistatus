Open source · Auto-hébergé · Prêt pour Docker

Toutes vos sauvegardes. Un seul tableau de bord.

Ne vous connectez plus à chaque interface web Duplicati une par une. duplistatus surveille chaque serveur et tâche depuis un écran unique — pour savoir que vos sauvegardes sont en ordre avant qu'une perte de données ne vous prenne au dépourvu.

duplistatus utilise les rapports HTTP intégrés de Duplicati, il n'y a donc rien à installer sur vos machines de sauvegarde.

La seule question qui compte

Toutes mes sauvegardes vont-elles bien ? Un seul écran vous répond, pour chaque serveur, chaque tâche et chaque exécution.

localhost:9666

Conçu pour ceux qui exécutent Duplicati sur plusieurs machines

Que vous utilisiez un NAS, un ordinateur portable, un VPS ou deux serveurs domestiques, duplistatus les regroupe tous sur un seul écran.

01

Visualisez chaque sauvegarde d'un coup d'œil

Une carte par serveur affiche les 10 dernières exécutions de chaque tâche. Passez à un tableau triable lorsque vous avez de nombreux serveurs, et ouvrez n'importe quelle exécution pour lire son journal complet, y compris les avertissements et les erreurs.

  • Totaux pour les serveurs, les tâches, les exécutions, la taille et le stockage
  • Tableau de bord à actualisation automatique pour une expérience de mur vidéo
  • Vérification de la version du serveur Duplicati par rapport à la dernière version publiée sur GitHub
Lire le guide du tableau de bord
02

Détectez les problèmes avant qu'ils ne se transforment en perte de données

duplistatus détecte automatiquement les sauvegardes en retard, en avertissement et en échec, et vous alerte par notification push ntfy ou e-mail SMTP.

  • Les vérifications des retards s'exécutent périodiquement par défaut
  • Recevez des notifications pour chaque tâche avec des filtres par tâche : désactivé, tout, avertissements ou erreurs
  • Réduisez le bruit des notifications grâce à l'e-mail de Résumé quotidien.
Lire les informations sur la surveillance des sauvegardes
03

Dépanner en toute confiance

Ouvrez n'importe quelle exécution pour lire son journal, avec les avertissements et les erreurs, et voir les points de récupération disponibles. Des graphiques pour la durée, la taille et le stockage sont disponibles lorsque vous souhaitez plus de détails.

  • Collecte automatique des journaux depuis vos serveurs Duplicati
  • Versions disponibles affichées pour chaque exécution
  • Graphiques pour la durée, la taille et le stockage

De zéro à opérationnel en quatre étapes

Le déploiement conteneurisé vous permet d'être opérationnel en quelques minutes, et non en plusieurs heures.

Étape 1

Déployer le conteneur

Récupérez l'image depuis Docker Hub ou GitHub, définissez votre fuseau horaire et montez un volume de données. L'interface utilisateur web écoute sur le port 9666. Les migrations de schéma s'appliquent automatiquement au démarrage.

Démarrer
Guide d'installation
Étape 2

Pointez Duplicati vers duplistatus

Configurez chaque serveur Duplicati pour envoyer des rapports JSON via POST vers /api/upload. Ensuite, collectez l'historique des journaux afin que les intervalles de surveillance soient renseignés automatiquement. 

--send-http-json-urls=http://host:9666/api/upload
--send-http-log-level=Information
--send-http-max-log-lines=500
Configuration de Duplicati
Étape 3

Configurer les alertes

ntfy est déjà configuré. Remplacez le sujet par le vôtre, puis scannez le code QR généré par duplistatus pour le configurer sur votre téléphone.
Configurez les paramètres du serveur de messagerie pour commencer à recevoir des e-mails de duplistatus.

Paramètres de notification
Étape 4

Laissez duplistatus surveiller vos sauvegardes

duplistatus se charge de la surveillance. Si une sauvegarde est en retard, ou se termine avec des avertissements ou des erreurs, vous recevez une notification ou un e-mail.
Pour plus de sérénité, activez le Résumé quotidien optionnel : vous le recevez tous les jours, même quand tout va bien.

Guide de l'utilisateur

Sécurisé par défaut. Ajoutez une protection supplémentaire quand vous en avez besoin.

La connexion est activée dès le premier démarrage, ce qui protège votre homelab privé d'entrée de jeu. Ajoutez des clés API et des listes d'adresses IP autorisées quand vous l'exposez à Internet.

Connexion avec des rôles

Connectez-vous en tant qu'Admin ou Utilisateur. Limitez les serveurs visibles par chaque utilisateur.

Clés API

Des clés distinctes pour les téléversements Duplicati et pour les tableaux de bord ou widgets en lecture seule, avec des limites de taille de téléversement et de débit.

Listes d'adresses IP autorisées

Deux listes d'autorisation indépendantes : une pour l'interface d'administration, une pour les API externes. Elles protègent contre l'usurpation d'IP client quand duplistatus fonctionne derrière un proxy inverse.

Protection CSRF

Les routes basées sur des sessions sont protégées contre les attaques par falsification de requête intersites (CSRF).

Journalisation d'audit

Chaque modification de configuration et action utilisateur est enregistrée. Filtrez, exportez et définissez la durée de conservation des enregistrements.

Journaux de l'application

Une visionneuse réservée aux administrateurs vous permet de rechercher, filtrer et exporter les journaux de l'application, avec des mises à jour en direct.

Vous l'exposez à Internet ? Exécutez-le derrière un proxy inverse avec HTTPS. Lire le guide

Démarrez en quelques minutes

Récupérez l'image, montez un volume de données et ouvrez le port 9666. 

# download the compose file
wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
# start the container
docker compose -f duplistatus.yml up -d
# duplistatus production compose.yml
services:
  duplistatus:
    image: ghcr.io/wsj-br/duplistatus:latest
    container_name: duplistatus
    restart: unless-stopped
    environment:
      - TZ=Europe/London
      - PWD_ENFORCE=true
      - PWD_MIN_LEN=8
    ports:
      - "9666:9666"
    volumes:
      - duplistatus_data:/app/data
    networks:
      - duplistatus_network

networks:
  duplistatus_network:
    driver: bridge

volumes:
  duplistatus_data:
    name: duplistatus_data
# Create the volume
docker volume create duplistatus_data

# Start the container
docker run -d \
  --name duplistatus \
  -p 9666:9666 \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -v duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest
mkdir -p ~/duplistatus_data
# Start the container (standalone)
podman run -d \
  --name duplistatus \
  --userns=keep-id \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -p 9666:9666 \
  -v ~/duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest

Une fois le conteneur démarré :

  1. 1 Ouvrez http://localhost:9666 dans votre navigateur
  2. 2 Connectez-vous avec le compte admin par défaut. Il vous sera demandé de modifier le mot de passe admin par défaut lors de la première connexion.
  3. 3 Connectez vos serveurs Duplicati en suivant ces instructions, puis utilisez Collecter les journaux de sauvegarde pour importer l'historique
  4. 4 Vous l'exposez à Internet ? Ajoutez une protection supplémentaire en activant les clés API et les listes d'adresses IP autorisées, et placez-le derrière un proxy inverse avec HTTPS.
