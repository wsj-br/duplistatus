# 版本 0.9.x {/* #version-09x */}

## 概述 {/* #overview */}

版本 0.9.x 是一个重大发布，引入了全面的**用户访问控制和安全系统**。此发布将**duplistatus**从开放访问应用程序转变为具有基于角色的访问控制、全面审计日志记录和企业级安全功能的安全多用户系统。所有现有功能现在都受到身份验证保护，确保只有授权用户才能访问和管理备份监控。

## 重大变更 {/* #breaking-changes */}

### 需要身份验证 {/* #authentication-required */}

- **所有页面现在都需要身份验证** - 用户必须登录才能访问应用程序
- **默认管理员账户**会自动创建：
  - 用户名：`admin`
  - 密码：`Duplistatus09`（首次登录时必须更改）
- **现有会话被失效** - 升级后所有用户必须登录
- **API 端点现在需要身份验证** - 外部集成必须包含会话 cookie 或使用经过身份验证的请求

:::warning
**升级到版本 0.9.x 后，所有用户必须登录。** 默认管理员凭据为 admin/Duplistatus09。首次登录后请立即更改密码。
:::

### 数据库模式迁移 {/* #database-schema-migration */}

- **现有安装从 v3.1 自动迁移到 v4.0**
- **新增表**：`users`、`sessions`、`audit_log`
- 迁移前**自动创建数据库备份**
- **新安装**直接以架构 v4.0 开始（无需迁移）

## 新功能 {/* #new-features */}

### 用户访问控制和安全系统 {/* #user-access-control--security-system */}

#### 身份验证系统 {/* #authentication-system */}

- 具有安全会话管理的**用户登录/登出功能**
- 使用 bcrypt 哈希（成本因子 12）的**基于密码的身份验证**
- **账户锁定机制**（5 次失败尝试，15 分钟锁定）
- 首次登录时**强制更改密码**
- **密码策略强制执行**：
  - 最少 8 个字符
  - 至少一个大写字母
  - 至少一个小写字母
  - 至少一个数字
  - 特殊字符可选
- **"记住我"功能**，使用 localStorage 持久化用户名
- **基于会话的身份验证**，使用数据库支持的会话（替换内存中会话）
- **CSRF 保护**与身份验证集成
- 用于会话安全的**仅 HTTP cookie**
- 用于安全监控的**IP 地址和用户代理跟踪**

#### 用户管理（仅管理员） {/* #user-management-admin-only */}

- 具有自动生成临时密码的**用户创建**
- 具有搜索、分页和筛选的**用户列表**
- **用户编辑**（用户名、管理员状态、密码更改要求）
- 具有临时密码显示的**密码重置功能**
- 具有保护措施的**用户删除**（防止删除最后一个管理员）
- **基于角色的访问控制**（管理员/用户角色）
- **状态指示器**（活动、已锁定、必须更改密码）
- **最后登录跟踪**和显示

#### 审计日志系统 {/* #audit-logging-system */}

- 所有系统更改和用户操作的**全面审计跟踪**
- 具有高级筛选的**审计日志查看器**：
  - 日期范围筛选
  - 用户筛选
  - 操作筛选
  - 类别筛选
  - 状态筛选
- **导出功能**（CSV 和 JSON 格式）
- **审计日志统计**和分析
- **可配置的保留期限**（30-365 天，默认为 90 天）
- **自动清理 cron 任务**（每天世界标准时间凌晨 2 点运行）
- **支持试运行的手动清理 API**
- **审计日志记录**包括：
  - 认证事件（登录、登出、密码更改、账户锁定）
  - 用户管理操作（创建、更新、删除、密码重置）
  - 配置更改（电子邮件、NTFY、模板、超时容忍度、备份设置）
  - 备份操作（收集、删除、清理）
  - 服务器管理（添加、更新、删除）
  - 系统操作（迁移、清理、通知）

### 设置页面重新设计 {/* #settings-page-redesign */}

- **现代化侧边栏导航**，支持折叠侧边栏
- **用户特定的侧边栏状态持久化**（每个用户的折叠/展开偏好设置被保存）
- **分组设置区域**：
  - **通知**：备份通知、备份监控、模板
  - **集成**：NTFY、电子邮件
  - **系统**：服务器、用户（仅管理员）、审计日志
- **固定侧边栏**，滚动时保持可见
- **响应式设计**，优化间距
- **侧边栏标题中的设置图标和“系统设置”标题**
- **返回按钮**集成到应用头部

### 用户界面增强 {/* #user-interface-enhancements */}

- **独立登录页面**，采用现代设计
- **登录表单上的“记住我”复选框**，用于用户名持久化
- **登录和密码更改表单上的显示/隐藏密码按钮**
- **更改密码模态框**，带有实时验证检查列表
- **应用头部中的用户指示器和登出按钮**
- **基于角色的 UI 可见性**（普通用户看不到仅限管理员的功能）
- **整个 UI 中的状态徽章和指示器**
- **存储在 localStorage 中的用户特定偏好**（例如，侧边栏折叠状态）

### 安全功能 {/* #security-features */}

- **使用 bcrypt 的密码哈希**（行业标准）
- **审计日志中的敏感数据清理**（密码、令牌、密钥从不记录）
- **登录尝试的速率限制**
- **会话过期**（24 小时）
- **所有状态更改操作的 CSRF 令牌验证**
- **用于密码重置的管理员恢复 CLI 工具**（如果被锁定）

### 开发者工具 {/* #developer-tools */}

- **管理员恢复 CLI 脚本**（`admin-recovery`），便于在 Docker 容器中执行
- **本地和 Docker 中都可用**，具有自动路径检测
- **全面的 TypeScript 接口**（无 `any` 类型）
- **用于路由保护的身份验证中间件**
- **审计日志记录实用程序类**，带有便捷方法

## 🚀 迁移说明 {/* #-migration-notes */}

### 从版本 0.8.x {/* #from-version-08x */}

此版本引入了身份验证，要求所有用户登录。从版本 0.8.x 升级时：

1. **自动数据库迁移**：应用程序将自动将您的数据库架构从 v3.1 迁移到 v4.0
2. **数据库备份**：迁移前会创建自动备份
3. **默认管理员账户**：创建一个默认管理员账户：
   - 用户名：`admin`
   - 密码：`Duplistatus09`
   - **您必须在首次登录时更改此密码**
4. **会话失效**：所有现有会话都将失效
5. **需要用户登录**：升级后所有用户都必须登录
6. **API 身份验证**：外部集成必须更新以包含身份验证

### 安全注意事项 {/* #security-considerations */}

- **更改默认密码**：首次登录后立即更改默认管理员密码
- **创建用户账户**：为每个需要访问权限的人创建单独的用户账户
- **查看审计日志**：定期检查审计日志以进行安全监控
- **配置保留期限**：根据您的合规要求设置适当的审计日志保留期限
- **备份主密钥**：如果从 0.8.x 升级，请确保已备份 `.duplistatus.key` 文件

### 首次登录步骤 {/* #first-login-steps */}

1. 使用默认凭据（`admin` / `Duplistatus09`）**登录**
2. 提示时**更改密码**（首次登录强制执行）
3. 为其他用户**创建用户账户**（设置 → 用户）
4. 如需要**配置审计日志保留**（设置 → 审计日志）
5. **查看审计日志**以验证系统正常工作

## API 端点 {/* #api-endpoints */}

### 身份验证端点 {/* #authentication-endpoints */}

- `POST /api/auth/login` - 用户身份验证
- `POST /api/auth/logout` - 会话终止
- `GET /api/auth/me` - 当前用户信息
- `POST /api/auth/change-password` - 更改密码

### 用户管理端点（仅管理员） {/* #user-management-endpoints-admin-only */}

- `GET /api/users` - 列出用户
- `POST /api/users` - 创建用户
- `PATCH /api/users/{id}` - 更新用户
- `DELETE /api/users/{id}` - 删除用户

### 审计日志端点 {/* #audit-log-endpoints */}

- `GET /api/audit-log` - 查询审计日志
- `GET /api/audit-log/download` - 导出审计日志
- `GET /api/audit-log/stats` - 审计统计
- `POST /api/audit-log/cleanup` - 手动清理（仅管理员）
- `GET /api/audit-log/retention` - 获取保留设置
- `PATCH /api/audit-log/retention` - 更新保留（仅管理员）

:::note
所有 API 端点现在都需要身份验证。有关身份验证的详细信息，请参阅 [API 参考](../api-reference/authentication-security.md)。
:::
