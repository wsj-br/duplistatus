# 版本 1.2.1 {/* #version-121 */}

## 概述 {/* #overview */}

版本 1.2.1 是一个小版本，它引入了显著的备份通知管理增强功能，改进了审计日志功能，修复了边缘情况下的下次运行/过期检测，并添加了数据库备份和恢复功能。该版本专注于改善用户通过通知设置的体验。

## 新功能 {/* #new-features */}

### 增强的备份通知管理 {/* #enhanced-backup-notifications-management */}

- **服务器级默认值和继承系统**：在服务器级别配置默认的其他目标（通知事件、电子邮件和 NTFY 主题），所有备份都会自动继承。备份可以根据需要覆盖这些默认值，并通过清晰的视觉指示器显示继承状态。
- **改进的视觉层次**：备份现在按服务器分组，具有不同的服务器标题行。继承的值用链接图标标记，可以轻松将覆盖的值恢复为继承。
- **批量操作**：“同步所有”按钮清除所有备份覆盖，使所有备份都从服务器默认值继承。“清除所有”按钮清除所有其他目标，同时保持继承结构。
- **测试功能**：在备份通知设置页面中添加了测试电子邮件和测试通知按钮。测试按钮适用于单个备份设置和批量编辑操作，允许您在应用更改之前验证通知传递。
- **二维码支持**：为 NTFY 主题添加了二维码按钮，以便轻松与移动设备共享通知主题。

### 通知模板增强 {/* #notification-template-enhancements */}

- **新 `{log_text}` 变量**：在通知模板中添加了 `{log_text}` 变量，提供对日志文本消息的访问，以便在通知消息中使用。该变量包含警告和错误的完整文本，格式为纯文本，每行一个项目。
- **自动模板迁移**：系统包括一个惰性升级机制，在升级后首次读取旧默认模板时自动检测并更新。自定义模板保持不变。

### 数据库管理 {/* #database-management */}

- **数据库备份功能**：管理员现在可以从数据库维护设置页面创建整个数据库的备份。支持二进制（.db）和 SQL 文本（.sql）格式，以提供灵活性。
- **数据库恢复功能**：从先前创建的备份文件中恢复数据库，自动创建安全备份，验证完整性，并在失败时回滚。恢复后清除所有会话以确保安全。

### 主密钥检测 {/* #master-key-detection */}

- **自动主密钥更改检测**：登录后，系统会自动检查 `.duplistatus.key` 文件是否已更改。如果检测到更改，所有加密密码都将被清除，并弹出模态窗口通知用户需要重新配置密码。这可以防止从备份或迁移到新系统时出现错误。

### 备份监控改进 {/* #backup-monitoring-improvements */}

- **增强的 CSV 导出**：在备份监控设置页面中，通过“下载 CSV”按钮生成的 CSV 文件中添加了“最后备份时间戳（DB）”列。这允许用户将数据库中的实际最后备份时间戳与配置的“最后备份”时间戳进行比较。
- **下次运行工具提示**：在每行的“下次运行”值上悬停时，会显示一个工具提示，显示数据库中的最后备份时间戳，格式与“下次运行”显示相同。

### 审计日志增强 {/* #audit-logging-enhancements */}

- **单独的通知审计日志条目**：现在每个通知和电子邮件发送都会生成一个单独的审计日志条目，其中包含有关通道、配置和结果（成功或失败）的详细信息。这包括测试通知，为通知传递提供了更好的可追溯性。
- **强大的失败日志记录**：所有通知失败的审计日志操作现在都包含在try-catch块中，以防止审计日志错误中断通知流程。如果在记录电子邮件失败时SMTP配置不可用，系统会尝试检索SMTP配置。
- **改进的配置更新审计日志记录**：`email_config_updated`和`ntfy_config_updated`审计日志条目现在仅在配置发生实际更改时才记录。当检测到更改时，审计日志会包含每个修改字段的旧值和新值，使得更容易跟踪具体发生了什么变化。

### 文档改进 {/* #documentation-improvements */}

- 文档风格已更新，以与应用程序的外观和感觉保持一致。侧边栏也已修订，以提高可见性并使导航更容易。

## 🐛 错误修复 {/* #-bug-fixes */}

- **修正审计日志时间戳**：审计日志查看器中的时间戳现在正确显示在用户浏览器的时区中，而不是GMT。SQLite时间戳（存储在UTC中）现在被正确解析为UTC，并转换为浏览器的本地时区以供显示。
- **修正“下次运行”计算和过期检测**：备份监控设置中的“下次运行”列现在准确计算并显示下一个预期的备份日期，考虑到备份计划和最后备份时间戳。这适用于计划备份和手动运行的备份作业，从而实现更可靠的过期检测。

## 🚀 迁移说明 {/* #-migration-notes */}

### 从版本1.1.x {/* #from-version-11x */}

升级到版本1.2.1时：

1. **通知模板**：系统将在升级后首次访问时自动更新默认通知模板以包含新的`{log_text}`变量。自定义模板将保持不变。如果您希望在自己的模板中使用新的`{log_text}`变量，则需要手动更新它们或恢复默认模板。

2. **主密钥更改**：如果您从备份中恢复或迁移到具有不同`.duplistatus.key`文件的新系统，系统将自动检测到这一点，并提示您重新配置加密密码（SMTP密码和Duplicati服务器密码）。

3. **数据库备份/恢复**：新的数据库备份和恢复功能在数据库维护设置页面中可用。建议在升级之前创建备份，尽管此版本不需要数据库架构更改。

4. **无需数据库迁移**：此版本不需要任何数据库架构更改。

## API 端点 {/* #api-endpoints */}

此版本中引入了以下API端点。

### 认证和安全端点 {/* #authentication--security-endpoints */}

- `GET /api/auth/admin-must-change-password` - 检查管理员用户是否必须更改密码

### 数据库管理端点 {/* #database-management-endpoints */}

- `GET /api/database/backup` - 创建数据库备份（二进制或SQL格式）
- `POST /api/database/restore` - 从备份文件恢复数据库

### 备份管理端点 {/* #backup-management-endpoints */}

- `GET /api/backups/last-timestamps` - 获取所有服务器备份组合的最后备份时间戳
