# 版本 0.8.x {/* #version-08x */}

## 概述 {/* #overview */}

版本 0.8.x 是一次重大更新，引入了重要的安全增强功能、改进的服务器管理功能以及支持 SMTP 电子邮件的全面通知系统。此版本发布专注于加强安全性、提升用户体验并提供更灵活的备份监控选项。

## 新功能 {/* #new-features */}

### 服务器管理增强功能 {/* #server-management-enhancements */}

- **自动保存服务器 URL 和密码** 以便收集备份
  - 用户可以使用两种方法更新 URL 和密码：
     - 使用更新后的值重新收集备份
     - 在 [设置 → 服务器设置](../user-guide/settings/server-settings.md) 中修改设置

### 增强的备份监控 {/* #enhanced-backup-monitoring */}

- **新的 `Backup monitoring` 配置标签页**，具有与 Duplicati 服务器兼容的时间间隔设置
    - 支持自定义时间间隔（例如，"1D12h"）
    - 在收集备份日志期间从 Duplicati 配置自动更新逾期时间间隔
    - **建议：** 在 Duplicati 服务器中更改备份作业时间间隔后运行收集以同步 duplistatus 配置
    - 通知模板现在使用 `{backup_interval}` 而不是 `{backup_interval_value}` 和 `{backup_interval_type}`。

### NTFY 设备配置 {/* #ntfy-device-configuration */}

- **二维码生成** 用于自动设备配置以接收来自 **duplistatus** 的通知
   - 右键单击应用程序工具栏中的 `View NTFY Messages` 按钮
   - [设置 → NTFY 设置](../user-guide/settings/ntfy-settings.md) 中的 "配置设备" 按钮

### 改进的备份收集 {/* #improved-backup-collection */}

- **自动 HTTP/HTTPS 检测**，按以下顺序尝试连接：HTTPS → 自签名 HTTPS → HTTP 回退
- **服务器选择下拉菜单** 在 `Collect Backup Logs` 界面中用于直接针对特定服务器收集
- **主机名中接受多个地址**（逗号分隔）（必须共享相同的密码和端口）
- **单服务器备份收集按钮** 添加到 `Dashboard (table)`、[设置 → 备份监控](../user-guide/settings/backup-monitoring-settings.md) 和 [设置 → 服务器](../user-guide/settings/server-settings.md)
- **批量收集功能** 用于所有具有有效配置（url 和密码）的服务器
   - [设置 → 备份监控](../user-guide/settings/backup-monitoring-settings.md) 和 [设置 → 服务器](../user-guide/settings/server-settings.md) 中的 `Collect All` 按钮
   - 应用程序工具栏中 `Collect Backup Logs` 按钮的右键上下文菜单

### 增强的通知系统 {/* #enhanced-notification-system */}

- **SMTP 电子邮件通知支持：**
    - 在 [设置 → 电子邮件设置](../user-guide/settings/email-settings.md) 中配置 SMTP 服务器
    - 每个备份作业配置 NTFY 和/或电子邮件通知
    - 使用现有的 [设置 → 通知模板](../user-guide/settings/notification-templates.md) 的 HTML 格式模板
- **每个备份作业通知配置：**
    - 在 [设置 → 备份通知](../user-guide/settings/backup-notifications-settings.md) 中的单独通知偏好
    - 当 NTFY 或电子邮件未正确配置时的视觉指示器（灰色图标）

- **区域设置支持：**
    - 创建了一个新的环境变量 `LANG` 以在应用程序中设置区域设置
    - 现在通知和日志中的日期和数字格式是可预测的

## 🔒 安全增强功能 {/* #-security-enhancements */}

### CSRF 保护 {/* #csrf-protection */}

- **基于会话的身份验证** 具有强大的会话管理
- **CSRF 令牌验证** 对所有状态更改 API 请求强制执行
- **会话在 24 小时后自动过期**；CSRF 令牌每 30 分钟刷新一次
- 确保防止跨站请求伪造，同时保持与外部 API 的兼容性

### 明文密码最小化 {/* #plaintext-password-minimization */}

- **只能通过用户界面设置密码**；没有 API 端点暴露存储的密码
- **在整个系统中最小化明文密码操作**

### 敏感数据的高级加密 {/* #advanced-cryptography-for-sensitive-data */}

- **敏感数据加密**（例如密码、SMTP 凭据）使用 AES-256-GCM
- **主密钥自动生成**并安全存储在 `.duplistatus.key` 中
- **使用 100,000 次迭代的 PBKDF2** 进行密钥派生以增强安全性
- **验证身份验证标签**并在使用后安全清除内存
- **主密钥文件权限**严格设置为 0400 以实现最大保护

## 🚀 迁移说明 {/* #-migration-notes */}

### 从版本 0.7.x {/* #from-version-07x */}

此发布版包含重要的安全增强和新功能。从版本 0.7.x 升级时：

1. **自动数据库迁移：** 应用程序将自动迁移您的数据库模式以支持新功能
2. **主密钥生成：** 将生成新的主密钥用于敏感数据的加密
3. **会话管理：** 现有会话将失效并建立新的受 CSRF 保护的会话
4. **配置更新：** 某些配置键已更新以支持新功能
5. **模板变更：** 变量 `{backup_interval_value}` 和 `{backup_interval_type}` 已被 `{backup_interval}` 替换。默认模板将自动调整，但自定义模板不会迁移。请检查您的模板。

### 安全注意事项 {/* #security-considerations */}

- **主密钥文件：** 确保 `.duplistatus.key` 文件得到适当备份和保护
- **文件权限：** 主密钥文件将具有受限权限（0400）以确保安全
- **密码加密：** 现有密码将使用新的加密系统进行加密
