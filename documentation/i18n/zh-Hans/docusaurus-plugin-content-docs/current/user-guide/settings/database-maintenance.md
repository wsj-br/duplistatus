# 数据库维护 {/* #database-maintenance */}

通过数据库维护操作管理您的备份数据并优化性能。

![数据库维护](../../assets/screen-settings-database-maintenance.png)

<br/>

## 数据库备份 {/* #database-backup */}

为安全保存或迁移目的创建整个数据库的备份。

1.  导航至 [设置 → 数据库维护](database-maintenance.md)。
2.  在 **数据库备份** 部分，选择备份格式：
    - **数据库文件 (.db)**：二进制格式 - 最快的备份，完全保留所有数据库结构
    - **SQL 转储 (.sql)**：文本格式 - 可读的 SQL 语句，可在恢复前编辑
3.  点击 <IconButton icon="lucide:download" label="下载备份" />。
4.  备份文件将下载到您的计算机，文件名包含时间戳。

**备份格式：**

- **.db 格式**：推荐用于常规备份。使用 SQLite 的备份 API 创建数据库文件的精确副本，即使数据库正在使用中也能保证一致性。
- **.sql 格式**：用于迁移、检查或在恢复前编辑数据时很有用。包含重新创建数据库所需的所有 SQL 语句。

**最佳实践：**

- 在主要操作（清理、合并等）之前创建常规备份
- 将备份存储在与应用程序分开的安全位置
- 定期测试恢复过程以确保备份有效

<br/>

## 数据库恢复 {/* #database-restore */}

从之前创建的备份文件中恢复您的数据库。

1.  导航至 [设置 → 数据库维护](database-maintenance.md)。
2.  在 **数据库恢复** 部分，点击文件输入并选择备份文件：
    - 支持的格式：`.db`、`.sql`、`.sqlite`、`.sqlite3`
    - 最大文件大小：100MB
3.  点击 <IconButton icon="lucide:upload" label="恢复数据库" />。
4.  在对话框中确认操作。

**恢复过程：**

- 在恢复前会自动创建当前数据库的安全备份
- 当前数据库将被备份文件替换
- 为安全起见，所有会话都会被清除（用户必须重新登录）
- 恢复后会验证数据库完整性
- 所有缓存都会被清除以确保数据是最新的

**恢复格式：**

- **.db 文件**：数据库文件直接被替换。最快的恢复方法。
- **.sql 文件**：执行 SQL 语句以重新创建数据库。如果需要，允许选择性恢复。

:::warning
恢复数据库将 **替换所有当前数据**。此操作无法撤消。  
会自动创建安全备份，但建议在恢复前创建您自己的备份。
 
**重要提示：** 为安全起见，恢复后所有用户会话都会被清除。您需要重新登录。
:::

**故障排除：**

- 如果还原失败，原始数据库将自动从安全备份中恢复
- 确保备份文件未损坏且符合预期格式
- 对于大型数据库，还原过程可能需要几分钟

## 数据清理周期 {/* #data-cleanup-period */}

删除过时的备份记录以释放存储空间并提高系统性能。

1.  导航至 [设置 → 数据库维护](database-maintenance.md)。
2.  选择保留期限：
    - **6 个月**：保留最近 6 个月的记录。
    - **1 年**：保留最近 1 年的记录。
    - **2 年**：保留最近 2 年的记录（默认）。
    - **删除所有数据**：删除所有备份记录和服务器。 
3.  点击 <IconButton icon="lucide:trash-2" label="清除旧记录" />。
4.  在对话框中确认操作。

**清理效果：**

- 删除选定周期之前的备份记录
- 更新所有相关统计信息和指标

:::warning

选择“删除所有数据”选项将从系统中**永久删除所有备份记录和配置设置**。

强烈建议在执行此操作之前创建数据库备份。

:::

<br/>

## 删除备份任务数据 {/* #delete-backup-job-data */}

删除特定备份任务（类型）的数据。

1.  导航至 [设置 → 数据库维护](database-maintenance.md)。
2.  从下拉列表中选择一个备份任务。
    - 备份将按服务器别名或名称排序，然后按备份名称排序。
3.  点击 <IconButton icon="lucide:folder-open" label="删除备份任务" />。
4.  在对话框中确认操作。

**删除效果：**

- 永久删除与此备份任务/服务器关联的所有数据。
- 清理关联的配置设置。
- 相应地更新仪表板统计信息。

<br/>

## 删除服务器数据 {/* #delete-server-data */}

删除特定服务器及其所有关联的备份数据。

1.  导航至 [设置 → 数据库维护](database-maintenance.md)。
2.  从下拉列表中选择一个服务器。
3.  点击 <IconButton icon="lucide:server" label="删除服务器数据" />。
4.  在对话框中确认操作。

**删除效果：**

- 永久删除所选服务器及其所有备份记录
- 清理关联的配置设置
- 相应地更新仪表板统计信息

<br/>

## 合并重复服务器 {/* #merge-duplicate-servers */}

检测并合并具有相同名称但不同 ID 的重复服务器。使用此功能将它们合并为单个服务器条目。

当 Duplicati 的 `machine-id` 在升级或重新安装后发生变化时，可能会发生这种情况。仅当存在重复服务器时才会显示重复服务器。如果未检测到重复项，该部分将显示一条消息，指示所有服务器均具有唯一名称。

1.  转到 [设置 → 数据库维护](database-maintenance.md)。
2.  如果检测到重复服务器，将出现 **合并重复服务器** 部分。
3.  查看重复服务器组的列表：
    - 每个组显示具有相同名称但不同 ID 的服务器
    - **目标服务器**（按创建日期最新）会被突出显示
    - 将单独列出将被合并的 **旧服务器 ID**
4.  通过选中每个组旁边的复选框来选择要合并的服务器组。
5.  单击 <IconButton icon="lucide:git-merge" label="合并所选服务器" />。
6.  在对话框中确认操作。

**合并过程：**

- 所有旧服务器 ID 都合并到目标服务器（按创建日期最新）
- 所有备份记录和配置都转移到目标服务器
- 同一备份名称的重复 `backup_id` 值合并为单个 ID（最新备份行获胜）
- 旧服务器条目将被删除
- 仪表板统计信息会自动更新

:::info[重要]
此操作无法撤消。建议在确认前进行数据库备份。
:::
