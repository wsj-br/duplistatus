# Duplicati 版本 {/* #duplicati-versions */}

此页面显示存储在 **duplistatus** 缓存中的最新 Duplicati 发布版本，并允许管理员配置从 GitHub 刷新这些版本的频率。

![Duplicati 版本](../../assets/screen-settings-duplicati-versions.png)

缓存由[仪表板](../dashboard.md#duplicati-server-version) 和 [服务器](server-settings.md) 页面使用，为每个服务器版本着色，并显示其是否为当前版本或已过时。

## 最新频道版本 {/* #latest-channel-versions */}

表格列出了每个 Duplicati 频道的最新缓存版本：

| 频道 | 描述 |
|:---------------|:-------------------------------------------------|
| **Stable** | 最新稳定版发布 |
| **Beta** | 最新测试版发布 |
| **Experimental** | 最新实验版发布 |
| **Canary** | 最新金丝雀版发布 |

上次成功从 GitHub 更新的时间显示在表格上方。如果尚未找到某个频道，或者缓存从未更新过，页面将显示版本不可用。

管理员可以点击 **立即更新** 来立即获取最新发布。这不需要 cron 服务运行。如果无法访问 GitHub，**duplistatus** 将保留之前的缓存。

## 版本检查计划 {/* #version-check-schedule */}

**在仪表板上显示版本**用于在[仪表板](../dashboard.md#duplicati-server-version)卡片视图中开启或关闭版本徽章。仪表板表格始终显示**版本**列。默认情况下此功能为开启状态，也可在[显示设置](display-settings.md)中进行配置。这是每个用户的显示偏好设置。

管理员可以选择 **duplistatus** 检查 GitHub 上新的 Duplicati 发布的频率：

| 间隔 | 运行 |
|:-------------------|:-------------------------------------------------------------|
| **每天一次** | 在配置的开始时间运行一次 |
| **每 12 小时** | 在开始时间和 12 小时后运行 |
| **每 6 小时** | 在开始时间和之后每 6 小时运行 |

开始时间在您的浏览器时区中选择，使用与每日摘要相同的紧凑时间控件。选择任意 `HH:mm` 时间。**duplistatus** 将该值存储为 UTC，cron 服务以 UTC 运行检查。

示例：

- 每日且开始时间为 06:00 的任务将在 06:00 执行。
- 每日且开始时间为 06:30 的任务将在 06:30 执行。
- 每 12 小时且开始时间为 08:15 的任务将在 08:15 和 20:15 执行。
- 每 6 小时且开始时间为 02:45 的任务将在 02:45、08:45、14:45 和 20:45 执行。

启动时，如果缓存的年龄超过所选间隔（24 小时、12 小时或 6 小时），**duplistatus** 还会刷新缓存，包括在新的空数据库上也是如此。临时的 GitHub 故障（例如 HTTP 504）将被重试。刷新失败时会保留最后缓存的版本。

普通用户可以查看缓存的版本和计划，并可以开启或关闭**在仪表板上显示版本**。只有管理员可以更改间隔时间、开始时间或强制更新。

:::note
更改计划会在[审计日志](audit-logs-viewer.md)中写入 `duplicati_version_check_updated` 条目。成功的和失败的 GitHub 更新会被记录为 `duplicati_version_refresh`，触发器为 `startup`、`cron` 或 `manual`。
:::
