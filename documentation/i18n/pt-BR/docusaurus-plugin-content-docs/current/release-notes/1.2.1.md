# Versão 1.2.1 {/* #version-121 */}

## Visão Geral {/* #overview */}

A versão 1.2.1 é uma versão menor que introduz melhorias significativas no gerenciamento de notificações de backup, aprimora as capacidades de registro de auditoria, corrige a detecção de execução agendada/atrasada em casos extremos e adiciona funcionalidade de backup e restauração de banco de dados. Essa versão se concentra em melhorar a experiência do usuário com as configurações de notificação.

## Novos recursos {/* #new-features */}

### Gerenciamento Aprimorado de Notificações de Backup {/* #enhanced-backup-notifications-management */}

- **Padrões e sistema de herança no nível do servidor**: Configure destinos adicionais padrão (eventos de notificação, e-mails e tópicos NTFY) no nível do servidor que todos os backups herdam automaticamente. Backups podem substituir esses padrões quando necessário, com indicadores visuais claros mostrando o status de herança.
- **Hierarquia visual aprimorada**: Backups agora são agrupados por servidor com linhas de cabeçalho de servidor distintas. Valores herdados são marcados claramente com ícones de link, e valores substituídos podem ser facilmente revertidos para herança.
- **Operações em lote**: O botão "Sincronizar para Todos" limpa todas as substituições de backup para que todos os backups herdem dos padrões do servidor. O botão "Limpar Tudo" limpa todos os destinos adicionais, mantendo a estrutura de herança.
- **Funcionalidade de teste**: Adicionado botões de teste de e-mail e teste de notificação diretamente na página de configurações de Notificações de Backup. Os botões de teste estão disponíveis tanto para configurações de backup individuais quanto para operações de edição em lote, permitindo verificar a entrega de notificações antes de aplicar alterações.
- **Suporte a código QR**: Adicionado botão de código QR para tópicos NTFY para compartilhar facilmente tópicos de notificação com dispositivos móveis.

### Melhorias nos Modelos de Notificação {/* #notification-template-enhancements */}

- **Nova variável `{log_text}`**: Adicionada a variável `{log_text}` aos modelos de notificação, fornecendo acesso a mensagens de texto de log para uso em mensagens de notificação. A variável contém o texto completo de avisos e erros combinados, formatado como texto simples com um item por linha.
- **Migração automática de modelo**: O sistema inclui um mecanismo de atualização preguiçoso que detecta e atualiza automaticamente modelos padrão antigos quando são lidos pela primeira vez após uma atualização. Modelos personalizados são preservados inalterados.

### Gerenciamento de Banco de Dados {/* #database-management */}

- **Funcionalidade de backup de banco de dados**: Administradores agora podem criar backups do banco de dados inteiro a partir da página de Manutenção do Banco de Dados. Suporta formatos binário (.db) e texto SQL (.sql) para flexibilidade.
- **Funcionalidade de restauração de banco de dados**: Restaure o banco de dados a partir de arquivos de backup criados anteriormente com criação automática de backup de segurança, validação de integridade e reversão em caso de falha. Todas as sessões são limpas após a restauração por segurança.

### Detecção de Chave Mestra {/* #master-key-detection */}

- **Detecção automática de alteração de chave mestra**: Após o login, o sistema verifica automaticamente se o arquivo `.duplistatus.key` foi alterado. Se detectado, todas as senhas criptografadas são limpas e um popup modal informa aos usuários que as senhas precisam ser reconfiguradas. Isso evita erros ao restaurar de backups ou migrar para um novo sistema.

### Melhorias no Monitoramento de Backup {/* #backup-monitoring-improvements */}

- **Exportação CSV aprimorada**: Adicionada a coluna "Último Timestamp de Backup (DB)" ao arquivo CSV gerado pelo botão "Baixar CSV" nas configurações de monitoramento de backup. Isso permite aos usuários comparar o timestamp real do último backup do banco de dados com o timestamp "Último Backup" configurado.
- **Dica de "Próxima Execução"**: Passe o mouse sobre o valor "Próxima Execução" em cada linha para exibir uma dica mostrando o timestamp do último backup do banco de dados, formatado da mesma forma que a exibição de "Próxima Execução".

### Melhorias no Registro de Auditoria {/* #audit-logging-enhancements */}

- **Entradas de auditoria de notificação individuais**: Cada notificação e e-mail enviado agora gera uma entrada separada no log de auditoria com detalhes sobre o canal, configuração e resultado (sucesso ou falha). Isso inclui notificações de teste, proporcionando melhor rastreabilidade para a entrega de notificações.
- **Registro robusto de falhas**: Todas as operações de registro de auditoria para falhas de notificação agora estão envolvidas em blocos try-catch para evitar que erros de registro de auditoria interrompam os fluxos de notificação. O sistema tenta recuperar a configuração SMTP se ela não estiver imediatamente disponível ao registrar falhas de e-mail.
- **Registro de auditoria aprimorado para atualizações de configuração**: As entradas de log de auditoria para `email_config_updated` e `ntfy_config_updated` agora registram apenas quando há alterações reais na configuração. Quando alterações são detectadas, o log de auditoria inclui os valores antigos e novos para cada campo modificado, facilitando o rastreamento do que foi alterado.

### Melhorias na documentação {/* #documentation-improvements */}

- O estilo da documentação foi atualizado para alinhar-se ao visual e ao estilo da aplicação. A barra lateral também foi revisada para melhorar a visibilidade e facilitar a navegação.

## 🐛 Correções de Bugs {/* #-bug-fixes */}

- **Correção de timestamps no log de auditoria**: Os timestamps no visualizador de log de auditoria agora são exibidos corretamente no fuso horário do navegador do usuário em vez de GMT. Os timestamps do SQLite (armazenados em UTC) são agora analisados corretamente como UTC e convertidos para o fuso horário local do navegador para exibição.
- **Cálculo correto de "Próxima Execução" e detecção de atraso**: A coluna "Próxima Execução" nas configurações de monitoramento de backup agora calcula e exibe corretamente a próxima data de backup esperada, levando em consideração tanto o agendamento de backup quanto o timestamp do último backup. Isso se aplica a ambos os trabalhos de backup agendados e executados manualmente, resultando em uma detecção de atraso mais confiável.

## 🚀 Notas de Migração {/* #-migration-notes */}

### A partir da Versão 1.1.x {/* #from-version-11x */}

Ao atualizar para a versão 1.2.1:

1. **Modelos de Notificação**: O sistema atualizará automaticamente os modelos de notificação padrão para incluir a nova variável `{log_text}` na primeira vez que eles forem acessados após a atualização. Modelos personalizados permanecerão inalterados. Se você deseja usar a nova variável `{log_text}` em seus próprios modelos, você precisará atualizá-los ou restaurar os modelos padrão manualmente.

2. **Alterações na Chave Mestra**: Se você restaurar de um backup ou migrar para um novo sistema com um arquivo `.duplistatus.key` diferente, o sistema detectará isso automaticamente e solicitará que você reconfigure as senhas criptografadas (senhas SMTP e senhas do servidor Duplicati).

3. **Backup/Restauração do Banco de Dados**: Nova funcionalidade de backup e restauração do banco de dados está disponível na página de configurações de manutenção do banco de dados. É recomendado criar um backup antes de atualizar, embora nenhuma alteração no esquema do banco de dados seja necessária para esta versão.

4. **Nenhuma Migração de Banco de Dados Necessária**: Esta versão não requer nenhuma alteração no esquema do banco de dados.

## Pontos de Extremidade da API {/* #api-endpoints */}

Os seguintes endpoints da API foram introduzidos nesta versão.

### Endpoints de Autenticação e Segurança {/* #authentication--security-endpoints */}

- `GET /api/auth/admin-must-change-password` - Verificar se o usuário administrador deve alterar a senha

### Endpoints de Gerenciamento de Banco de Dados {/* #database-management-endpoints */}

- `GET /api/database/backup` - Criar backup do banco de dados (formato binário ou SQL)
- `POST /api/database/restore` - Restaurar banco de dados a partir de arquivo de backup

### Endpoints de Gerenciamento de Backup {/* #backup-management-endpoints */}

- `GET /api/backups/last-timestamps` - Obter timestamps dos últimos backups para todas as combinações servidor-backup
