# Versão 1.2.1 {/* #version-121 */}

## Visão geral {/* #overview */}

A versão 1.2.1 é uma atualização menor que introduz melhorias significativas na gestão de notificações de backup, aprimora as capacidades de registro de auditoria, corrige a detecção de próxima execução/atraso em casos extremos e adiciona funcionalidade de backup e restauração de banco de dados. Esta versão foca em melhorar a experiência do usuário com as configurações de notificação.

## Novos Recursos {/* #new-features */}

### Gestão Aprimorada de Notificações de Backup {/* #enhanced-backup-notifications-management */}

- **Padrões e sistema de herança em nível de servidor**: Configurar destinos adicionais padrão (eventos de notificação, e-mails e tópicos NTFY) em nível de servidor que todos os backups herdam automaticamente. Os backups podem substituir esses padrões quando necessário, com indicadores visuais claros mostrando o status da herança.
- **Hierarquia visual aprimorada**: Os backups agora são agrupados por servidor com linhas de cabeçalho de servidor distintas. Os valores herdados são claramente marcados com ícones de link, e os valores substituídos podem ser facilmente revertidos para a herança.
- **Operações em lote**: O botão "Sincronizar para Todos" limpa todas as substituições de backup para que todos os backups herdem dos padrões do servidor. O botão "Limpar Tudo" limpa todos os destinos adicionais enquanto mantém a estrutura de herança.
- **Funcionalidade de teste**: Botões de teste de e-mail e notificação foram adicionados diretamente na página de configurações de Notificações de Backup. Os botões de teste estão disponíveis tanto para configurações de backup individuais quanto para operações de edição em lote, permitindo que você verifique a entrega de notificações antes de aplicar as alterações.
- **Suporte a QR code**: Botão de QR code adicionado para tópicos NTFY para compartilhar facilmente tópicos de notificação com dispositivos móveis.

### Melhorias nos Modelos de Notificação {/* #notification-template-enhancements */}

- **Nova variável `{log_text}`**: Variável `{log_text}` adicionada aos modelos de notificação, fornecendo acesso a mensagens de texto de log para uso em mensagens de notificação. A variável contém o texto completo de avisos e erros combinados, formatados como texto simples com um item por linha.
- **Migração automática de modelos**: O sistema inclui um mecanismo de atualização preguiçosa que detecta e atualiza automaticamente os antigos modelos padrão quando são lidos pela primeira vez após uma atualização. Modelos personalizados são preservados sem alterações.

### Gestão de Banco de Dados {/* #database-management */}

- **Funcionalidade de backup de banco de dados**: Os administradores agora podem criar backups de todo o banco de dados a partir da página de configurações de Manutenção do Banco de Dados. Suporta formatos binários (.db) e texto SQL (.sql) para flexibilidade.
- **Funcionalidade de restauração de banco de dados**: Restaure o banco de dados a partir de arquivos de backup criados anteriormente com criação automática de backup de segurança, validação de integridade e rollback em caso de falha. Todas as sessões são limpas após a restauração por motivos de segurança.

### Detecção de Chave Mestra {/* #master-key-detection */}

- **Detecção automática de mudança de chave mestra**: Após o login, o sistema verifica automaticamente se o arquivo `.duplistatus.key` foi alterado. Se detectado, todas as senhas criptografadas são limpas e um popup modal informa os usuários que as senhas precisam ser reconfiguradas. Isso previne erros ao restaurar de backups ou migrar para um novo sistema.

### Melhorias no Monitoramento de Backup {/* #backup-monitoring-improvements */}

- **Exportação CSV aprimorada**: Coluna "Timestamp do Último Backup (DB)" adicionada ao arquivo CSV gerado pelo botão "Baixar CSV" nas configurações de monitoramento de backup. Isso permite que os usuários comparem o timestamp real do último backup do banco de dados com o timestamp configurado de "Último Backup".
- **Dica de Próxima Execução**: Passar o mouse sobre o valor "Próxima Execução" em cada linha agora exibe uma dica mostrando o timestamp do último backup do banco de dados, formatado da mesma forma que a exibição de "Próxima Execução".

### Melhorias no Log de Auditoria {/* #audit-logging-enhancements */}

- **Entradas de auditoria de notificações individuais**: Cada notificação e e-mail enviado agora gera uma entrada de log de auditoria separada com detalhes sobre o canal, configuração e resultado (sucesso ou falha). Isso inclui notificações de teste, proporcionando melhor rastreabilidade para a entrega de notificações.
- **Registro de falhas robusto**: Todas as operações de registro de auditoria para falhas de notificação agora estão envoltas em blocos try-catch para evitar que erros de registro de auditoria quebrem os fluxos de notificação. O sistema tenta recuperar a configuração SMTP se não estiver imediatamente disponível ao registrar falhas de e-mail.
- **Registro de auditoria aprimorado para atualizações de configuração**: Tanto `email_config_updated` quanto `ntfy_config_updated` entradas de log de auditoria agora registram apenas quando há alterações reais na configuração. Quando alterações são detectadas, o log de auditoria inclui os valores antigos e novos para cada campo modificado, facilitando o rastreamento do que mudou especificamente.

### Melhorias na documentação {/* #documentation-improvements */}

- O estilo da documentação foi atualizado para alinhar-se com a aparência e a sensação do aplicativo. A barra lateral também foi revisada para melhorar a visibilidade e facilitar a navegação.

## 🐛 Correções de Bugs {/* #-bug-fixes */}

- **Correção de timestamps de log de auditoria**: Timestamps no visualizador de log de auditoria agora são exibidos corretamente no fuso horário do navegador do usuário em vez de GMT. Timestamps do SQLite (armazenados em UTC) agora são corretamente analisados como UTC e convertidos para o fuso horário local do navegador para exibição.
- **Correção do cálculo de "Próxima Execução" e detecção de atrasos**: A coluna "Próxima Execução" nas configurações de monitoramento de backup agora calcula e exibe com precisão a próxima data de backup esperada, levando em conta tanto o cronograma de backup quanto o timestamp do último backup. Isso se aplica tanto a trabalhos de backup agendados quanto a trabalhos de backup executados manualmente, resultando em uma detecção de atrasos mais confiável.

## 🚀 Notas de Migração {/* #-migration-notes */}

### Da Versão 1.1.x {/* #from-version-11x */}

Ao atualizar para a versão 1.2.1:

1. **Modelos de Notificação**: O sistema atualizará automaticamente os modelos de notificação padrão para incluir a nova variável `{log_text}` na primeira vez que forem acessados após a atualização. Modelos personalizados permanecerão inalterados. Se você quiser usar a nova variável `{log_text}` em seus próprios modelos, precisará atualizá-los ou restaurar os modelos padrão manualmente.

2. **Alterações na Chave Mestra**: Se você restaurar de um backup ou migrar para um novo sistema com um arquivo `.duplistatus.key` diferente, o sistema detectará isso automaticamente e solicitará que você reconfigure as senhas criptografadas (senhas SMTP e senhas do servidor Duplicati).

3. **Backup/Restauração do Banco de Dados**: Nova funcionalidade de backup e restauração de banco de dados está disponível na página de configurações de Manutenção do Banco de Dados. É recomendável criar um backup antes de atualizar, embora nenhuma alteração no esquema do banco de dados seja necessária para esta versão.

4. **Nenhuma Migração de Banco de Dados Necessária**: Esta versão não requer alterações no esquema do banco de dados.

## Endpoints da API {/* #api-endpoints */}

Os seguintes endpoints da API foram introduzidos nesta versão.

### Endpoints de Autenticação e Segurança {/* #authentication--security-endpoints */}

- `GET /api/auth/admin-must-change-password` - Verificar se o usuário administrador deve alterar a senha

### Endpoints de Gerenciamento de Banco de Dados {/* #database-management-endpoints */}

- `GET /api/database/backup` - Criar backup do banco de dados (formato binário ou SQL)
- `POST /api/database/restore` - Restaurar banco de dados a partir de arquivo de backup

### Endpoints de Gerenciamento de Backup {/* #backup-management-endpoints */}

- `GET /api/backups/last-timestamps` - Obter timestamps do último backup para todas as combinações de servidor-backup
