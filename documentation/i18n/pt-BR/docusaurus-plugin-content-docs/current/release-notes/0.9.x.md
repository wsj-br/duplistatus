# Versão 0.9.x {/* #version-09x */}

## Visão geral {/* #overview */}

A versão 0.9.x é um lançamento importante que introduz um **Sistema de Controle de Acesso e Segurança do Usuário** abrangente. Este lançamento transforma **duplistatus** de um aplicativo de acesso aberto em um sistema seguro de múltiplos usuários com controle de acesso baseado em funções, registro de auditoria abrangente e recursos de segurança de nível empresarial. Todas as funcionalidades existentes agora estão protegidas por autenticação, garantindo que apenas usuários autorizados possam acessar e gerenciar o monitoramento de backup.

## Mudanças Incompatíveis {/* #breaking-changes */}

### Autenticação Necessária {/* #authentication-required */}

- **Todas as páginas agora requerem autenticação** - Os usuários devem entrar para acessar o aplicativo
- **Conta de administrador padrão** é criada automaticamente:
  - Nome de usuário: `admin`
  - Senha: `Duplistatus09` (deve ser alterada no primeiro login)
- **Sessões existentes são invalidadas** - Todos os usuários devem entrar após a atualização
- **Endpoints da API agora requerem autenticação** - Integrações externas devem incluir cookies de sessão ou usar solicitações autenticadas

:::warning
**Todos os usuários devem entrar após atualizar para a versão 0.9.x.** As credenciais padrão do administrador são admin/Duplistatus09. Altere a senha imediatamente após o primeiro login.
:::

### Migração do Esquema do Banco de Dados {/* #database-schema-migration */}

- **Migração automática de v3.1 para v4.0** para instalações existentes
- **Novas tabelas adicionadas**: `users`, `sessions`, `audit_log`
- **Backup do banco de dados criado automaticamente** antes da migração
- **Novas instalações** começam diretamente com o esquema v4.0 (sem migração necessária)

## Novos Recursos {/* #new-features */}

### Sistema de Controle de Acesso e Segurança do Usuário {/* #user-access-control--security-system */}

#### Sistema de Autenticação {/* #authentication-system */}

- **Funcionalidade de login/logout do usuário** com gerenciamento de sessão seguro
- **Autenticação baseada em senha** com hashing bcrypt (fator de custo 12)
- **Mecanismo de bloqueio de conta** (5 tentativas falhas, bloqueio de 15 minutos)
- **Alteração forçada de senha** no primeiro login
- **Aplicação de política de senha**:
  - Mínimo de 8 caracteres
  - Pelo menos uma letra maiúscula
  - Pelo menos uma letra minúscula
  - Pelo menos um número
  - Caracteres especiais opcionais
- **Funcionalidade de "Lembrar-me"** com persistência do nome de usuário no localStorage
- **Autenticação baseada em sessão** com sessões suportadas por banco de dados (substitui a memória)
- **Proteção CSRF** integrada com autenticação
- **Cookies apenas HTTP** para segurança da sessão
- **Rastreamento de endereço IP e agente do usuário** para monitoramento de segurança

#### Gerenciamento de Usuários (Apenas Administrador) {/* #user-management-admin-only */}

- **Criação de usuário** com geração automática de senha temporária
- **Lista de usuários** com pesquisa, paginação e filtragem
- **Edição de usuário** (nome de usuário, status de administrador, requisito de alteração de senha)
- **Funcionalidade de redefinição de senha** com exibição de senha temporária
- **Exclusão de usuário** com salvaguardas (impede a exclusão do último administrador)
- **Controle de acesso baseado em função** (Funções de Administrador/Usuário)
- **Indicadores de status** (Ativo, Bloqueado, Deve Alterar Senha)
- **Rastreamento e exibição do último login**

#### Sistema de Registro de Auditoria {/* #audit-logging-system */}

- **Trilha de auditoria abrangente** para todas as alterações do sistema e ações do usuário
- **Visualizador de log de auditoria** com filtragem avançada:
  - Filtragem por intervalo de datas
  - Filtragem por usuário
  - Filtragem por ação
  - Filtragem por categoria
  - Filtragem por status
- **Funcionalidade de exportação** (formatos CSV e JSON)
- **Estatísticas e análises de log de auditoria**
- **Período de retenção configurável** (30-365 dias, padrão: 90 dias)
- **Tarefa cron de limpeza automática** (executa diariamente às 2 AM UTC)
- **API de limpeza manual** com suporte a execução de teste
- **Registro de auditoria para**:
  - Eventos de autenticação (login, logout, alterações de senha, bloqueios de conta)
  - Operações de gerenciamento de usuários (criação, atualização, exclusão, redefinições de senha)
  - Alterações de configuração (e-mail, NTFY, modelos, tolerância a atraso, configurações de backup)
  - Operações de backup (coleta, exclusão, limpeza)
  - Gerenciamento de servidor (adição, atualização, exclusão)
  - Operações do sistema (migrações, limpeza, notificações)

### Redesign da Página de Configurações {/* #settings-page-redesign */}

- **Navegação moderna na barra lateral** com barra lateral colapsável
- **Persistência do estado da barra lateral específica do usuário** (preferência colapsada/expandida salva por usuário)
- **Seções de configurações agrupadas**:
  - **Notificações**: Notificações de Backup, Monitoramento de Backup, Modelos
  - **Integrações**: NTFY, E-mail
  - **Sistema**: Servidores, Usuários (apenas administrador), Log de Auditoria
- **Barra lateral fixa** que permanece visível enquanto rola
- **Design responsivo** com espaçamento otimizado
- **Ícone de configurações e título "Configurações do Sistema"** no cabeçalho da barra lateral
- **Botão Voltar** integrado ao cabeçalho do aplicativo

### Melhorias na Interface do Usuário {/* #user-interface-enhancements */}

- **Página de login independente** com design moderno
- **Caixa de seleção "Lembrar-me"** no formulário de login para persistência do nome de usuário
- **Botões mostrar/ocultar senha** nos formulários de login e alteração de senha
- **Modal de alteração de senha** com lista de verificação de validação em tempo real
- **Indicador de usuário e botão de logout** no cabeçalho do aplicativo
- **Visibilidade da interface do usuário baseada em função** (recursos apenas para administradores ocultos de usuários regulares)
- **Emblemas e indicadores de status** por toda a interface do usuário
- **Preferências específicas do usuário** armazenadas no localStorage (por exemplo, estado da barra lateral colapsada)

### Recursos de Segurança {/* #security-features */}

- **Hashing de senha** com bcrypt (padrão da indústria)
- **Sanitização de dados sensíveis** em logs de auditoria (senhas, tokens, segredos nunca registrados)
- **Limitação de taxa** para tentativas de login
- **Expiração de sessão** (24 horas)
- **Validação de token CSRF** para todas as operações que alteram o estado
- **Ferramenta CLI de recuperação do administrador** para redefinição de senha se bloqueado

### Ferramentas para Desenvolvedores {/* #developer-tools */}

- **Script CLI de recuperação do administrador** (`admin-recovery`) para execução fácil em contêineres Docker
- **Funciona tanto localmente quanto no Docker** com detecção automática de caminho
- **Interfaces TypeScript abrangentes** (sem tipos `any`)
- **Middleware de autenticação** para proteção de rotas
- **Classe utilitária de logger de auditoria** com métodos convenientes

## 🚀 Notas de Migração {/* #-migration-notes */}

### Da Versão 0.8.x {/* #from-version-08x */}

Esta versão introduz autenticação e requer que todos os usuários façam login. Ao atualizar da versão 0.8.x:

1. **Migração Automática do Banco de Dados**: O aplicativo migrará automaticamente seu esquema de banco de dados da v3.1 para a v4.0
2. **Backup do Banco de Dados**: Um backup automático é criado antes da migração
3. **Conta de Administrador Padrão**: Uma conta de administrador padrão é criada:
   - Nome de usuário: `admin`
   - Senha: `Duplistatus09`
   - **Você deve alterar esta senha no primeiro login**
4. **Invalidar Sessões**: Todas as sessões existentes são invalidadas
5. **Login do Usuário Necessário**: Todos os usuários devem fazer login após a atualização
6. **Autenticação da API**: Integrações externas devem ser atualizadas para incluir autenticação

### Considerações de Segurança {/* #security-considerations */}

- **Alterar Senha Padrão**: Altere a senha padrão do administrador imediatamente após o primeiro login
- **Criar Contas de Usuário**: Crie contas de usuário individuais para cada pessoa que precisa de acesso
- **Revisar Logs de Auditoria**: Verifique os logs de auditoria regularmente para monitoramento de segurança
- **Configurar Retenção**: Defina um período de retenção de log de auditoria apropriado com base em seus requisitos de conformidade
- **Backup da Chave Mestra**: Se estiver atualizando da 0.8.x, certifique-se de que o arquivo `.duplistatus.key` esteja salvo

### Passos do Primeiro Login {/* #first-login-steps */}

1. **Entrar** com as credenciais padrão (`admin` / `Duplistatus09`)
2. **Alterar senha** quando solicitado (forçado no primeiro login)
3. **Criar contas de usuário** para outros usuários (Configurações → Usuários)
4. **Configurar retenção de log de auditoria** se necessário (Configurações → Log de Auditoria)
5. **Revisar logs de auditoria** para verificar se o sistema está funcionando corretamente

## Endpoints da API {/* #api-endpoints */}

### Endpoints de Autenticação {/* #authentication-endpoints */}

- `POST /api/auth/login` - Autenticação do usuário
- `POST /api/auth/logout` - Término de sessão
- `GET /api/auth/me` - Informações do usuário atual
- `POST /api/auth/change-password` - Alteração de senha

### Endpoints de Gerenciamento de Usuários (Apenas Administrador) {/* #user-management-endpoints-admin-only */}

- `GET /api/users` - Listar usuários
- `POST /api/users` - Criar usuário
- `PATCH /api/users/{id}` - Atualizar usuário
- `DELETE /api/users/{id}` - Excluir usuário

### Endpoints de Log de Auditoria {/* #audit-log-endpoints */}

- `GET /api/audit-log` - Consultar logs de auditoria
- `GET /api/audit-log/download` - Exportar logs de auditoria
- `GET /api/audit-log/stats` - Estatísticas de auditoria
- `POST /api/audit-log/cleanup` - Limpeza manual (apenas administrador)
- `GET /api/audit-log/retention` - Obter configuração de retenção
- `PATCH /api/audit-log/retention` - Atualizar retenção (apenas administrador)

:::note
Todos os endpoints da API agora requerem autenticação. Veja a [Referência da API](../api-reference/authentication-security.md) para detalhes sobre autenticação.
:::
