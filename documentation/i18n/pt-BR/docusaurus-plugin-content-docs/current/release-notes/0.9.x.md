# Versão 0.9.x {/* #version-09x */}

## Visão Geral {/* #overview */}

A versão 0.9.x é um lançamento importante que introduz um sistema abrangente de **Controle de Acesso de Usuário e Segurança**. Este lançamento transforma o **duplistatus** de uma aplicação de acesso aberto em um sistema multi-usuário seguro com controle de acesso baseado em funções, registro de auditoria abrangente e recursos de segurança de nível corporativo. Todas as funcionalidades existentes agora estão protegidas por autenticação, garantindo que apenas usuários autorizados possam acessar e gerenciar o monitoramento de backup.

## Alterações que quebram a compatibilidade {/* #breaking-changes */}

### Autenticação Obrigatória {/* #authentication-required */}

- **Todas as páginas agora exigem autenticação** - Usuários devem fazer login para acessar a aplicação
- **Conta de administrador padrão** é criada automaticamente:
  - Nome de usuário: `admin`
  - Senha: `Duplistatus09` (deve ser alterada no primeiro login)
- **Sessões existentes são invalidadas** - Todos os usuários devem fazer login após a atualização
- **Pontos de extremidade da API agora exigem autenticação** - Integrações externas devem incluir cookies de sessão ou usar solicitações autenticadas

:::warning
**Todos os usuários devem fazer login após atualizar para a versão 0.9.x.** As credenciais padrão do administrador são admin/Duplistatus09. Altere a senha imediatamente após o primeiro login.
:::

### Migração do Esquema do Banco de Dados {/* #database-schema-migration */}

- **Migração automática da v3.1 para v4.0** para instalações existentes
- **Novas tabelas adicionadas**: `users`, `sessions`, `audit_log`
- **Backup do banco de dados criado automaticamente** antes da migração
- **Novas instalações** começam diretamente com o esquema v4.0 (sem migração necessária)

## Novos recursos {/* #new-features */}

### Controle de Acesso de Usuário e Sistema de Segurança {/* #user-access-control--security-system */}

#### Sistema de Autenticação {/* #authentication-system */}

- **Funcionalidade de login/logout de usuário** com gerenciamento seguro de sessão
- **Autenticação baseada em senha** com hash bcrypt (fator de custo 12)
- **Mecanismo de bloqueio de conta** (5 tentativas falhas, bloqueio de 15 minutos)
- **Alteração forçada de senha** no primeiro login
- **Política de senha**:
  - Mínimo de 8 caracteres
  - Pelo menos uma letra maiúscula
  - Pelo menos uma letra minúscula
  - Pelo menos um número
  - Caracteres especiais opcionais
- **Funcionalidade "Lembrar-me"** com persistência do nome de usuário em localStorage
- **Autenticação baseada em sessão** com sessões com suporte a banco de dados (substitui em memória)
- **Proteção CSRF** integrada com autenticação
- **Cookies HTTP-only** para segurança de sessão
- **Rastreamento de endereço IP e agente do usuário** para monitoramento de segurança

#### Gerenciamento de Usuários (Somente Admin) {/* #user-management-admin-only */}

- **Criação de usuário** com geração automática de senha temporária
- **Lista de usuários** com pesquisa, paginação e filtragem
- **Edição de usuário** (nome de usuário, status de administrador, exigência de alteração de senha)
- **Funcionalidade de redefinição de senha** com exibição de senha temporária
- **Exclusão de usuário** com proteções (previne exclusão do último administrador)
- **Controle de acesso baseado em função** (Funções de Administrador/Usuário)
- **Indicadores de status** (Ativo, Bloqueado, Deve Alterar Senha)
- **Rastreamento e exibição do último login**

#### Sistema de Registro de Auditoria {/* #audit-logging-system */}

- **Trilha de auditoria abrangente** para todas as alterações do sistema e ações do usuário
- **Visualizador de log de auditoria** com filtragem avançada:
  - Filtragem por intervalo de datas
  - Filtragem por usuário
  - Filtragem por ação
  - Filtragem por categoria
  - Filtragem por status
- **Funcionalidade de exportação** (formatos CSV e JSON)
- **Estatísticas e análise do log de auditoria**
- **Período de retenção configurável** (30-365 dias, padrão: 90 dias)
- **Tarefa de limpeza automática cron** (executa diariamente às 2h UTC)
- **API de limpeza manual** com suporte a execução de teste
- **Registro de auditoria para**:
  - Eventos de autenticação (login, logout, alterações de senha, bloqueios de conta)
  - Operações de gerenciamento de usuários (criar, atualizar, excluir, redefinição de senha)
  - Alterações de configuração (e-mail, NTFY, modelos, tolerância de atraso, configurações de backup)
  - Operações de backup (coleta, exclusão, limpeza)
  - Gerenciamento de servidores (adicionar, atualizar, excluir)
  - Operações do sistema (migrações, limpeza, notificações)

### Redesenho da Página de Configurações {/* #settings-page-redesign */}

- **Navegação lateral moderna** com barra lateral recolhível
- **Persistência do estado da barra lateral específica do usuário** (preferência recolhida/expandida salva por usuário)
- **Seções de configurações agrupadas**:
  - **Notificações**: Notificações de Backup, Monitoramento de Backup, Modelos
  - **Integrações**: NTFY, E-mail
  - **Sistema**: Servidores, Usuários (apenas administrador), Log de Auditoria
- **Barra lateral fixa** que permanece visível ao rolar
- **Design responsivo** com espaçamento otimizado
- **Ícone de configurações e título "Configurações do Sistema"** no cabeçalho da barra lateral
- **Botão Voltar** integrado no cabeçalho do aplicativo

### Melhorias na Interface do Usuário {/* #user-interface-enhancements */}

- **Página de login independente** com design moderno
- **Caixa de seleção "Lembrar-me"** no formulário de login para persistência do nome de usuário
- **Botões mostrar/ocultar senha** nos formulários de login e alteração de senha
- **Modal de alteração de senha** com lista de verificação de validação em tempo real
- **Indicador de usuário e botão de logout** no cabeçalho do aplicativo
- **Visibilidade da interface baseada em função** (recursos apenas para administradores ocultos de usuários regulares)
- **Badges e indicadores de status** em toda a interface do usuário
- **Preferências específicas do usuário** armazenadas em localStorage (por exemplo, estado recolhido da barra lateral)

### Recursos de Segurança {/* #security-features */}

- **Hashing de senha** com bcrypt (padrão da indústria)
- **Sanitização de dados sensíveis** em logs de auditoria (senhas, tokens, segredos nunca registrados)
- **Limitação de taxa** para tentativas de login
- **Expiração de sessão** (24 horas)
- **Validação de token CSRF** para todas as operações que alteram o estado
- **Ferramenta CLI de recuperação de administrador** para redefinição de senha se bloqueado

### Ferramentas para Desenvolvedores {/* #developer-tools */}

- **Script CLI de recuperação de administrador** (`admin-recovery`) para execução fácil em contêineres Docker
- **Funciona localmente e no Docker** com detecção automática de caminho
- **Interfaces TypeScript abrangentes** (sem tipos `any`)
- **Middleware de autenticação** para proteção de rotas
- **Classe utilitária de registro de auditoria** com métodos de conveniência

## 🚀 Notas de Migração {/* #-migration-notes */}

### Da Versão 0.8.x {/* #from-version-08x */}

Esta versão introduz autenticação e exige que todos os usuários façam login. Ao atualizar da versão 0.8.x:

1. **Migração Automática do Banco de Dados**: O aplicativo migrará automaticamente o esquema do banco de dados da v3.1 para a v4.0
2. **Backup do Banco de Dados**: Um backup automático é criado antes da migração
3. **Conta de Administrador Padrão**: Uma conta de administrador padrão é criada:
   - Nome de usuário: `admin`
   - Senha: `Duplistatus09`
   - **Você deve alterar esta senha no primeiro login**
4. **Invalidar Sessões**: Todas as sessões existentes são invalidadas
5. **Login de Usuário Obrigatório**: Todos os usuários devem fazer login após a atualização
6. **Autenticação de API**: Integrações externas devem ser atualizadas para incluir autenticação

### Considerações de Segurança {/* #security-considerations */}

- **Alterar Senha Padrão**: Altere a senha do administrador padrão imediatamente após o primeiro login
- **Criar Contas de Usuário**: Crie contas de usuário individuais para cada pessoa que precise de acesso
- **Revisar Logs de Auditoria**: Verifique os logs de auditoria regularmente para monitoramento de segurança
- **Configurar Retenção**: Defina o período de retenção de logs de auditoria adequado com base em suas exigências de conformidade
- **Backup da Chave Mestra**: Se estiver atualizando a partir da versão 0.8.x, certifique-se de que o arquivo `.duplistatus.key` esteja em backup

### Passos para Primeiro Login {/* #first-login-steps */}

1. **Entre** com as credenciais padrão (`admin` / `Duplistatus09`)
2. **Altere a senha** quando solicitado (obrigatório no primeiro login)
3. **Crie contas de usuário** para outros usuários (Configurações → Usuários)
4. **Configure a retenção de logs de auditoria** se necessário (Configurações → Log de Auditoria)
5. **Revise os logs de auditoria** para verificar se o sistema está funcionando corretamente

## Pontos de Extremidade da API {/* #api-endpoints */}

### Pontos de Extremidade de Autenticação {/* #authentication-endpoints */}

- `POST /api/auth/login` - Autenticação de usuário
- `POST /api/auth/logout` - Encerramento de sessão
- `GET /api/auth/me` - Informações do usuário atual
- `POST /api/auth/change-password` - Alteração de senha

### Pontos de Extremidade de Gerenciamento de Usuários (Apenas Administrador) {/* #user-management-endpoints-admin-only */}

- `GET /api/users` - Listar usuários
- `POST /api/users` - Criar usuário
- `PATCH /api/users/{id}` - Atualizar usuário
- `DELETE /api/users/{id}` - Excluir usuário

### Pontos de Extremidade de Log de Auditoria {/* #audit-log-endpoints */}

- `GET /api/audit-log` - Consultar logs de auditoria
- `GET /api/audit-log/download` - Exportar logs de auditoria
- `GET /api/audit-log/stats` - Estatísticas de auditoria
- `POST /api/audit-log/cleanup` - Limpeza manual (apenas administrador)
- `GET /api/audit-log/retention` - Obter configuração de retenção
- `PATCH /api/audit-log/retention` - Atualizar retenção (apenas administrador)

:::note
Todos os pontos de extremidade da API agora exigem autenticação. Consulte a [Referência da API](../api-reference/authentication-security.md) para obter detalhes sobre autenticação.
:::
