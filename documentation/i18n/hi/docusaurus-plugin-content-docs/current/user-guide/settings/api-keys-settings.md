# API कुंजियाँ {/* #api-keys */}

व्यवस्थापक उन बाहरी HTTP API के लिए स्कोप्ड API कुंजियाँ बना सकते हैं जिनका उपयोग Duplicati और Homepage करते हैं। कुंजियाँ डिफ़ॉल्ट रूप से वैकल्पिक होती हैं ताकि मौजूदा Duplicati जॉब्स काम करती रहें।

![API कुंजियाँ](../../assets/screen-settings-api-keys.png)

## स्कोप {/* #scopes */}

| स्कोप | एंडपॉइंट्स |
|-------|-----------|
| अपलोड करें | `POST /api/upload` |
| पढ़ें | `GET /api/summary`, `GET /api/lastbackup/:id`, `GET /api/lastbackups/:id` |

एक अपलोड कुंजी रीड API को कॉल नहीं कर सकती, और एक रीड कुंजी रिपोर्ट अपलोड नहीं कर सकती।

## कुंजी बनाना {/* #creating-a-key */}

1. **सेटिंग्स → API कुंजियाँ** खोलें।
2. API कुंजियाँ कार्ड के निचले भाग में **API कुंजी बनाएँ** पर क्लिक करें।
3. एक नाम दर्ज करें, एक स्कोप चुनें, और वैकल्पिक रूप से समाप्ति (`YYYY-MM-DD`) सेट करें।
4. कुंजी जनरेट करें और सीक्रेट को तुरंत कॉपी करें। यह डायलॉग में केवल एक बार दिखाया जाता है।
5. इसके बाद सूची में `Qk7v…3xTa` जैसा फिंगरप्रिंट (पहले और अंतिम चार वर्ण), समाप्ति तिथि और स्थिति दिखाई देती है। वही फिंगरप्रिंट ऑडिट लॉग में दिखाई देता है।

### अक्षम करें या हटाएं {/* #disable-or-delete */}

कुंजी को हटाए बिना उसे अक्षम करने के लिए **कार्रवाइयाँ** कॉलम में चेकबॉक्स का उपयोग करें। अक्षम कुंजियाँ प्रमाणित नहीं कर सकतीं। कुंजी को फिर से सक्षम करने के लिए चेकबॉक्स पर फिर से टिक करें। समाप्त कुंजियों को सक्षम नहीं किया जा सकता; इसके बजाय एक नई कुंजी बनाएँ। हटाएं कुंजी को स्थायी रूप से हटा देता है।

### समाप्ति {/* #expiry */}

एक वैकल्पिक समाप्ति तिथि वह अंतिम कैलेंडर दिन है जब कुंजी मान्य रहती है। यह दिन की शुरुआत में मध्यरात्रि के बजाय **ब्राउज़र के स्थानीय टाइमज़ोन में उस दिन 23:59:59 पर समाप्त होती है**।

`2026-12-01` चुनने पर स्थानीय रूप से `2026-12-01T23:59:59` बनता है, फिर उस समय को UTC के रूप में संग्रहीत किया जाता है। UTC+1 वाले ब्राउज़र के लिए यह `2026-12-01T22:59:59.000Z` है। कुंजी 1 दिसंबर तक मान्य रहती है और स्थानीय समय 23:59:59 के बाद से समाप्त मानी जाती है (`expires_at <= now`)। API कुंजियाँ तालिका समाप्ति तिथि दिखाती है (या यदि कोई सेट नहीं की गई थी तो **कभी नहीं**)। उस समय के बाद स्थिति बैज बदलकर **समाप्त** (धूसर) हो जाता है; समाप्त कुंजियाँ सक्षम छोड़े जाने पर भी प्रमाणित नहीं कर सकतीं।

## कुंजी का उपयोग करना {/* #using-a-key */}

Duplicati कस्टम हेडर सेट नहीं कर सकता। कुंजी को रिपोर्ट URL में डालें:

```bash
--send-http-json-urls=https://your-host/api/upload?api_key=YOUR_KEY
```

Homepage विजेट समान क्वेरी पैरामीटर का उपयोग कर सकते हैं:

```yaml
url: http://your-host/api/summary?api_key=YOUR_READ_KEY
```

हेडर भेजने में सक्षम क्लाइंट इसके बजाय `X-Api-Key` या `Authorization: Bearer` का उपयोग कर सकते हैं। क्वेरी-स्ट्रिंग कुंजियाँ रिवर्स-प्रॉक्सी एक्सेस लॉग में दिखाई देती हैं।

## कुंजियाँ अनिवार्य करें {/* #require-keys */}

**बाहरी API के लिए API कुंजियाँ अनिवार्य करें** स्विच डिफ़ॉल्ट रूप से बंद होता है। जब तक यह बंद रहता है, बिना कुंजी वाले अनुरोधों की अनुमति होती है। यदि कोई क्लाइंट फिर भी कुंजी भेजता है, तो मान्य और मेल खाने वाले स्कोप की कुंजी स्वीकार और रिकॉर्ड की जाती है; अमान्य, अक्षम, समाप्त या गलत स्कोप वाली कुंजी को अनदेखा कर दिया जाता है और अनुरोध की अनुमति फिर भी दी जाती है। जब आप स्विच चालू करते हैं, तो मान्य कुंजी के बिना चारों बाहरी डेटा API `401` लौटाते हैं (और गलत कुंजियों को अस्वीकार करते हैं)। पहले कम से कम एक अपलोड कुंजी और एक रीड कुंजी सक्षम करें, अन्यथा Duplicati अपलोड और Homepage विजेट बंद हो जाएँगे। परिवर्तन स्वचालित रूप से सहेजे जाते हैं।

## बाहरी API सुरक्षा {/* #external-api-protection */}

यही पृष्ठ सार्वजनिक अपलोड और रीड API के लिए API कुंजियाँ अनिवार्य कर सकता है, और `/api/upload` के लिए अधिकतम बॉडी आकार (डिफ़ॉल्ट 5 MB) तथा प्रति-IP दर सीमाएँ कॉन्फ़िगर करता है। आकार और दर सीमाएँ तब भी लागू होती हैं जब कुंजियाँ वैकल्पिक हों और ये फ़्लडिंग से बचाव का मुख्य साधन हैं। स्विच और सीमा फ़ील्ड स्वचालित रूप से सहेजे जाते हैं; कोई अलग सहेजें बटन नहीं है।

[IP अनुमति सूची](ip-allowlist-settings.md) भी देखें। IP अनुमति सूची और API कुंजियाँ स्वतंत्र सुविधाएँ हैं; आप इनमें से किसी एक का या दोनों का एक साथ उपयोग कर सकते हैं। दोनों को सक्षम करने से आईपी पते के आधार पर पहुँच को प्रतिबंधित करके और API कुंजी अनिवार्य करके सुरक्षा बढ़ जाती है।
