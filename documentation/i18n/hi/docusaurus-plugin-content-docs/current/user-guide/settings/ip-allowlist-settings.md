# IP अनुमति सूची {/* #ip-allowlist */}

व्यवस्थापक यह सीमित कर सकते हैं कि एडमिन इंटरफ़ेस और बाहरी डेटा API तक कौन पहुंच सकता है। दोनों सूचियाँ स्वतंत्र हैं। दोनों डिफ़ॉल्ट रूप से बंद हैं।

![IP अनुमति सूची](../../assets/screen-settings-ip-allowlist.png)

एप्लिकेशन `scripts/peer-ip.cjs` द्वारा सेट किए गए आंतरिक हेडर से TCP पीयर पता पढ़ता है। कोई क्लाइंट उस हेडर को स्पूफ़ नहीं कर सकता है। **पहचाना गया IP** एक्सेस निर्णयों के लिए उपयोग किए जाने वाले TCP **पीयर IP** और **अनुमति सूची IP** को दिखाता है (वे तब तक मेल खाते हैं जब तक कि विश्वसनीय-प्रॉक्सी हेडर लागू न हों)।

अस्वीकृत अनुरोध HTTP 403 (API पाथ पर `IP_NOT_ALLOWED`) लौटाते हैं। उन्हें ऑडिट लॉग में नहीं लिखा जाता है। एप्लिकेशन stdout (उदाहरण के लिए `docker logs`) पर एक दर-सीमित (rate-limited) `console.warn` लाइन उत्सर्जित की जाती है — प्रति मिनट प्रति क्लाइंट IP और सतह (एडमिन, बाहरी, या प्रोब) पर अधिकतम एक लॉग, और प्रति घंटे दस — ताकि स्कैनर लॉग को भर न सकें।

## विश्वसनीय प्रॉक्सी {/* #trusted-proxies */}

**रिवर्स प्रॉक्सी हेडर पर भरोसा करें** को केवल तभी सक्षम करें जब duplistatus तक केवल ऐसे रिवर्स प्रॉक्सी के माध्यम से ही पहुंचा जा सके जो `X-Forwarded-For` / `X-Real-IP` को **ओवरराइट** करता हो (अपेंड न करें)। **जोड़ें** के साथ प्रत्येक प्रॉक्सी CIDR जोड़ें (या कॉमा- या न्यूलाइन-विभाजित सूची पेस्ट करें)। प्रविष्टियाँ हटाने योग्य चिप्स के रूप में दिखाई देती हैं। जब TCP पीयर उस सूची में नहीं होता है, तो फ़ॉरवर्ड किए गए हेडर को अनदेखा कर दिया जाता है।

## एडमिन इंटरफ़ेस {/* #admin-interface */}

सक्षम होने पर, पृष्ठ, लॉगिन, CSRF और सत्र API केवल सूचीबद्ध CIDR स्वीकार करते हैं। **जोड़ें** के साथ प्रविष्टियाँ जोड़ें; जब आपका वर्तमान **अनुमति सूची IP** सूची में होता है, तो उसे **मौजूदा IP** टैग किया जाता है। **127.0.0.1** और **::1** डिफ़ॉल्ट रूप से शामिल हैं और उन्हें हटाया नहीं जा सकता है। **वर्तमान IP जोड़ें** और **हाल के एडमिन लॉगिन IP** (ऑडिट लॉग से) त्वरित सुझाव प्रदान करते हैं। आप इस सूची को तब तक सक्षम नहीं कर सकते जब तक कि आपका वर्तमान IP पहले से शामिल न हो (या आप लूपबैक से कनेक्ट नहीं हो रहे हों)। लॉकआउट को निम्न के साथ पुनर्प्राप्त किया जा सकता है:

```bash
ADMIN_IP_ALLOWLIST_ENABLED=false
```

या अपने CIDR को `ADMIN_IP_ALLOWLIST` में जोड़कर। पुनर्प्राप्ति के पूर्ण चरण (Docker रीक्रिएट, फिर सेटिंग्स ठीक करें और ओवरराइड हटाएं) [Locked Out by IP Allowlist](../troubleshooting.md#locked-out-by-ip-allowlist) में हैं।

## बाहरी API {/* #external-apis */}

सक्षम होने पर, `/api/upload`, `/api/summary`, और `/api/lastbackup*` केवल सूचीबद्ध CIDR स्वीकार करते हैं।

`/api/health` और `/api/ping` अकेले बाहरी सूची में नहीं हैं (डैशबोर्ड पिंग एडमिन UI IP से आता है)। जब **कोई भी** अनुमति सूची सक्षम होती है, तो वे प्रोब लूपबैक (`127.0.0.1`, `::1`) और **एडमिन या बाहरी** सूची से CIDR स्वीकार करते हैं। गैर-सूचीबद्ध IP HTTP 403 प्राप्त करते हैं। जब दोनों सूचियाँ बंद होती हैं, तो प्रोब सार्वजनिक रहते हैं।

गैर-लूपबैक प्रोब अनुरोध भी दर-सीमित (HTTP 429, `PROBE_RATE_LIMITED`) होते हैं: `/api/ping` 60/मिनट और 600/घंटे; `/api/health` 30/मिनट और 120/घंटे। इन-कंटेनर Docker जाँच localhost पर पहुँचती हैं और कभी भी थ्रॉटल नहीं होती हैं। ऐप-स्तरीय सीमाएँ वॉल्यूमेट्रिक कनेक्शन फ़्लड को नहीं रोकती हैं; उसे रिवर्स प्रॉक्सी पर कॉन्फ़िगर करें।

API कुंजियों की आवश्यकता न होने पर उपयोग की जाने वाली सुरक्षा यह सूची है। एडमिन सूची की तरह ही CIDR को चिप्स के रूप में जोड़ें। **127.0.0.1** और **::1** डिफ़ॉल्ट रूप से शामिल हैं और उन्हें हटाया नहीं जा सकता। ऑडिट लॉग से **हाल के अपलोड स्रोत IP** त्वरित-जोड़ सुझावों के रूप में पेश किए जाते हैं।

यदि यह अनुमति सूची और API कुंजियाँ दोनों आवश्यक हैं, तो अनुरोध को **दोनों** पास करने होंगे।

## एनवायरनमेंट ओवरराइड {/* #environment-overrides */}

| वैरिएबल | उद्देश्य |
|----------|---------|
| `IP_TRUSTED_PROXIES` | कॉमा-विभाजित विश्वसनीय प्रॉक्सी CIDR (इसका अर्थ ट्रस्ट-प्रॉक्सी भी है) |
| `ADMIN_IP_ALLOWLIST_ENABLED` | `true` / `false` |
| `ADMIN_IP_ALLOWLIST` | कॉमा-विभाजित CIDR |
| `EXTERNAL_API_IP_ALLOWLIST_ENABLED` | `true` / `false` |
| `EXTERNAL_API_IP_ALLOWLIST` | कॉमा से अलग किए गए सीआईडीआर |

एनवायरनमेंट मान डेटाबेस को ओवरराइड करते हैं ताकि यूआई के बिना भी लॉकआउट को रिकवर किया जा सके।
