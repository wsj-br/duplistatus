# संस्करण 1.4.1 {#version-141}

## Overview {#overview}

संस्करण 1.4.1 डैशबोर्ड अनुभव में महत्वपूर्ण सुधार लाता है, जिसमें इनलाइन चार्ट नियंत्रण, बढ़ा हुआ फ़िल्टरिंग क्षमता, सिस्टम थीम समर्थन, और लोकेल फ़ॉर्मेटिंग विकल्प शामिल हैं। यह रिलीज़ चार्ट रेंडरिंग, बैकअप विवरण लोडिंग, और सर्वर कनेक्टिविटी डिटेक्शन के प्रभावित कई बगों को भी संबोधित करती है। इसके अलावा, निर्भरताओं में सुरक्षा कमजोरियों को भी हल कर दिया गया है।

---

## नई सुविधाएँ {#new-features}

### इनलाइन चार्ट नियंत्रण {#inline-chart-controls}

- **चार्ट समय सीमा चयनकर्ता**: डिस्प्ले सेटिंग्स में नेविगेट किए बिना त्वरित समय सीमा स्विचिंग के लिए चार्ट पैनल हेडर में स्टॉक-चार्ट-शैली पिल बटन (`1W | 2W | 1M | 3M`)। डिस्प्ले सेटिंग्स के साथ राज्य साझा करता है।
- **चार्ट शैली टॉगल (समस्या #54)**: चार्ट पैनल हेडर से सीधे लाइन और बार चार्ट के बीच स्विच करने के लिए टॉगल बटन। सभी पैनलों में स्थायी और सिंक किया गया है।
- **सरल समय सीमाएँ**: 7 विकल्पों से 4 केंद्रित सीमाओं में कम कर दिया गया है (1 सप्ताह, 2 सप्ताह, 1 महीना, 3 महीने), 1 महीना नया डिफ़ॉल्ट है।

### डिस्प्ले और फ़ॉर्मेटिंग विकल्प {#display-and-formatting-options}

- **सिस्टम थीम समर्थन**: डिस्प्ले सेटिंग्स में "सिस्टम (OS का पालन करें)" विकल्प शामिल है, जो आपकी ऑपरेटिंग सिस्टम की लाइट/डार्क प्राथमिकता को स्वचालित रूप से मैच करता है।
- **फ़ॉर्मेट लोकेल ओवरराइड (समस्या #59)**: उपयोगकर्ता UI भाषा के स्वतंत्र रूप से फ़ॉर्मेटिंग लोकेल का चयन कर सकते हैं, सेटिंग्स > डिस्प्ले सेटिंग्स में (416 लोकेल समर्थित)। तारीख, समय, और संख्या फ़ॉर्मेटिंग चयनित फ़ॉर्मेट लोकेल का पालन करता है, लाइव पूर्वावलोकन के साथ।

### सर्वर फ़िल्टरिंग {#server-filtering}

- **डैशबोर्ड सर्वर फ़िल्टर**: खोज फ़ील्ड को ऐप हेडर में स्थानांतरित कर दिया गया है, ऑटो-रिफ्रेश और टूलबार क्रियाओं के साथ। नियंत्रण खाली होने पर केवल खोज आइकन दिखाता है; होवर/क्लिक टेक्स्ट फ़ील्ड को विस्तारित करता है।
- **बढ़ा हुआ फ़िल्टर मैचिंग (समस्या #53)**: फ़िल्टर अब सर्वर आईडी, URL, और किसी भी बैकअप जॉब नाम से मैच करता है। फ़िल्टर बदलने पर अवलोकन कार्ड ग्रिड अपडेट नहीं होने की समस्या को ठीक किया गया है।
- **सेटिंग्स फ़िल्टरिंग**: सेटिंग्स > बैकअप मॉनिटरिंग और सेटिंग्स > सर्वर में सर्वर सूचियों में फ़िल्टर इनपुट जोड़ा गया है।

## सुधार {#improvements}

### चार्ट डेटा हैंडलिंग {#chart-data-handling}

- **रोलिंग समय विंडोज**: समय सीमाएँ अब रोलिंग दिन विंडोज का उपयोग करती हैं: 1W = अंतिम 7 दिन, 2W = अंतिम 14 दिन, 1M = अंतिम 30 दिन, 3M = अंतिम 90 दिन (पहले कैलेंडर-आधारित थे)।
- **डेटा संयोजन**: बकेटिंग से पहले कैलेंडर दिन द्वारा सभी चार्ट डेटा पॉइंट्स संयोजित किए गए। एक ही दिन पर कई बैकअप को उचित रूप से संयोजित किया गया है।
- **सीमित डेटा पॉइंट्स**: चार्ट अब बेहतर प्रदर्शन और पठनीयता के लिए अधिकतम 30 डेटा पॉइंट्स को लागू करते हैं।
- **टूलटिप सरलता**: टूलटिप अब केवल तारीख (उदाहरण के लिए, "5/12/26") को प्रदर्शित करती है, तारीख और समय के बजाय।

### बैकअप शेड्यूलिंग {#backup-scheduling}

- **UTC-आधारित गणना**: अगली अपेक्षित बैकअप और विलंबित पता लगाने अब UTC में अंतराल और वीकडे चेक को आगे बढ़ाता है, स्थानीय समय के बजाय, जब होस्ट समय क्षेत्र डीएसटी को पार करता है तो एक घंटे का UTC ड्रिफ्ट से बचाता है।
- **बढ़ा हुआ विलंबित सहिष्णुता**: नए इंस्टॉल और डिफ़ॉल्ट अब विलंबित सहिष्णुता के लिए 2 घंटे का उपयोग करते हैं, 1 घंटे के बजाय।

### कनेक्टिविटी और विश्वसनीयता {#connectivity-and-reliability}

- **कनेक्टिविटी लॉस डिटेक्शन**: `/api/ping` एंडपॉइंट और 30-सेकंड हेडर-आधारित कनेक्टिविटी प्रोब जोड़ा गया है। रिफ्रेश और ऑटो-रिफ्रेश विफलताएँ अब कच्ची त्रुटि पाठ को प्रकट किए बिना लॉस्ट-कनेक्शन मोडल खोलती हैं।
- **UI प्राथमिकताओं की स्थिरता**: उपयोगकर्ता UI प्राथमिकताओं (अवलोकन साइड पैनल, चार्ट समय सीमा, चार्ट शैली) को पृष्ठ रिफ्रेश पर स्थिर नहीं होने वाली रेस कंडीशन की समस्या को ठीक किया गया।

### Documentation {#documentation}

- **डुप्लिकेटी रिमोट एक्सेस स्पष्टीकरण (समस्या #40)**: दस्तावेज़ अब स्पष्ट करते हैं कि डुप्लिकेटी रिमोट एक्सेस वैकल्पिक है और केवल तभी आवश्यक है जब डुप्लिकेटी UI के सीधे लिंक की आवश्यकता होती है।

## बग ठीक {#bug-fixes}

- **अवलोकन चार्ट पैनल समय सीमा फ़िल्टर को अनदेखा करना**: पैनल अब सभी डेटा पॉइंट्स को प्रदर्शित करता है, चयनित समय सीमा के बावजूद। पैनल अब उचित समय सीमा पैरामीटर के साथ API से अपने स्वयं के डेटा को फेच करता है।
- **बैकअप विवरण पर OOM क्रैश (समस्या #62)**: क्वेरी और UI रेंडरिंग को अनुकूलित करके `JavaScript heap out of memory` को रोक दिया गया। बैकअप लॉग अब एक बार में सभी लोड किए जाने के बजाय ऑन-डिमांड फेच किए जाते हैं, 1000 लाइनों की अधिकतम सीमा के साथ।
- **बैकअप संस्करण पार्सिंग (समस्या #65)**: `convertTimestampToISO()` अब डुप्लिकेटी द्वारा विभिन्न सिस्टम लोकेल्स में उपयोग किए जाने वाले सभी सामान्य लोकेल-विशिष्ट टाइमस्टैम्प फ़ॉर्मेट्स को संभालता है।

## सुरक्षा {#security}

### निर्भरता कमजोरी ठीक {#dependency-vulnerability-fixes}

- **npm audit vulnerabilities**: 7 vulnerabilities (1 uchch, 6 madhyam) hal kar diye:
  - `postcss@8.4.31` (XSS) hal karne ke liye `next` ko `16.3.0-canary.19` tak update kiya gaya
  - `serialize-javascript@^7.0.5` (RCE, DoS) hal karne ke liye `.pnpmfile.cjs` add kiya gaya
  - 4 madhyam vulnerabilities hal karne ke liye `mermaid` override ko `>=11.14.1` tak update kiya gaya
  - `postcss@^8.5.14` aur `serialize-javascript@^7.0.5` dependencies explicitly add kiya gaya

- **pnpm overrides**: transitive `uuid >=14.0.0` aur `postcss >=8.5.10` ke liye root `pnpm.overrides` add kiya gaya.

- **High-severity vulnerabilities**: `minimatch >=3.1.4` aur `serialize-javascript >=7.0.3` ke liye pnpm overrides ke through 4 high-severity vulnerabilities hal kiya gaya.

## माइग्रेशन नोट्स {#migration-notes}

### Sanskaran 1.3.2 se {#from-version-132}

Sanskaran 1.4.1 tak upgrade karte waqt:

1. **Database migration ki zarurat nahi**: Is release mein koi database schema changes ki zarurat nahi hai.
2. **Naya default overdue tolerance**: Naye installations mein 1 ghante ke bajaye 2 ghante overdue tolerance default hoga. Pichle sammaan baki rahenge.
3. **Chart preferences**: Chart samay pariman aur shaili preferences ab alag tarike se store kiya jata hai aur upgrade ke baad defaults (1 Mahina, Rekha chart) tak reset ho jayenge.
4. **Dependencies**: Updated lockfile aur overrides lagane ke liye `pnpm install` chalao.

## चेंजलॉग {#changelog}

### Sanskaran 1.4.1 changes {#version-141-changes}

- **Add kiya gaya**: Chart panel headers mein pill buttons (1W, 2W, 1M, 3M) ke saath Inline Chart Time Range Selector.
- **Add kiya gaya**: Chart panel header se line aur bar charts (issue #54) ke beech switch karne ke liye Inline Chart Style Toggle.
- **Add kiya gaya**: Display Settings mein Chart Style setting (Samaan rekhaen / Bar Chart toggle).
- **Add kiya gaya**: Theme "System (OS ka palan karen)" option add kiya gaya jo OS preference ko automatically match karta hai.
- **Add kiya gaya**: Format locale override (issue #59) — UI language ke alawa formatting locale independently select kare (416 locales supported).
- **Add kiya gaya**: Settings > Backup Monitoring, Settings > Servers, aur main Dashboard mein Server filtering (issue #53).
- **Add kiya gaya**: Connectivity loss detection `/api/ping` aur 30-second header-based probe ke saath.
- **Changed**: Chart Time Range options 7 se 4 tak kam kiya gaya (1W, 2W, 1M, 3M), default ab 1 mahina hai.
- **Changed**: Time range calculations ab rolling day windows ka use karte hain (1W = last 7 days, etc.).
- **Changed**: Chart data bucketing se pehle calendar day ke hisaab se consolidate kiya gaya; maximum 30 data points enforce kiya gaya.
- **Changed**: Chart tooltip ab sirf taareekh dikhata hai date aur time ke bajaye.
- **Changed**: Naye installations ke liye default overdue tolerance 1h se 2h tak badal diya gaya.
- **Changed**: Next expected backup calculations ab UTC ka use karte hain DST drift issues se bachne ke liye.
- **Changed**: Dashboard server filter ab app header mein hota hai aur auto-refresh ke saath.
- **Fixed**: Page refresh par user UI preferences persist nahi hoti.
- **Fixed**: Overview charts panel time range filter ko ignore karta hai.
- **Fixed**: Backup details par OOM crash (issue #62) — logs ab on-demand fetch hote hain 1000 line limit ke saath.
- **Fixed**: Locale-specific timestamp formats ke liye backup version parsing (issue #65).
- **Security**: Dependency updates aur pnpm overrides ke through 7 npm audit vulnerabilities hal kiya gaya.
- **Security**: `minimatch` aur `serialize-javascript` mein high-severity vulnerabilities hal kiya gaya.
