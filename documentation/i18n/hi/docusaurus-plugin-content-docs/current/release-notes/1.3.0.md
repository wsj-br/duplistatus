# संस्करण 1.3.0 {#version-130}

## Overview {#overview}

संस्करण 1.3.0 में कॉन्फ़िगर करने योग्य पासवर्ड नीति, प्रशासक के लिए एक नया एप्लिकेशन लॉग्स व्यूअर, लोकल-आवरे वीकडे डिस्प्ले, और कई उपयोगकर्ता अनुभव सुधार शामिल हैं। यह रिलीज़ प्रशासनिक उपकरणों को बढ़ाने और अंतर्राष्ट्रीयकरण समर्थन को सुधारने पर ध्यान केंद्रित करता है।

## New Features {#new-features}

### कॉन्फ़िगर करने योग्य पासवर्ड नीति {#configurable-password-policy}

- **पासवर्ड नीति पर्यावरण चर**: पर्यावरण चर के माध्यम से पासवर्ड सत्यापन आवश्यकताओं को कॉन्फ़िगर करें:
  - `PWD_ENFORCE`: पासवर्ड जटिलता आवश्यकताओं (अप्परकेस, लोअरकेस, संख्याएँ) को निष्क्रिय करने के लिए `false` सेट करें। डिफ़ॉल्ट रूप से सभी नियमों को लागू किया जाता है। जब निष्क्रिय किया जाता है, तो केवल न्यूनतम लंबाई लागू होती है।
  - `PWD_MIN_LEN`: वर्णों में न्यूनतम पासवर्ड लंबाई सेट करता है। डिफ़ॉल्ट रूप से 8 वर्ण।
  - डिफ़ॉल्ट पासवर्ड चेक (डिफ़ॉल्ट एडमिन पासवर्ड का उपयोग रोकना) हमेशा लागू होता है, भले ही `PWD_ENFORCE` सेटिंग हो।

### एप्लिकेशन लॉग्स व्यूअर {#application-logs-viewer}

- **नया प्रशासक-केवल लॉग्स व्यूअर**: सेटिंग्स पृष्ठ से सीधे एप्लिकेशन लॉग्स देखें और डाउनलोड करें:
  - एकीकृत `application.log` फ़ाइल और रोटेटेड लॉग संस्करणों तक पहुंच
  - कॉन्फ़िगर करने योग्य लाइन काउंट सेलेक्टर (100, 500, 1000, 5000, 10000 लाइनों)
  - रियल-टाइम खोज फ़िल्टर केस-इनसेंसिटिव टेक्स्ट मैचिंग के साथ
  - रियल-टाइम लॉग मॉनिटरिंग के लिए ऑटो-स्क्रॉल टॉगल ऑटोमेटिक पोलिंग के साथ
  - क्लिपबोर्ड पर कॉपी करें और फ़िल्टर किए गए लॉग्स को टेक्स्ट फ़ाइल के रूप में निर्यात करें
  - लाइन काउंट, फ़ाइल आकार, और अंतिम संशोधित टाइमस्टैम्प दिखाने वाला फ़ाइल मेटाडेटा डिस्प्ले
  - कंटेनर स्टार्टअप पर लॉग रोटेशन (`LOG_ROTATION_VERSIONS` के माध्यम से कॉन्फ़िगर किया जा सकता है, डिफ़ॉल्ट: 5)

### संदर्भ-आधारित उपयोगकर्ता गाइड {#context-aware-user-guide}

- **डायनैमिक हेल्प बटन**: ऐप हेडर में उपयोगकर्ता गाइड बटन अब वर्तमान पृष्ठ के लिए प्रासंगिक दस्तावेज़ खोलता है। टूलटिप अपडेट हो जाता है ताकि "`Page Name` के लिए सहायता" दिखाया जा सके, जो दर्शाता है कि कौन सा दस्तावेज़ खुला जाएगा।

### सर्वर कॉन्फ़िगरेशन सुधार {#server-configuration-enhancement}

- **डुप्लिकेटी यूआई तक त्वरित पहुंच**: सर्वर कॉन्फ़िगरेशन बटन या सर्वर चयन पॉपओवर में किसी भी सर्वर आइटम पर राइट-क्लिक करने से डुप्लिकेटी लेगसी यूआई (`/ngax`) एक नए टैब में खुल जाता है।

## 🔧 सुधार {#-improvements}

### लोकल-आवरे वीकडे डिस्प्ले {#locale-aware-weekday-display}

- **अंतर्राष्ट्रीयकृत वीकडे क्रमबद्धता**: बैकअप मॉनिटरिंग फॉर्म में वीकडे डिस्प्ले अब आपके ब्राउज़र के लोकल सेटिंग्स का सम्मान करता है। वीकडे लोकल के आधार पर सही क्रम में प्रदर्शित होते हैं (UK/यूरोप के लिए सोमवार-रविवार, US/ब्राज़ील के लिए रविवार-शनिवार)।

### सुधारित SMTP त्रुटि हैंडलिंग {#enhanced-smtp-error-handling}

- **सुधारित त्रुटि संदेश**: SMTP त्रुटि संदेश अब अधिक सटीक मार्गदर्शन प्रदान करते हैं:
  - प्रमाणीकरण त्रुटियाँ स्पष्ट रूप से उपयोगकर्ता नाम/पासवर्ड मुद्दों को दर्शाती हैं
  - SSL/TLS संस्करण त्रुटियाँ सही ढंग से पहचानी जाती हैं
  - कनेक्शन प्रकार सुझाव केवल तब दिखाई देते हैं जब वास्तव में प्रासंगिक हों

### टोस्ट सूचना व्यवहार {#toast-notification-behaviour}

- **स्थायी त्रुटि सूचनाएं**: त्रुटि टोस्ट अब मैन्युअल रूप से बंद किए जाने तक स्थायी रहती हैं, यह सुनिश्चित करते हुए कि आप महत्वपूर्ण त्रुटि संदेशों को नहीं छूटते। सफलता और सूचनात्मक टोस्ट 3 सेकंड के बाद स्वचालित रूप से डिस्मिस हो जाते हैं।

### सूचना सेटिंग्स तालिका {#notification-settings-table}

- **सरलित लेआउट**: सूचना सेटिंग्स तालिका को एक संयुक्त "सर्वर / बैकअप" कॉलम के साथ सरलित किया गया है और अतिरिक्त गंतव्य कॉन्फ़िगरेशन स्थिति को दर्शाने वाले संदर्भात्मक आइकन शामिल हैं।

## 🚀 माइग्रेशन नोट्स {#-migration-notes}

### Sanskaran 1.2.x se {#from-version-12x}

Sanskaran 1.3.0 mein upgrade karte samay:

1. **Password Policy**: Nayi password policy default roop se sabhi complexity requirements ko lagu karti hai. Yadi aapko ek saral password policy ki avashyakta hai, to `PWD_ENFORCE` aur `PWD_MIN_LEN` environment variables ko configure karein.

2. **Application logs**: Sabhi container output (server aur cron service) ab ek hi `data/logs/application.log` file mein samahit hain.

3. **Log Rotation**: Log rotation ko `LOG_ROTATION_VERSIONS` environment variable ke madhyam se configure kiya ja sakta hai (default: 5 sanskaran).

4. **No Database Migration Required**: This release does not require any database schema changes.

## API Endpoints {#api-endpoints}

Is sanskaran mein nimnalikhit API endpoint prastut kiya gaya hai:

### Password Policy Endpoint {#password-policy-endpoint}

- `GET /api/auth/password-policy` - Vartaman password policy configuration pradan karta hai

### Application Logs Endpoints {#application-logs-endpoints}

- `GET /api/application-logs` - File selection aur tail functionality ke saath logs dekhein
- `GET /api/application-logs/export` - Filter kiye gaye logs ko text file ke roop mein export karein

### Hataye gaye Endpoints {#removed-endpoints}

Is sanskaran mein nimnalikhit unused API endpoints hata diye gaye hain:

- `DELETE /api/backups/[backupId]` - Keval development-only endpoint jiska kabhi upyog nahi kiya gaya
- `GET /api/audit-log/stats` - Endpoint ko Audit Log Viewer dwara call nahi kiya gaya tha

## चेंजलॉग {#changelog}

### Sanskaran 1.3.0 Badlav {#version-130-changes}

- **Added**: `PWD_ENFORCE` aur `PWD_MIN_LEN` environment variables ke madhyam se configurable password policy
- **Added**: Sammaan mein Application Log Viewer (keval admin ke liye)
- **Added**: Configurable version count ke saath Log rotation (`LOG_ROTATION_VERSIONS`)
- **Added**: Context-aware Upyogkarta Guide button jo sambandhit documentation kholta hai
- **Added**: Duplicati legacy UI kholne ke liye server configuration par right-click karein
- **Added**: Password policy configuration ke liye API endpoint `GET /api/auth/password-policy`
- **Added**: Application logs dekhne aur export karne ke liye API endpoints
- **Changed**: Weekday display ab browser locale settings ka palan karta hai
- **Changed**: Truti toasts tab tak bane rehte hain jab tak unhe manually band na kiya jaye
- **Changed**: Safalta toasts 3 seconds ke baad auto-dismiss ho jate hain (pichle 5 seconds)
- **Changed**: Notification sammaan table ko combined "Server / Backup" column ke saath saral banaya gaya
- **Changed**: Sabhi container logs ko ek hi `application.log` file mein samahit kiya gaya
- **Improved**: SMTP truti sandesh adhik sateek margdarshan pradan karte hain
- **Removed**: Unused API endpoints (`DELETE /api/backups/[backupId]` aur `GET /api/audit-log/stats`) jinhe application dwara call nahi kiya ja raha tha
