# संस्करण 0.9.x {#version-09x}

## Overview {#overview}

संस्करण 0.9.x एक प्रमुख रिलीज़ है जो एक व्यापक **उपयोगकर्ता एक्सेस कंट्रोल & सुरक्षा प्रणाली** पेश करता है। यह रिलीज़ **duplistatus** को एक खुले-एक्सेस एप्लिकेशन से एक सुरक्षित, बहु-उपयोगकर्ता प्रणाली में बदल देता है जिसमें भूमिका-आधारित एक्सेस कंट्रोल, व्यापक ऑडिट लॉगिंग, और एंटरप्राइज़-ग्रेड सुरक्षा सुविधाएँ हैं। सभी मौजूदा कार्यक्षमता अब प्रमाणीकरण के पीछे सुरक्षित है, यह सुनिश्चित करते हुए कि केवल अधिकृत उपयोगकर्ता बैकअप मॉनिटरिंग को एक्सेस और प्रबंधित कर सकते हैं।

## Breaking Changes {#breaking-changes}

### प्रमाणीकरण आवश्यक {#authentication-required}

- **सभी पृष्ठ अब प्रमाणीकरण की आवश्यकता हैं** - उपयोगकर्ताओं को एप्लिकेशन तक पहुंचने के लिए लॉग इन करना होगा
- **डिफ़ॉल्ट एडमिन खाता** स्वचालित रूप से बनाया जाता है:
  - उपयोगकर्ता नाम: `admin`
  - पासवर्ड: `Duplistatus09` (पहले लॉगिन पर बदलना होगा)
- **मौजूदा सत्र अमान्य हैं** - अपग्रेड के बाद सभी उपयोगकर्ताओं को लॉग इन करना होगा
- **API एंडपॉइंट अब प्रमाणीकरण की आवश्यकता हैं** - बाहरी एकीकरण में सत्र कुकीज़ शामिल करनी चाहिए या प्रमाणित अनुरोधों का उपयोग करना चाहिए

:::warning
**सभी उपयोगकर्ताओं को संस्करण 0.9.x पर अपग्रेड करने के बाद लॉग इन करना होगा।** डिफ़ॉल्ट एडमिन क्रेडेंशियल हैं admin/Duplistatus09। पहले लॉगिन के बाद तुरंत पासवर्ड बदलें।
:::

### डेटाबेस स्कीमा माइग्रेशन {#database-schema-migration}

- **v3.1 से v4.0 के लिए स्वचालित माइग्रेशन** मौजूदा स्थापनाओं के लिए
- **नए तालिकाएँ जोड़ी गईं**: `users`, `sessions`, `audit_log`
- **माइग्रेशन से पहले स्वचालित रूप से डेटाबेस बैकअप बनाया गया**
- **नए स्थापनाएँ** सीधे स्कीमा v4.0 से शुरू होती हैं (कोई माइग्रेशन की आवश्यकता नहीं)

## New Features {#new-features}

### उपयोगकर्ता एक्सेस कंट्रोल & सुरक्षा प्रणाली {#user-access-control--security-system}

#### प्रमाणीकरण प्रणाली {#authentication-system}

- **उपयोगकर्ता लॉगिन/लॉगआउट कार्यक्षमता** सुरक्षित सत्र प्रबंधन के साथ
- **पासवर्ड-आधारित प्रमाणीकरण** bcrypt हैशिंग के साथ (लागत कारक 12)
- **खाता लॉकआउट यांत्रिकी** (5 असफल प्रयास, 15-मिनट लॉकआउट)
- **पहले लॉगिन पर पासवर्ड बदलना**
- **पासवर्ड नीति प्रवर्तन**:
  - न्यूनतम 8 अक्षर
  - कम से कम एक अपरकेस अक्षर
  - कम से कम एक लोअरकेस अक्षर
  - कम से कम एक संख्या
  - विशेष अक्षर वैकल्पिक
- **"मुझे याद रखें" कार्यक्षमता** उपयोगकर्ता नाम स्थायीकरण के साथ localStorage में
- **सत्र-आधारित प्रमाणीकरण** डेटाबेस-बैक्ड सत्रों के साथ (इन-मेमरी से बदलाव)
- **CSRF सुरक्षा** प्रमाणीकरण के साथ एकीकृत
- **HTTP-केवल कुकीज़** सत्र सुरक्षा के लिए
- **IP पते और उपयोगकर्ता एजेंट ट्रैकिंग** सुरक्षा मॉनिटरिंग के लिए

#### उपयोगकर्ता प्रबंधन (केवल एडमिन) {#user-management-admin-only}

- **उपयोगकर्ता निर्माण** स्वचालित अस्थायी पासवर्ड जनरेशन के साथ
- **उपयोगकर्ता सूची** खोज, पेजिनेशन, और फ़िल्टरिंग के साथ
- **उपयोगकर्ता संपादन** (उपयोगकर्ता नाम, एडमिन स्थिति, पासवर्ड बदलने की आवश्यकता)
- **पासवर्ड रीसेट कार्यक्षमता** अस्थायी पासवर्ड प्रदर्शन के साथ
- **उपयोगकर्ता हटाने** सुरक्षाओं के साथ (अंतिम एडमिन को हटाने से रोकता है)
- **भूमिका-आधारित एक्सेस कंट्रोल** (एडमिन/उपयोगकर्ता भूमिकाएँ)
- **स्थिति इंडिकेटर** (सक्रिय, लॉक किया गया, पासवर्ड बदलना है)
- **अंतिम लॉगिन ट्रैकिंग** और प्रदर्शन

#### ऑडिट लॉगिंग प्रणाली {#audit-logging-system}

- **Sabhi Pranali aur Upyogkarta Kriyaen ke liye Sampradayaik Audit Trail**
- **Audit Log Viewer** with advanced filtering:
  - Taareekh range filtering
  - Upyogkarta filtering
  - क्रिया फ़िल्टरिंग
  - श्रेणी फ़िल्टरिंग
  - स्थिति फ़िल्टरिंग
- **निर्यात कार्यक्षमता** (CSV और JSON प्रारूप)
- **Audit log statistics** aur analytics
- **Configurable retention period** (30-365 din, default: 90 din)
- **Automatic cleanup cron job** (har din 2 AM UTC par chalta hai)
- **Manual cleanup API** dry-run support ke saath
- **Audit logging for**:
  - Authentication events (login, logout, password changes, account lockouts)
  - User management operations (create, update, delete, password resets)
  - Configuration changes (email, NTFY, templates, overdue tolerance, backup settings)
  - Backup operations (collection, deletion, cleanup)
  - Server management (add, update, delete)
  - System operations (migrations, cleanup, notifications)

### User Interface Enhancements {#user-interface-enhancements}

- **Standalone login page** modern design ke saath

## 🚀 माइग्रेशन नोट्स {#-migration-notes}

### From Version 0.8.x {#from-version-08x}

This release introduces authentication and requires all users to log in. When upgrading from version 0.8.x:

1. **Automatic Database Migration**: The application will automatically migrate your database schema from v3.1 to v4.0
2. **Database Backup**: An automatic backup is created before migration
3. **Default Admin Account**: A default admin account is created:
   - Username: `admin`
   - Password: `Duplistatus09`
   - **You must change this password on first login**
4. **Session Invalidation**: All existing sessions are invalidated
5. **User Login Required**: All users must log in after upgrade
6. **API Authentication**: External integrations must be updated to include authentication

### सुरक्षा विचार {#security-considerations}

- **Change Default Password**: Change the default admin password immediately after first login
- **Create User Accounts**: Create individual user accounts for each person who needs access
- **Review Audit Logs**: Check audit logs regularly for security monitoring
- **Configure Retention**: Set appropriate audit log retention period based on your compliance requirements
- **Backup Master Key**: If upgrading from 0.8.x, ensure the `.duplistatus.key` file is backed up

### First Login Steps {#first-login-steps}

1. **Log in** with default credentials (`admin` / `Duplistatus09`)
2. **Change password** when prompted (forced on first login)
3. **Create user accounts** for other users (Settings → Users)
4. **Configure audit log retention** if needed (Settings → Audit Log)
5. **Review audit logs** to verify system is working correctly

## API Endpoints {#api-endpoints}

### Authentication Endpoints {#authentication-endpoints}

- `POST /api/auth/login` - User authentication
- `POST /api/auth/logout` - Session termination
- `GET /api/auth/me` - Current user information
- `POST /api/auth/change-password` - Password change

### User Management Endpoints (Admin Only) {#user-management-endpoints-admin-only}

- `GET /api/users` - List users
- `POST /api/users` - Create user
- `PATCH /api/users/{id}` - Update user
- `DELETE /api/users/{id}` - Delete user

### Audit Log Endpoints {#audit-log-endpoints}

- `GET /api/audit-log` - Query audit logs
- `GET /api/audit-log/download` - Export audit logs
- `GET /api/audit-log/stats` - Audit statistics
- `POST /api/audit-log/cleanup` - Manual cleanup (admin only)
- `GET /api/audit-log/retention` - Get retention setting
- `PATCH /api/audit-log/retention` - Update retention (admin only)

:::note
All API endpoints now require authentication. See the [API Reference](../api-reference/authentication-security.md) for details on authentication.
:::
