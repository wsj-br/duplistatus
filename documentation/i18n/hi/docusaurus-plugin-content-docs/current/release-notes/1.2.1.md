# संस्करण 1.2.1 {#version-121}

## Overview {#overview}

संस्करण 1.2.1 एक छोटा रिलीज़ है जो बैकअप सूचना प्रबंधन में महत्वपूर्ण सुधार करता है, ऑडिट लॉगिंग क्षमताओं को बेहतर बनाता है, एज केस में अगला चलन/विलंबित पता लगाने को ठीक करता है और डेटाबेस बैकअप और पुनर्स्थापना कार्यक्षमता जोड़ता है। यह रिलीज़ सूचना सेटिंग्स के साथ उपयोगकर्ता अनुभव को बेहतर बनाने पर ध्यान केंद्रित करता है।

## New Features {#new-features}

### सुधारित बैकअप सूचना प्रबंधन {#enhanced-backup-notifications-management}

- **सर्वर-स्तरीय डिफ़ॉल्ट और विरासत प्रणाली**: सर्वर स्तर पर डिफ़ॉल्ट अतिरिक्त गंतव्यों (सूचना घटनाएँ, ईमेल, और NTFY विषय) को कॉन्फ़िगर करें जो सभी बैकअप स्वचालित रूप से विरासत में लेते हैं। बैकअप आवश्यकता पड़ने पर इन डिफ़ॉल्ट को ओवरराइड कर सकते हैं, जिसमें विरासत स्थिति दिखाने वाले स्पष्ट दृश्य संकेतक होते हैं।
- **सुधारित दृश्य हायरार्की**: बैकअप अब सर्वर के अनुसार समूहबद्ध किए जाते हैं, जिसमें अलग-अलग सर्वर हेडर पंक्तियाँ होती हैं। विरासत में प्राप्त मान लिंक आइकन के साथ स्पष्ट रूप से चिह्नित किए जाते हैं, और ओवरराइड किए गए मान को आसानी से विरासत में वापस लाया जा सकता है।
- **बुल्क ऑपरेशन**: "सभी के साथ सिंक करें" बटन सभी बैकअप ओवरराइड को साफ़ करता है ताकि सभी बैकअप सर्वर डिफ़ॉल्ट से विरासत में लें। "सभी साफ़ करें" बटन सभी अतिरिक्त गंतव्यों को साफ़ करता है जबकि विरासत संरचना बनाए रखता है।
- **टेस्ट कार्यक्षमता**: बैकअप सूचना सेटिंग्स पृष्ठ में टेस्ट ईमेल और टेस्ट सूचना बटन जोड़े गए हैं। टेस्ट बटन व्यक्तिगत बैकअप सेटिंग्स और बुल्क संपादन ऑपरेशन दोनों के लिए उपलब्ध हैं, जिससे आप परिवर्तनों को लागू करने से पहले सूचना वितरण की पुष्टि कर सकते हैं।
- **QR कोड समर्थन**: NTFY विषयों के लिए आसानी से मोबाइल डिवाइसों के साथ सूचना विषय साझा करने के लिए QR कोड बटन जोड़ा गया है।

### सूचना टेम्पलेट सुधार {#notification-template-enhancements}

- **नया `{log_text}` चर**: सूचना टेम्पलेट में `{log_text}` चर जोड़ा गया है, जिससे लॉग टेक्स्ट संदेशों तक पहुंच मिलती है, जो सूचना संदेशों में उपयोग के लिए हैं। चर में चेतावनियों और त्रुटियों के पूर्ण टेक्स्ट को एक पंक्ति में एक आइटम के रूप में सादा टेक्स्ट के रूप में शामिल किया गया है।
- **स्वचालित टेम्पलेट माइग्रेशन**: प्रणाली में एक लेज़ी अपग्रेड यांत्रिकी शामिल है जो स्वचालित रूप से पुराने डिफ़ॉल्ट टेम्पलेट को अपग्रेड करने के लिए पहचानती है जब वे पहली बार अपग्रेड के बाद पढ़े जाते हैं। कस्टम टेम्पलेट को अपरिवर्तित रखा जाता है।

### डेटाबेस प्रबंधन {#database-management}

- **डेटाबेस बैकअप कार्यक्षमता**: व्यवस्थापक अब डेटाबेस प्रबंधन सेटिंग्स पृष्ठ से पूरे डेटाबेस का बैकअप बना सकते हैं। लचीलापन के लिए बाइनरी (.db) और SQL टेक्स्ट (.sql) प्रारूप दोनों का समर्थन करता है।
- **डेटाबेस पुनर्स्थापना कार्यक्षमता**: पूर्व में बनाए गए बैकअप फ़ाइलों से डेटाबेस को पुनर्स्थापित करें, जिसमें स्वचालित सुरक्षा बैकअप निर्माण, एकीकरण सत्यापन, और विफलता पर रोलबैक शामिल है। सुरक्षा के लिए पुनर्स्थापना के बाद सभी सत्र साफ़ किए जाते हैं।

### मास्टर कुंजी पता लगाने {#master-key-detection}

- **स्वचालित मास्टर कुंजी बदलाव पता लगाने**: लॉगिन के बाद, प्रणाली स्वचालित रूप से जाँचती है कि क्या `.duplistatus.key` फ़ाइल बदल गई है। यदि पता चलता है, तो सभी एन्क्रिप्टेड पासवर्ड साफ़ किए जाते हैं और एक मोडल पॉपअप उपयोगकर्ताओं को सूचित करता है कि पासवर्ड को फिर से कॉन्फ़िगर करने की आवश्यकता है। यह बैकअप से पुनर्स्थापित करने या नए प्रणाली पर माइग्रेट करने के दौरान त्रुटियों को रोकता है।

### बैकअप मॉनिटरिंग सुधार {#backup-monitoring-improvements}

- **सुधारित CSV निर्यात**: बैकअप मॉनिटरिंग सेटिंग्स में "डाउनलोड CSV" बटन द्वारा उत्पन्न CSV फ़ाइल में "अंतिम बैकअप टाइमस्टैम्प (DB)" कॉलम जोड़ा गया है। इससे उपयोगकर्ता डेटाबेस से वास्तविक अंतिम बैकअप टाइमस्टैम्प को कॉन्फ़िगर किए गए "अंतिम बैकअप" टाइमस्टैम्प के साथ तुलना कर सकते हैं।
- **अगला चलन टूलटिप**: प्रत्येक पंक्ति में "अगला चलन" मान पर होवर करने पर एक टूलटिप प्रदर्शित होता है जो डेटाबेस से अंतिम बैकअप टाइमस्टैम्प दिखाता है, जिसका प्रारूप "अगला चलन" प्रदर्शन के समान है।

### Audit Logging Enhancements {#audit-logging-enhancements}

- **Individual notification audit entries**: Each notification and email sent now generates a separate audit log entry with details about the channel, configuration, and outcome (success or failure). This includes test notifications, providing better traceability for notification delivery.
- **Robust failure logging**: All audit logging operations for notification failures are now wrapped in try-catch blocks to prevent audit logging errors from breaking notification flows. The system attempts to retrieve SMTP configuration if it's not immediately available when logging email failures.
- **Improved audit logging for configuration updates**: Both `email_config_updated` and `ntfy_config_updated` audit log entries now only record when there are actual changes to the configuration. When changes are detected, the audit log includes old and new values for each modified field, making it easier to track what specifically changed.

### Documentation improvements {#documentation-improvements}

- The documentation style has been updated to align with the application's look and feel. The sidebar has also been revised to improve visibility and make navigation easier.

## 🐛 बग फिक्स {#-bug-fixes}

- **Fixed audit log timestamps**: Timestamps in the audit log viewer now correctly display in the user's browser timezone instead of GMT. SQLite timestamps (stored in UTC) are now properly parsed as UTC and converted to the browser's local timezone for display.
- **Corrected "Next Run" calculation and overdue detection**: The "Next Run" column in backup monitoring settings now accurately calculates and displays the next expected backup date, taking into account both the backup schedule and the last backup timestamp. This applies to both scheduled and manually run backup jobs, resulting in more reliable overdue detection.

## 🚀 माइग्रेशन नोट्स {#-migration-notes}

### From Version 1.1.x {#from-version-11x}

When upgrading to version 1.2.1:

1. **Notification Templates**: The system will automatically update the default notification templates to include the new `{log_text}` variable the first time they are accessed after upgrading. Custom templates will remain unchanged. If you would like to use the new `{log_text}` variable in your own templates, you will need to update them or restore the default templates manually.

2. **Master Key Changes**: If you restore from a backup or migrate to a new system with a different `.duplistatus.key` file, the system will automatically detect this and prompt you to reconfigure encrypted passwords (SMTP passwords and Duplicati server passwords).

3. **Database Backup/Restore**: New database backup and restore functionality is available in the Database Maintenance settings page. It's recommended to create a backup before upgrading, though no database schema changes are required for this release.

4. **No Database Migration Required**: This release does not require any database schema changes.

## API Endpoints {#api-endpoints}

The following API endpoints have been introduced in this version.

### Authentication & Security Endpoints {#authentication--security-endpoints}

- `GET /api/auth/admin-must-change-password` - Check if admin user must change password

### Database Management Endpoints {#database-management-endpoints}

- `GET /api/database/backup` - Create database backup (binary or SQL format)
- `POST /api/database/restore` - Restore database from backup file

### Backup Management Endpoints {#backup-management-endpoints}

- `GET /api/backups/last-timestamps` - Get last backup timestamps for all server-backup combinations
