# प्रशासन {/* #administration */}

## बैकअप एकत्र करें - `/api/backups/collect` {/* #collect-backups---apibackupscollect */}
- **एंडपॉइंट**: `/api/backups/collect`
- **मेथड**: POST
- **विवरण**: अपने API के माध्यम से सीधे Duplicati सर्वर से बैकअप डेटा एकत्र करता है। यह एंडपॉइंट स्वचालित रूप से सर्वोत्तम कनेक्शन प्रोटोकॉल (SSL सत्यापन के साथ HTTPS, स्व-हस्ताक्षरित प्रमाणपत्रों के साथ HTTPS, या फ़ॉलबैक के रूप में HTTP) का पता लगाता है और बैकअप जानकारी प्राप्त करने और इसे स्थानीय डेटाबेस में प्रोसेस करने के लिए Duplicati सर्वर से कनेक्ट होता है।
- **प्रमाणीकरण**: मान्य सत्र और सीएसआरएफ टोकन की आवश्यकता है
- **अनुरोध निकाय**:

  ```json
  {
    "hostname": "duplicati-server.local",
    "port": 8200,
    "password": "your-password",
    "downloadJson": false
  }
  ```

- **प्रतिक्रिया**:

  ```json
  {
    "success": true,
    "serverName": "Server Name",
    "serverAlias": "My Server",
    "stats": {
      "processed": 5,
      "skipped": 2,
      "errors": 0
    },
    "backupSettings": {
      "added": 2,
      "total": 7
    }
  }
  ```

- **त्रुटि प्रतिक्रियाएं**:
  - `400`: अमान्य अनुरोध पैरामीटर या कनेक्शन विफल
  - `500`: बैकअप संग्रह के दौरान सर्वर त्रुटि
- **नोट्स**: 
  - एंडपॉइंट स्वचालित रूप से इष्टतम कनेक्शन प्रोटोकॉल (HTTPS → स्व-हस्ताक्षरित के साथ HTTPS → HTTP) का पता लगाता है
  - प्रोटोकॉल का पता लगाने के प्रयास सुरक्षा प्राथमिकता के क्रम में किए जाते हैं
  - कनेक्शन टाइमआउट पर्यावरण चर के माध्यम से कॉन्फ़िगर करने योग्य हैं
  - डीबगिंग के लिए विकास मोड में एकत्रित डेटा लॉग करता है
  - सुनिश्चित करता है कि सभी सर्वर और सभी बैकअप के लिए बैकअप सेटिंग्स पूर्ण हैं
  - निर्दिष्ट न होने पर डिफ़ॉल्ट पोर्ट 8200 का उपयोग करता है
  - पता लगाया गया प्रोटोकॉल और सर्वर URL स्वचालित रूप से डेटाबेस में संग्रहीत किए जाते हैं
  - `serverAlias` डेटाबेस से प्राप्त किया जाता है और यदि कोई उपनाम सेट नहीं है तो खाली हो सकता है
  - फ्रंटएंड को प्रदर्शन उद्देश्यों के लिए `serverAlias || serverName` का उपयोग करना चाहिए
  - JSON डाउनलोड और प्रत्यक्ष API संग्रह दोनों विधियों का समर्थन करता है

## बैकअप क्लीनअप - `/api/backups/cleanup` {/* #cleanup-backups---apibackupscleanup */}
- **एंडपॉइंट**: `/api/backups/cleanup`
- **मेथड**: POST
- **विवरण**: प्रतिधारण अवधि के आधार पर पुराने बैकअप डेटा को हटाता है। यह एंडपॉइंट हालिया और महत्वपूर्ण डेटा को सुरक्षित रखते हुए पुराने बैकअप रिकॉर्ड को हटाकर डेटाबेस के आकार को प्रबंधित करने में मदद करता है।
- **प्रमाणीकरण**: मान्य सत्र और सीएसआरएफ टोकन की आवश्यकता है
- **अनुरोध निकाय**:

  ```json
  {
    "retentionPeriod": "6 months"
  }
  ```

- **प्रतिधारण अवधियां**: `"6 months"`, `"1 year"`, `"2 years"`, `"Delete all data"`
- **प्रतिक्रिया**:

  ```json
  {
    "message": "Successfully deleted 15 old backups",
    "status": 200
  }
  ```

"सारा डेटा हटाएं" विकल्प के लिए:

  ```json
  {
    "message": "Successfully deleted all 15 backups and 3 servers, and cleared configuration settings",
    "status": 200
  }
  ```

- **त्रुटि प्रतिक्रियाएं**:
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `400`: अमान्य प्रतिधारण अवधि निर्दिष्ट
  - `500`: विस्तृत त्रुटि जानकारी के साथ क्लीनअप ऑपरेशन के दौरान सर्वर त्रुटि
- **नोट्स**: 
  - क्लीनअप ऑपरेशन अपरिवर्तनीय है
  - बैकअप डेटा को डेटाबेस से स्थायी रूप से हटा दिया जाता है
  - यदि सभी बैकअप हटा दिए जाते हैं तब भी मशीन रिकॉर्ड सुरक्षित रखे जाते हैं
  - जब "सारा डेटा हटाएं" चुना जाता है, तो सभी मशीनें और बैकअप हटा दिए जाते हैं और कॉन्फ़िगरेशन साफ़ कर दिया जाता है
  - बेहतर त्रुटि रिपोर्टिंग में विकास मोड में विवरण और स्टैक ट्रेस शामिल होते हैं
  - समय-आधारित प्रतिधारण और पूर्ण डेटा हटाने दोनों का समर्थन करता है

## बैकअप जॉब हटाएं - `/api/backups/delete-job` {/* #delete-backup-job---apibackupsdelete-job */}
- **एंडपॉइंट**: `/api/backups/delete-job`
- **मेथड**: DELETE
- **विवरण**: एक विशिष्ट सर्वर-बैकअप संयोजन के लिए सभी बैकअप रिकॉर्ड हटाता है। यह एंडपॉइंट केवल विकास मोड में उपलब्ध है।
- **प्रमाणीकरण**: मान्य सत्र और सीएसआरएफ टोकन की आवश्यकता है
- **अनुरोध निकाय**:

  ```json
  {
    "serverId": "server-id",
    "backupName": "Backup Name"
  }
  ```

- **प्रतिक्रिया**:

  ```json
  {
    "message": "Successfully deleted 5 backup record(s) for \"Files\" from server \"My Server\"",
    "status": 200,
    "deletedCount": 5,
    "serverName": "My Server",
    "backupName": "Files"
  }
  ```

- **त्रुटि प्रतिक्रियाएं**:
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: बैकअप जॉब हटाना केवल विकास मोड में उपलब्ध है
  - `400`: सर्वर आईडी और बैकअप नाम आवश्यक हैं
  - `404`: हटाने के लिए कोई बैकअप नहीं मिला
  - `500`: विस्तृत त्रुटि जानकारी के साथ हटाने के दौरान सर्वर त्रुटि
- **नोट्स**: 
  - यह ऑपरेशन केवल विकास मोड में उपलब्ध है
  - यह ऑपरेशन अपरिवर्तनीय है
  - निर्दिष्ट सर्वर-बैकअप संयोजन के लिए सभी बैकअप रिकॉर्ड स्थायी रूप से हटा दिए जाएंगे
  - हटाए गए बैकअप की संख्या और सर्वर जानकारी लौटाता है
  - यदि उपलब्ध हो तो प्रदर्शन के लिए सर्वर उपनाम का उपयोग करता है, अन्यथा सर्वर नाम पर फ़ॉलबैक करता है

## बैकअप शेड्यूल सिंक करें - `/api/backups/sync-schedule` {/* #sync-backup-schedules---apibackupssync-schedule */}
- **एंडपॉइंट**: `/api/backups/sync-schedule`
- **मेथड**: POST
- **विवरण**: Duplicati सर्वर से बैकअप शेड्यूल जानकारी को सिंक्रनाइज़ करता है। यह एंडपॉइंट सर्वर से कनेक्ट होता है, सभी बैकअप के लिए शेड्यूल जानकारी प्राप्त करता है, और दोहराव अंतराल, अनुमत सप्ताह के दिन और शेड्यूल समय सहित शेड्यूल विवरण के साथ स्थानीय बैकअप सेटिंग्स को अपडेट करता है।
- **प्रमाणीकरण**: मान्य सत्र और सीएसआरएफ टोकन की आवश्यकता है
- **अनुरोध निकाय**:

  ```json
  {
    "hostname": "duplicati-server.local",
    "port": 8200,
    "password": "your-password",
    "serverId": "optional-server-id"
  }
  ```

या केवल serverId के साथ (संग्रहीत पासवर्ड का उपयोग करता है):

  ```json
  {
    "serverId": "server-id"
  }
  ```

या serverId और अपडेट किए गए क्रेडेंशियल्स के साथ:

  ```json
  {
    "serverId": "server-id",
    "hostname": "new-hostname.local",
    "port": 8200,
    "password": "new-password"
  }
  ```

- **प्रतिक्रिया**:

  ```json
  {
    "success": true,
    "serverName": "Server Name",
    "stats": {
      "processed": 5,
      "errors": 0
    }
  }
  ```

त्रुटियों के साथ:

  ```json
  {
    "success": true,
    "serverName": "Server Name",
    "stats": {
      "processed": 3,
      "errors": 2
    },
    "errors": [
      "Backup Name 1: Error message",
      "Backup Name 2: Error message"
    ]
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य अनुरोध पैरामीटर, serverId प्रदान न किए जाने पर होस्टनाम/पासवर्ड गायब, या कनेक्शन विफल
  - `404`: सर्वर नहीं मिला (जब serverId प्रदान किया गया हो) या सर्वर के लिए कोई पासवर्ड संग्रहीत नहीं है
  - `500`: शेड्यूल सिंक्रनाइज़ेशन के दौरान सर्वर त्रुटि
- **नोट्स**: 
  - एंडपॉइंट स्वचालित रूप से इष्टतम कनेक्शन प्रोटोकॉल का पता लगाता है (HTTPS → स्व-हस्ताक्षरित के साथ HTTPS → HTTP)
  - संग्रहीत सर्वर क्रेडेंशियल्स का उपयोग करने के लिए केवल serverId के साथ कॉल किया जा सकता है
  - सर्वर कनेक्शन विवरण अपडेट करने के लिए serverId और नए क्रेडेंशियल्स के साथ कॉल किया जा सकता है
  - नए सर्वर्स के लिए serverId के बिना होस्टनाम/पोर्ट/पासवर्ड के साथ कॉल किया जा सकता है
  - शेड्यूल जानकारी के साथ बैकअप सेटिंग्स को अपडेट करता है, जिसमें शामिल हैं:
    - `expectedInterval`: दोहराव अंतराल (उदा., "दैनिक", "साप्ताहिक", "मासिक")
    - `allowedWeekDays`: अनुमत सप्ताह के दिनों की सरणी (0=रविवार, 1=सोमवार, आदि)
    - `time`: बैकअप के लिए निर्धारित समय
  - सर्वर पर मिले सभी बैकअप को प्रोसेस करता है
  - प्रोसेस किए गए बैकअप और आई किसी भी त्रुटियों के आँकड़े लौटाता है
  - सफल और विफल सिंक संचालन के लिए ऑडिट घटनाओं को लॉग करता है
  - निर्दिष्ट न होने पर डिफ़ॉल्ट पोर्ट 8200 का उपयोग करता है

## सर्वर कनेक्शन जाँचें - `/api/servers/test-connection` {/* #test-server-connection---apiserverstest-connection */}
- **एंडपॉइंट**: `/api/servers/test-connection`
- **मेथड**: POST
- **विवरण**: यह सत्यापित करने के लिए duplicati सर्वर से कनेक्शन की जाँच करता है कि यह सुलभ है।
- **अनुरोध बॉडी**:

  ```json
  {
    "server_url": "http://localhost:8200"
  }
  ```

- **प्रतिक्रिया**:

  ```json
  {
    "success": true,
    "message": "Connection successful"
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य URL प्रारूप या सर्वर URL गायब
  - `500`: कनेक्शन जाँच के दौरान सर्वर त्रुटि
- **नोट्स**: 
  - एंडपॉइंट URL प्रारूप को मान्य करता है और कनेक्टिविटी की जाँच करता है
  - यदि सर्वर 401 स्थिति के साथ प्रतिक्रिया देता है तो सफलता लौटाता है (क्रेडेंशियल्स के बिना लॉगिन एंडपॉइंट के लिए अपेक्षित)
  - duplicati सर्वर के लॉगिन एंडपॉइंट से कनेक्शन की जाँच करता है
  - HTTP और HTTPS दोनों प्रोटोकॉल का समर्थन करता है
  - कनेक्शन जाँच के लिए टाइमआउट कॉन्फ़िगरेशन का उपयोग करता है

## सर्वर URL प्राप्त करें - `/api/servers/:serverId/server-url` {/* #get-server-url---apiserversserveridserver-url */}
- **एंडपॉइंट**: `/api/servers/:serverId/server-url`
- **मेथड**: GET
- **विवरण**: एक विशिष्ट सर्वर के लिए सर्वर URL पुनर्प्राप्त करता है।
- **पैरामीटर**:
  - `serverId`: सर्वर पहचानकर्ता

- **प्रतिक्रिया**:

  ```json
  {
    "serverId": "server-id",
    "server_url": "http://localhost:8200"
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `404`: सर्वर नहीं मिला
  - `500`: सर्वर त्रुटि
- **नोट्स**:
  - विशिष्ट सर्वर के लिए सर्वर URL लौटाता है
  - सर्वर कनेक्शन प्रबंधन के लिए उपयोग किया जाता है
  - यदि कोई सर्वर URL सेट नहीं है तो खाली स्ट्रिंग लौटाता है

## सर्वर URL अपडेट करें - `/api/servers/:serverId/server-url` {/* #update-server-url---apiserversserveridserver-url */}
- **एंडपॉइंट**: `/api/servers/:serverId/server-url`
- **मेथड**: PATCH
- **विवरण**: एक विशिष्ट सर्वर के लिए सर्वर URL अपडेट करता है।
- **प्रमाणीकरण**: मान्य सत्र और CSRF टोकन की आवश्यकता है
- **पैरामीटर**:
  - `serverId`: सर्वर पहचानकर्ता
- **अनुरोध बॉडी**:

  ```json
  {
    "server_url": "http://localhost:8200"
  }
  ```

- **प्रतिक्रिया**:

  ```json
  {
    "message": "Server URL updated successfully",
    "serverId": "server-id",
    "serverName": "Server Name",
    "server_url": "http://localhost:8200"
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `400`: अमान्य URL प्रारूप
  - `404`: सर्वर नहीं मिला
  - `500`: अपडेट के दौरान सर्वर त्रुटि

  - एंडपॉइंट अपडेट करने से पहले URL प्रारूप को मान्य करता है
  - खाली या null सर्वर URL की अनुमति है
  - HTTP और HTTPS दोनों प्रोटोकॉल का समर्थन करता है
  - अपडेट की गई सर्वर जानकारी लौटाता है

## उपयोगकर्ता प्रबंधन {/* #user-management */}

  ```json
      }

      "page": 1,

    }

  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: निषिद्ध - एडमिन विशेषाधिकार आवश्यक
  - `500`: आंतरिक सर्वर त्रुटि
- **नोट्स**:
  - केवल एडमिन उपयोगकर्ताओं के लिए सुलभ
  - पृष्ठांकन और खोज फ़िल्टरिंग का समर्थन करता है
  - लॉक स्थिति सहित उपयोगकर्ता खाता स्थिति लौटाता है

### उपयोगकर्ता बनाएं - `/api/users` {/* #create-user---apiusers */}
- **एंडपॉइंट**: `/api/users`
- **विधि**: POST
- **विवरण**: एक नया उपयोगकर्ता खाता बनाता है। एक अस्थायी पासवर्ड उत्पन्न कर सकता है या प्रदान किए गए पासवर्ड का उपयोग कर सकता है।
- **प्रमाणीकरण**: एडमिन विशेषाधिकार, मान्य सत्र और CSRF टोकन आवश्यक
- **अनुरोध बॉडी**:

  ```json
  {
    "username": "newuser",
    "password": "optional-password",
    "isAdmin": false,
    "requirePasswordChange": true
  }
  ```

- `username`: आवश्यक, 3-50 वर्णों का होना चाहिए, अद्वितीय
  - `password`: वैकल्पिक, यदि प्रदान नहीं किया गया तो एक सुरक्षित अस्थायी पासवर्ड उत्पन्न किया जाता है
  - `isAdmin`: वैकल्पिक, डिफ़ॉल्ट false
  - `requirePasswordChange`: वैकल्पिक, डिफ़ॉल्ट true
- **प्रतिक्रिया**:

  ```json
  {
    "user": {
      "id": "user-id",
      "username": "newuser",
      "isAdmin": false,
      "mustChangePassword": true
    },
    "temporaryPassword": "generated-password-123"
  }
  ```

- `temporaryPassword` केवल तभी शामिल किया जाता है जब पासवर्ड स्वतः उत्पन्न हुआ हो
- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य उपयोगकर्ता नाम प्रारूप, पासवर्ड नीति उल्लंघन, या सत्यापन त्रुटियाँ
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: निषिद्ध - एडमिन विशेषाधिकार आवश्यक
  - `409`: उपयोगकर्ता नाम पहले से मौजूद है
  - `500`: आंतरिक सर्वर त्रुटि
- **नोट्स**:
  - केवल एडमिन उपयोगकर्ताओं के लिए सुलभ
  - उपयोगकर्ता नाम केस-असंवेदनशील है और लोअरकेस में संग्रहीत किया जाता है
  - यदि पासवर्ड प्रदान नहीं किया जाता है, तो एक सुरक्षित 12-वर्ण का पासवर्ड उत्पन्न किया जाता है
  - उत्पन्न अस्थायी पासवर्ड केवल एक बार प्रतिक्रिया में लौटाए जाते हैं
  - उपयोगकर्ता निर्माण ऑडिट लॉग में दर्ज किया जाता है

### उपयोगकर्ता अपडेट करें - `/api/users/:id` {/* #update-user---apiusersid */}

- **प्रमाणीकरण**: एडमिन विशेषाधिकारों, मान्य सत्र और CSRF टोकन की आवश्यकता है
- **पैरामीटर**:
  - `id`: अपडेट करने के लिए उपयोगकर्ता आईडी
- **अनुरोध बॉडी**:

- **प्रतिक्रिया** (पासवर्ड रीसेट के साथ):

  ```json
  {
    "user": {
  ```

- **प्रतिक्रिया** (पासवर्ड रीसेट के बिना):

  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन

  - `409`: उपयोगकर्ता नाम पहले से मौजूद है (यदि उपयोगकर्ता नाम बदल रहे हैं)
  - `500`: आंतरिक सर्वर त्रुटि
- **नोट्स**:
  - केवल एडमिन उपयोगकर्ताओं के लिए सुलभ
  - उपयोगकर्ता नाम परिवर्तनों की विशिष्टता के लिए सत्यापन किया जाता है
  - पासवर्ड रीसेट एक सुरक्षित 12-वर्ण का अस्थायी पासवर्ड उत्पन्न करता है
  - सभी परिवर्तन ऑडिट लॉग में दर्ज किए जाते हैं

  ```json
    "message": "User deleted successfully"
  }
  ```

  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन

  - `404`: उपयोगकर्ता नहीं मिला

  - केवल एडमिन उपयोगकर्ताओं के लिए सुलभ
  - अपना स्वयं का खाता नहीं हटा सकते
  - अंतिम एडमिन खाता नहीं हटा सकते (कम से कम एक एडमिन बना रहना चाहिए)

## ऑडिट लॉग प्रबंधन {/* #audit-log-management */}

### ऑडिट लॉग सूचीबद्ध करें - `/api/audit-log` {/* #list-audit-logs---apiaudit-log */}
- **एंडपॉइंट**: `/api/audit-log`
- **विधि**: GET
- **विवरण**: फ़िल्टरिंग, पृष्ठांकन और खोज क्षमताओं के साथ ऑडिट लॉग प्रविष्टियाँ प्राप्त करता है। पृष्ठ-आधारित और ऑफ़सेट-आधारित दोनों पृष्ठांकन का समर्थन करता है।
- **प्रमाणीकरण**: वैध सत्र और CSRF टोकन आवश्यक (लॉग-इन उपयोगकर्ता आवश्यक)
- **क्वेरी पैरामीटर**:
  - `page` (वैकल्पिक): पेज-आधारित पेजिनेशन के लिए पृष्ठ संख्या
  - `offset` (वैकल्पिक): ऑफ़सेट-आधारित पेजिनेशन के लिए ऑफ़सेट (पेज से पहले प्राथमिकता लेता है)
  - `limit` (वैकल्पिक): प्रति पृष्ठ आइटम (डिफ़ॉल्ट: 50)
  - `startDate` (वैकल्पिक): इस तिथि से लॉग फ़िल्टर करें (ISO प्रारूप)
  - `endDate` (वैकल्पिक): इस तिथि तक लॉग फ़िल्टर करें (ISO प्रारूप)
  - `userId` (वैकल्पिक): उपयोगकर्ता आईडी से फ़िल्टर करें
  - `username` (वैकल्पिक): उपयोगकर्ता नाम से फ़िल्टर करें
  - `action` (वैकल्पिक): कार्रवाई नाम से फ़िल्टर करें
  - `category` (वैकल्पिक): श्रेणी से फ़िल्टर करें (`auth`, `user_management`, `config`, `backup`, `server`)
  - `status` (वैकल्पिक): स्थिति से फ़िल्टर करें (`success`, `failure`, `error`)
- **प्रतिक्रिया**:

  ```json
  {
    "logs": [

        "userId": "user-id",
        "username": "admin",
        "action": "login",
        "category": "auth",
        "targetType": "user",
        "targetId": "user-id",
        "status": "success",
        "ipAddress": "192.168.1.100",
        "userAgent": "Mozilla/5.0...",
        "details": {
          "is_admin": true
        },
        "errorMessage": null
      }
    ],
    "pagination": {
      "page": 1,
      "limit": 50,
      "total": 150,
      "totalPages": 3
    }
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `500`: आंतरिक सर्वर त्रुटि
- **नोट्स**:
  - पेज-आधारित (`page`) और ऑफ़सेट-आधारित (`offset`) दोनों प्रकार के पेजिनेशन का समर्थन करता है
  - `details` फ़ील्ड में अतिरिक्त संदर्भ के साथ पार्स किया गया JSON होता है
  - सभी ऑडिट लॉग क्वेरीज़ लॉग की जाती हैं

- **क्वेरी पैरामीटर**:
  - `format` (वैकल्पिक): निर्यात प्रारूप - `csv` या `json` (डिफ़ॉल्ट: `csv`)
  - `startDate` (वैकल्पिक): इस तिथि से लॉग फ़िल्टर करें (ISO प्रारूप)

- **एंडपॉइंट**: `/api/database/backup`
- **मेथड**: GET
- **विवरण**: बाइनरी (.db) या SQL (.sql) फ़ॉर्मेट में डेटाबेस का बैकअप बनाता है। बैकअप फ़ाइल स्वचालित रूप से टाइमस्टैम्प वाले फ़ाइलनाम के साथ डाउनलोड हो जाती है।
- **प्रमाणीकरण**: एडमिन विशेषाधिकार, मान्य सत्र और CSRF टोकन आवश्यक
- **क्वेरी पैरामीटर्स**:
  - `format` (वैकल्पिक): बैकअप फ़ॉर्मेट - `db` (बाइनरी) या `sql` (SQL डंप)। डिफ़ॉल्ट: `db`
- **प्रतिक्रिया**:
  - Content-Type: `application/octet-stream` (.db के लिए) या `text/plain` (.sql के लिए)
  - Content-Disposition: `attachment; filename="duplistatus-backup-YYYY-MM-DDTHH-MM-SS.db"` या `.sql`
  - बाइनरी फ़ाइल सामग्री (.db के लिए) या SQL टेक्स्ट सामग्री (.sql के लिए)
- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य फ़ॉर्मेट ("db" या "sql" होना चाहिए)
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: प्रतिबंधित - एडमिन विशेषाधिकार आवश्यक
  - `500`: डेटाबेस बैकअप बनाने में विफल
- **नोट्स**:
  - केवल एडमिन उपयोगकर्ताओं के लिए सुलभ
  - बाइनरी प्रारूप अखंडता के लिए SQLite की बैकअप विधि का उपयोग करता है
  - SQL प्रारूप सभी डेटाबेस सामग्री का टेक्स्ट डंप बनाता है
  - फ़ाइल नाम में टाइमस्टैम्प सर्वर के स्थानीय समय क्षेत्र का उपयोग करता है
  - बैकअप ऑपरेशन ऑडिट लॉग में लॉग किया जाता है
  - डाउनलोड के बाद अस्थायी फ़ाइलें स्वचालित रूप से साफ़ कर दी जाती हैं

  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: निषिद्ध - एडमिन विशेषाधिकार आवश्यक
  - `500`: डेटाबेस पुनर्स्थापित करने में विफल (यदि पुनर्स्थापना विफल होती है तो सुरक्षा बैकअप से मूल डेटाबेस पुनर्स्थापित किया जाता है)

  - पुनर्स्थापना से पहले स्वचालित रूप से एक सुरक्षा बैकअप बनाता है
  - बाइनरी (.db) और SQL (.sql) दोनों प्रारूपों का समर्थन करता है
  - पुनर्स्थापना के बाद डेटाबेस अखंडता मान्य करता है
  - यदि पुनर्स्थापना विफल होती है, तो सुरक्षा बैकअप से स्वचालित रूप से पुनर्स्थापित करता है
  - सफल पुनर्स्थापना के बाद सुरक्षा के लिए सभी सत्र साफ़ कर दिए जाते हैं
  - उपयोगकर्ता को फिर से लॉग इन करने की आवश्यकता इंगित करने के लिए `requiresReauth: true` लौटाता है
  - पुनर्स्थापना ऑपरेशन ऑडिट लॉग में लॉग किया जाता है
  - SQL प्रारूप के लिए, निष्पादन से पहले SQL सामग्री मान्य करता है
  - पुनर्स्थापना के बाद डेटाबेस कनेक्शन पुनः आरंभ किया जाता है
  - पुनर्स्थापना के बाद सभी कैश अमान्य कर दिए जाते हैं

## बैकअप टाइमस्टैम्प {/* #backup-timestamps */}

### अंतिम बैकअप टाइमस्टैम्प प्राप्त करें - `/api/backups/last-timestamps` {/* #get-last-backup-timestamps---apibackupslast-timestamps */}
- **एंडपॉइंट**: `/api/backups/last-timestamps`
- **विधि**: GET
- **विवरण**: प्रत्येक सर्वर-बैकअप संयोजन के लिए अंतिम बैकअप टाइमस्टैम्प पुनर्प्राप्त करता है। आसान लुकअप के लिए एक मैप लौटाता है।
- **प्रमाणीकरण**: वैध सत्र और CSRF टोकन की आवश्यकता है
- **प्रतिक्रिया**:

  ```json
  {
    "timestamps": {
      "server-id-1:Backup Name 1": "2024-03-20T10:00:00Z",
      "server-id-1:Backup Name 2": "2024-03-20T11:00:00Z",
      "server-id-2:Backup Name 1": "2024-03-20T12:00:00Z"
    },
    "raw": [
      {
        "server_name": "Server Name",
        "server_id": "server-id-1",
        "backup_name": "Backup Name 1",
        "date": "2024-03-20T10:00:00Z"
      }
    ]
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `500`: अंतिम बैकअप टाइमस्टैम्प प्राप्त करने में विफल
- **नोट्स**:
  - आसान लुकअप के लिए एक मैप (`server_id:backup_name` द्वारा) और कच्चा सरणी प्रारूप दोनों लौटाता है
  - कैशिंग रोकने के लिए कैश नियंत्रण हेडर शामिल करता है
  - सभी सर्वर-बैकअप संयोजनों में अंतिम बैकअप समय ट्रैक करने के लिए उपयोगी
  - टाइमस्टैम्प ISO प्रारूप में हैं

## एप्लिकेशन लॉग प्रबंधन {/* #application-logs-management */}

### एप्लिकेशन लॉग प्राप्त करें - `/api/application-logs` {/* #get-application-logs---apiapplication-logs */}
- **एंडपॉइंट**: `/api/application-logs`
- **विधि**: GET
- **विवरण**: लॉग फ़ाइलों से एप्लिकेशन लॉग प्रविष्टियाँ पुनर्प्राप्त करता है। टेल कार्यक्षमता के साथ वर्तमान और रोटेटेड लॉग फ़ाइलों को पढ़ने का समर्थन करता है।
- **प्रमाणीकरण**: एडमिन विशेषाधिकार, मान्य सत्र और CSRF टोकन आवश्यक है
- **क्वेरी पैरामीटर**:
  - `file` (वैकल्पिक): पढ़ने के लिए लॉग फ़ाइल का नाम - `application.log`, `application.log.1`, `application.log.2`, आदि। यदि प्रदान नहीं किया गया, तो उपलब्ध फ़ाइलों की सूची लौटाता है
  - `tail` (वैकल्पिक): फ़ाइल के अंत से लौटाने के लिए पंक्तियों की संख्या (डिफ़ॉल्ट: 1000, न्यूनतम: 1, अधिकतम: 10000)
- **प्रतिक्रिया** (फ़ाइल पैरामीटर के साथ):

  ```json
  {
    "logs": "log content as string...",
    "fileSize": 1024000,
    "lastModified": "2024-03-20T10:00:00Z",
    "lineCount": 5000,
    "currentFile": "application.log",
    "availableFiles": ["application.log", "application.log.1", "application.log.2"]
  }
  ```

- **प्रतिक्रिया** (फ़ाइल पैरामीटर के बिना):

  ```json
  {
    "logs": "",
    "fileSize": 0,
    "lastModified": "2024-03-20T10:00:00Z",
    "lineCount": 0,
    "currentFile": "",
    "availableFiles": ["application.log", "application.log.1", "application.log.2"]
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य टेल पैरामीटर (1-10000 होना चाहिए) या अमान्य फ़ाइल पैरामीटर प्रारूप
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: निषिद्ध - एडमिन विशेषाधिकार आवश्यक
  - `404`: लॉग फ़ाइल नहीं मिली
  - `500`: लॉग फ़ाइल पढ़ने में विफल
- **नोट्स**:
  - केवल एडमिन उपयोगकर्ताओं के लिए सुलभ
  - वर्तमान लॉग फ़ाइल और रोटेटेड लॉग फ़ाइलों (अधिकतम 10 रोटेटेड फ़ाइलें) को पढ़ने का समर्थन करता है
  - निर्दिष्ट लॉग फ़ाइल से अंतिम N पंक्तियाँ (टेल) लौटाता है
  - लॉग फ़ाइल का नाम पर्यावरण चर द्वारा निर्धारित होता है (डिफ़ॉल्ट: `application.log`)
  - जब फ़ाइल पैरामीटर प्रदान नहीं किया जाता है तो उपलब्ध लॉग फ़ाइलों की सूची लौटाता है
  - डायरेक्टरी ट्रैवर्सल हमलों को रोकने के लिए फ़ाइल नाम मान्य किए जाते हैं
  - रोटेटेड फ़ाइलें क्रमिक रूप से क्रमांकित होती हैं (`.1`, `.2`, आदि)

### एप्लिकेशन लॉग निर्यात करें - `/api/application-logs/export` {/* #export-application-logs---apiapplication-logsexport */}
- **एंडपॉइंट**: `/api/application-logs/export`
- **मेथड**: GET
- **विवरण**: फ़िल्टर किए गए पाठ प्रारूप में एप्लिकेशन लॉग प्रविष्टियों को निर्यात करता है। लॉग स्तर और खोज स्ट्रिंग द्वारा फ़िल्टरिंग का समर्थन करता है।
- **प्रमाणीकरण**: एडमिन विशेषाधिकार, मान्य सत्र और CSRF टोकन आवश्यक है
- **क्वेरी पैरामीटर**:
  - `file` (आवश्यक): निर्यात करने के लिए लॉग फ़ाइल नाम - `application.log`, `application.log.1`, `application.log.2`, आदि।
  - `logLevels` (वैकल्पिक): शामिल करने के लिए लॉग स्तरों की अल्पविराम से अलग की गई सूची - `INFO`, `WARN`, `ERROR` (डिफ़ॉल्ट: `INFO,WARN,ERROR`)
  - `search` (वैकल्पिक): लॉग लाइनों को फ़िल्टर करने के लिए खोज स्ट्रिंग (केस-असंवेदनशील)
- **प्रतिक्रिया**:
  - Content-Type: `text/plain`
  - Content-Disposition: `attachment; filename="duplistatus-logs-YYYY-MM-DDTHH-MM-SS.txt"`
  - सादा पाठ के रूप में फ़िल्टर किया गया लॉग कंटेंट
- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: फ़ाइल पैरामीटर आवश्यक है या अमान्य फ़ाइल पैरामीटर प्रारूप
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: निषिद्ध - एडमिन विशेषाधिकार आवश्यक
  - `500`: लॉग निर्यात करने में विफल
- **नोट्स**:
  - केवल एडमिन उपयोगकर्ताओं के लिए सुलभ
  - लॉग स्तर और खोज मानदंड के आधार पर फ़िल्टर की गई लॉग प्रविष्टियों को निर्यात करता है
  - लॉग स्तरों द्वारा फ़िल्टरिंग का समर्थन करता है: `INFO`, `WARN`, `ERROR`
  - खोज स्ट्रिंग फ़िल्टरिंग केस-असंवेदनशील है
  - खाली लाइनें स्वचालित रूप से फ़िल्टर हो जाती हैं
  - लॉग फ़ाइल नाम एनवायरनमेंट वेरिएबल द्वारा निर्धारित किया जाता है (डिफ़ॉल्ट: `application.log`)
  - डायरेक्टरी ट्रैवर्सल हमलों को रोकने के लिए फ़ाइल नामों को मान्य किया जाता है
  - निर्यात की गई फ़ाइल में फ़ाइल नाम में टाइमस्टैम्प शामिल होता है
  - बाहरी विश्लेषण और ट्रबलशूटिंग के लिए उपयोगी
