# प्रशासन {/* #administration */}

## बैकअप एकत्र करें - `/api/backups/collect` {/* #collect-backups---apibackupscollect */}
- **एंडपॉइंट**: `/api/backups/collect`
- **विधि**: POST
- **विवरण**: अपने एपीआई के माध्यम से एक ड्यूप्लिकेटी सर्वर से सीधे बैकअप डेटा एकत्र करता है। यह एंडपॉइंट स्वचालित रूप से सर्वोत्तम कनेक्शन प्रोटोकॉल (एसएसएल सत्यापन के साथ एचटीटीपीएस, स्व-हस्ताक्षरित प्रमाणपत्रों के साथ एचटीटीपीएस या फॉलबैक के रूप में एचटीटीपी) का पता लगाता है और बैकअप जानकारी प्राप्त करने और इसे स्थानीय डेटाबेस में संसाधित करने के लिए ड्यूप्लिकेटी सर्वर से कनेक्ट होता है।
- **प्रमाणीकरण**: मान्य सत्र और सीएसआरएफ टोकन की आवश्यकता है
- **अनुरोध निकाय**:

  ```json
  {
    "hostname": "duplicati-server.local",
    "port": 8200,
    "password": "your-password",
    "downloadJson": false
  }
  ```

- **प्रतिक्रिया**:

  ```json
  {
    "success": true,
    "serverName": "Server Name",
    "serverAlias": "My Server",
    "stats": {
      "processed": 5,
      "skipped": 2,
      "errors": 0
    },
    "backupSettings": {
      "added": 2,
      "total": 7
    }
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य अनुरोध पैरामीटर या कनेक्शन विफल
  - `500`: बैकअप संग्रह के दौरान सर्वर त्रुटि
- **नोट्स**: 
  - एंडपॉइंट स्वचालित रूप से इष्टतम कनेक्शन प्रोटोकॉल (HTTPS → स्व-हस्ताक्षरित के साथ HTTPS → HTTP) का पता लगाता है
  - सुरक्षा प्राथमिकता के क्रम में प्रोटोकॉल डिटेक्शन प्रयास किए जाते हैं
  - कनेक्शन टाइमआउट को पर्यावरण चर के माध्यम से कॉन्फ़िगर किया जा सकता है
  - डीबगिंग के लिए डेवलपमेंट मोड में संग्रहीत डेटा को लॉग करता है
  - सभी सर्वर और बैकअप के लिए बैकअप सेटिंग्स पूर्ण होना सुनिश्चित करता है
  - यदि निर्दिष्ट नहीं किया गया है तो डिफ़ॉल्ट पोर्ट 8200 का उपयोग करता है
  - पता लगाया गया प्रोटोकॉल और सर्वर यूआरएल स्वचालित रूप से डेटाबेस में संग्रहीत किया जाता है
  - `serverAlias` को डेटाबेस से पुनर्प्राप्त किया जाता है और यदि कोई उपनाम सेट नहीं है तो यह खाली हो सकता है
  - डिस्प्ले उद्देश्यों के लिए फ्रंटेंड को `serverAlias || serverName` का उपयोग करना चाहिए
  - जेएसओएन डाउनलोड और सीधे एपीआई संग्रह दोनों विधियों का समर्थन करता है

## बैकअप साफ करें - `/api/backups/cleanup` {/* #cleanup-backups---apibackupscleanup */}
- **एंडपॉइंट**: `/api/backups/cleanup`
- **विधि**: POST
- **विवरण**: धारण अवधि के आधार पर पुराना बैकअप डेटा हटाता है। यह एंडपॉइंट पुराने बैकअप रिकॉर्ड को हटाकर डेटाबेस का आकार प्रबंधित करने में मदद करता है जबकि हाल के और महत्वपूर्ण डेटा को संरक्षित रखता है।
- **प्रमाणीकरण**: मान्य सत्र और सीएसआरएफ टोकन की आवश्यकता है
- **अनुरोध निकाय**:

  ```json
  {
    "retentionPeriod": "6 months"
  }
  ```

- **धारण अवधियाँ**: `"6 months"`, `"1 year"`, `"2 years"`, `"Delete all data"`
- **प्रतिक्रिया**:

  ```json
  {
    "message": "Successfully deleted 15 old backups",
    "status": 200
  }
  ```

"सारा डेटा हटाएं" विकल्प के लिए:

  ```json
  {
    "message": "Successfully deleted all 15 backups and 3 servers, and cleared configuration settings",
    "status": 200
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `401`: अनधिकृत - अमान्य सत्र या सीएसआरएफ टोकन
  - `400`: निर्दिष्ट धारण अवधि अमान्य है
  - `500`: साफ-सफाई के दौरान सर्वर त्रुटि विस्तृत त्रुटि जानकारी के साथ
- **नोट्स**: 
  - साफ-सफाई का काम अपरिवर्तनीय है
  - बैकअप डेटा को डेटाबेस से स्थायी रूप से हटा दिया जाता है
  - मशीन रिकॉर्ड को संरक्षित रखा जाता है भले ही सभी बैकअप हटा दिए गए हों
  - जब "सारा डेटा हटाएं" का चयन किया जाता है, तो सभी मशीनों और बैकअप को हटा दिया जाता है और कॉन्फ़िगरेशन साफ़ कर दिया जाता है
  - डेवलपमेंट मोड में विस्तृत त्रुटि रिपोर्टिंग विवरण और स्टैक ट्रेस शामिल करता है
  - समय-आधारित धारण और पूर्ण डेटा हटाने दोनों का समर्थन करता है

## बैकअप जॉब हटाएं - `/api/backups/delete-job` {/* #delete-backup-job---apibackupsdelete-job */}
- **एंडपॉइंट**: `/api/backups/delete-job`
- **विधि**: DELETE
- **विवरण**: एक विशिष्ट सर्वर-बैकअप संयोजन के लिए सभी बैकअप रिकॉर्ड हटाता है। यह एंडपॉइंट केवल डेवलपमेंट मोड में उपलब्ध है।
- **प्रमाणीकरण**: मान्य सत्र और सीएसआरएफ टोकन की आवश्यकता है
- **अनुरोध निकाय**:

  ```json
  {
    "serverId": "server-id",
    "backupName": "Backup Name"
  }
  ```

- **प्रतिक्रिया**:

  ```json
  {
    "message": "Successfully deleted 5 backup record(s) for \"Files\" from server \"My Server\"",
    "status": 200,
    "deletedCount": 5,
    "serverName": "My Server",
    "backupName": "Files"
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `401`: अनधिकृत - अमान्य सत्र या सीएसआरएफ टोकन
  - `403`: बैकअप जॉब हटाना केवल डेवलपमेंट मोड में उपलब्ध है
  - `400`: सर्वर आईडी और बैकअप नाम की आवश्यकता है
  - `404`: हटाने के लिए कोई बैकअप नहीं मिला
  - `500`: विस्तृत त्रुटि जानकारी के साथ हटाने के दौरान सर्वर त्रुटि
- **नोट्स**: 
  - यह कार्य केवल डेवलपमेंट मोड में उपलब्ध है
  - यह कार्य अपरिवर्तनीय है
  - निर्दिष्ट सर्वर-बैकअप संयोजन के लिए सभी बैकअप रिकॉर्ड स्थायी रूप से हटा दिए जाएंगे
  - हटाए गए बैकअप की संख्या और सर्वर जानकारी लौटाता है
  - यदि उपलब्ध हो तो प्रदर्शन के लिए सर्वर उपनाम का उपयोग करता है, अन्यथा सर्वर नाम पर वापस आ जाता है

## बैकअप अनुसूचियाँ सिंक करें - `/api/backups/sync-schedule` {/* #sync-backup-schedules---apibackupssync-schedule */}
- **एंडपॉइंट**: `/api/backups/sync-schedule`
- **विधि**: POST
- **विवरण**: एक ड्यूप्लिकेटी सर्वर से बैकअप अनुसूचि जानकारी सिंक्रनाइज़ करता है। यह एंडपॉइंट सर्वर से कनेक्ट होता है, सभी बैकअप के लिए अनुसूचि जानकारी पुनर्प्राप्त करता है, और अनुसूचि विवरण सहित स्थानीय बैकअप सेटिंग्स को अपडेट करता है जिसमें दोहराव अंतराल, अनुमति दिनों के दिन, और अनुसूचि समय शामिल हैं।
- **प्रमाणीकरण**: मान्य सत्र और सीएसआरएफ टोकन की आवश्यकता है
- **अनुरोध निकाय**:

  ```json
  {
    "hostname": "duplicati-server.local",
    "port": 8200,
    "password": "your-password",
    "serverId": "optional-server-id"
  }
  ```

या केवल सर्वर आईडी के साथ (संग्रहीत पासवर्ड का उपयोग करता है):

  ```json
  {
    "serverId": "server-id"
  }
  ```

या सर्वर आईडी और अपडेट किए गए क्रेडेंशियल्स के साथ:

  ```json
  {
    "serverId": "server-id",
    "hostname": "new-hostname.local",
    "port": 8200,
    "password": "new-password"
  }
  ```

- **प्रतिक्रिया**:

  ```json
  {
    "success": true,
    "serverName": "Server Name",
    "stats": {
      "processed": 5,
      "errors": 0
    }
  }
  ```

त्रुटियों के साथ:

  ```json
  {
    "success": true,
    "serverName": "Server Name",
    "stats": {
      "processed": 3,
      "errors": 2
    },
    "errors": [
      "Backup Name 1: Error message",
      "Backup Name 2: Error message"
    ]
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य अनुरोध पैरामीटर, जब serverId प्रदान नहीं किया गया हो तो होस्टनाम/पासवर्ड गुम है, या कनेक्शन विफल हुआ है
  - `404`: सर्वर नहीं मिला (जब serverId प्रदान किया गया हो) या सर्वर के लिए कोई पासवर्ड संग्रहीत नहीं है
  - `500`: अनुसूची समन्वयन के दौरान सर्वर त्रुटि
- **नोट**: 
  - एंडपॉइंट स्वचालित रूप से इष्टतम कनेक्शन प्रोटोकॉल का पता लगाता है (HTTPS → स्व-हस्ताक्षरित के साथ HTTPS → HTTP)
  - संग्रहीत सर्वर क्रेडेंशियल का उपयोग करने के लिए केवल serverId के साथ बुलाया जा सकता है
  - सर्वर कनेक्शन विवरण अपडेट करने के लिए serverId और नए क्रेडेंशियल के साथ बुलाया जा सकता है
  - नए सर्वर के लिए serverId के बिना होस्टनाम/पोर्ट/पासवर्ड के साथ बुलाया जा सकता है
  - अनुसूची सूचना के साथ बैकअप सेटिंग्स अपडेट करता है जिसमें शामिल हैं:
    - `expectedInterval`: दोहराव अंतराल (उदाहरण के लिए, "दैनिक", "साप्ताहिक", "मासिक")
    - `allowedWeekDays`: अनुमत सप्ताह के दिनों की सरणी (0=रविवार, 1=सोमवार, आदि)
    - `time`: बैकअप के लिए निर्धारित समय
  - सर्वर पर पाए गए सभी बैकअप की प्रक्रिया करता है
  - संसाधित बैकअप और कोई त्रुटियों के बारे में आँकड़े लौटाता है
  - सफल और विफल समन्वयन संचालन के लिए ऑडिट घटनाओं को लॉग करता है
  - यदि निर्दिष्ट नहीं किया गया हो तो डिफ़ॉल्ट पोर्ट 8200 का उपयोग करता है

## सर्वर कनेक्शन की जाँच करें - `/api/servers/test-connection` {/* #test-server-connection---apiserverstest-connection */}
- **एंडपॉइंट**: `/api/servers/test-connection`
- **विधि**: POST
- **विवरण**: यह सत्यापित करने के लिए कि एक duplicati सर्वर के लिए कनेक्शन की जाँच करें कि क्या यह सुलभ है।
- **अनुरोध निकाय**:

  ```json
  {
    "server_url": "http://localhost:8200"
  }
  ```

- **प्रतिक्रिया**:

  ```json
  {
    "success": true,
    "message": "Connection successful"
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य URL प्रारूप या गुम सर्वर URL
  - `500`: कनेक्शन जाँच के दौरान सर्वर त्रुटि
- **नोट**: 
  - एंडपॉइंट URL प्रारूप को मान्य करता है और कनेक्टिविटी की जाँच करता है
  - तब सफलता लौटाता है जब सर्वर 401 स्थिति के साथ प्रतिक्रिया देता है (क्रेडेंशियल के बिना लॉगिन एंडपॉइंट के लिए अपेक्षित)
  - duplicati सर्वर के लॉगिन एंडपॉइंट पर कनेक्शन की जाँच करता है
  - HTTP और HTTPS दोनों प्रोटोकॉल का समर्थन करता है
  - कनेक्शन परीक्षण के लिए टाइमआउट कॉन्फ़िगरेशन का उपयोग करता है

## सर्वर URL प्राप्त करें - `/api/servers/:serverId/server-url` {/* #get-server-url---apiserversserveridserver-url */}
- **एंडपॉइंट**: `/api/servers/:serverId/server-url`
- **विधि**: GET
- **विवरण**: किसी विशिष्ट सर्वर के लिए सर्वर URL पुनः प्राप्त करता है।
- **पैरामीटर**:
  - `serverId`: सर्वर पहचानकर्ता

- **प्रतिक्रिया**:

  ```json
  {
    "serverId": "server-id",
    "server_url": "http://localhost:8200"
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `404`: सर्वर नहीं मिला
  - `500`: सर्वर त्रुटि
- **नोट**:
  - विशिष्ट सर्वर के लिए सर्वर URL लौटाता है
  - सर्वर कनेक्शन प्रबंधन के लिए उपयोग किया जाता है
  - खाली स्ट्रिंग लौटाता है यदि कोई सर्वर URL सेट नहीं है

## सर्वर URL अपडेट करें - `/api/servers/:serverId/server-url` {/* #update-server-url---apiserversserveridserver-url */}
- **एंडपॉइंट**: `/api/servers/:serverId/server-url`
- **विधि**: PATCH
- **विवरण**: किसी विशिष्ट सर्वर के लिए सर्वर URL अपडेट करता है।
- **प्रमाणीकरण**: मान्य सत्र और CSRF टोकन की आवश्यकता है
- **पैरामीटर**:
  - `serverId`: सर्वर पहचानकर्ता
- **अनुरोध निकाय**:

  ```json
  {
    "server_url": "http://localhost:8200"
  }
  ```

- **प्रतिक्रिया**:

  ```json
  {
    "message": "Server URL updated successfully",
    "serverId": "server-id",
    "serverName": "Server Name",
    "server_url": "http://localhost:8200"
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `400`: अमान्य URL प्रारूप
  - `404`: सर्वर नहीं मिला
  - `500`: अपडेट के दौरान सर्वर त्रुटि
- **नोट**: 
  - अपडेट करने से पहले एंडपॉइंट URL प्रारूप को मान्य करता है
  - खाली या नल सर्वर URL की अनुमति है
  - HTTP और HTTPS दोनों प्रोटोकॉल का समर्थन करता है
  - अपडेट किए गए सर्वर जानकारी लौटाता है

## सर्वर पासवर्ड प्राप्त करें - `/api/servers/:serverId/password` {/* #get-server-password---apiserversserveridpassword */}
- **एंडपॉइंट**: `/api/servers/:serverId/password`

- **नोट**:
  - पासवर्ड अपडेट ऑपरेशन के साथ उपयोग के लिए CSRF टोकन लौटाता है

## उपयोगकर्ता प्रबंधन {/* #user-management */}

### उपयोगकर्ता सूची - `/api/users` {/* #list-users---apiusers */}
- **एंडपॉइंट**: `/api/users`
- **विधि**: GET
- **विवरण**: पृष्ठांकन और वैकल्पिक खोज फ़िल्टरिंग के साथ सभी उपयोगकर्ताओं को सूचीबद्ध करता है। लॉगिन इतिहास और खाता स्थिति सहित उपयोगकर्ता जानकारी लौटाता है।
- **प्रमाणीकरण**: व्यवस्थापक विशेषाधिकारों, वैध सत्र और CSRF टोकन की आवश्यकता होती है
- **क्वेरी पैरामीटर**:
  - `page` (वैकल्पिक): पृष्ठ संख्या (डिफ़ॉल्ट: 1)
  - `limit` (वैकल्पिक): प्रति पृष्ठ वस्तुएँ (डिफ़ॉल्ट: 50)
  - `search` (वैकल्पिक): उपयोगकर्ता नाम से फ़िल्टर करने के लिए खोज शब्द
- **प्रतिक्रिया**:

  ```json
  {
    "users": [
      {
        "id": "user-id",
        "username": "admin",
        "isAdmin": true,
        "mustChangePassword": false,
        "createdAt": "2024-01-01T00:00:00Z",
        "lastLoginAt": "2024-01-15T10:30:00Z",
        "lastLoginIp": "192.168.1.100",
        "failedLoginAttempts": 0,
        "lockedUntil": null,
        "isLocked": false
      }
    ],
    "pagination": {
      "page": 1,
      "limit": 50,
      "total": 5,
      "totalPages": 1
    }
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: निषिद्ध - व्यवस्थापक विशेषाधिकारों की आवश्यकता है
  - `500`: आंतरिक सर्वर त्रुटि
- **नोट्स**:
  - केवल व्यवस्थापक उपयोगकर्ताओं के लिए सुलभ
  - पृष्ठांकन और खोज फ़िल्टरिंग का समर्थन करता है
  - लॉक स्थिति सहित उपयोगकर्ता खाता स्थिति लौटाता है

### उपयोगकर्ता बनाएं - `/api/users` {/* #create-user---apiusers */}
- **एंडपॉइंट**: `/api/users`
- **विधि**: POST
- **विवरण**: एक नया उपयोगकर्ता खाता बनाता है। एक अस्थायी पासवर्ड उत्पन्न कर सकता है या प्रदान किए गए पासवर्ड का उपयोग कर सकता है।
- **प्रमाणीकरण**: एडमिन विशेषाधिकार, मान्य सत्र और CSRF टोकन की आवश्यकता है
- **अनुरोध बॉडी**:

  ```json
  {
    "username": "newuser",
    "password": "optional-password",
    "isAdmin": false,
    "requirePasswordChange": true
  }
  ```

- `username`: आवश्यक, 3-50 वर्ण होना चाहिए, अद्वितीय होना चाहिए
  - `password`: वैकल्पिक, यदि प्रदान नहीं किया गया तो एक सुरक्षित अस्थायी पासवर्ड उत्पन्न किया जाता है
  - `isAdmin`: वैकल्पिक, डिफ़ॉल्ट झूठा
  - `requirePasswordChange`: वैकल्पिक, डिफ़ॉल्ट सत्य
- **प्रतिक्रिया**:

  ```json
  {
    "user": {
      "id": "user-id",
      "username": "newuser",
      "isAdmin": false,
      "mustChangePassword": true
    },
    "temporaryPassword": "generated-password-123"
  }
  ```

- `temporaryPassword` केवल तभी शामिल किया जाता है जब पासवर्ड स्वतः उत्पन्न किया गया हो
- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य उपयोगकर्ता नाम प्रारूप, पासवर्ड नीति का उल्लंघन, या सत्यापन त्रुटियाँ
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: निषिद्ध - व्यवस्थापक विशेषाधिकारों की आवश्यकता है
  - `409`: उपयोगकर्ता नाम पहले से मौजूद है
  - `500`: आंतरिक सर्वर त्रुटि
- **नोट्स**:
  - केवल व्यवस्थापक उपयोगकर्ताओं के लिए सुलभ
  - उपयोगकर्ता नाम केस-असंवेदनशील है और छोटे अक्षरों में संग्रहीत किया जाता है
  - यदि पासवर्ड प्रदान नहीं किया गया है, तो एक सुरक्षित 12-वर्ण पासवर्ड उत्पन्न किया जाता है
  - उत्पन्न अस्थायी पासवर्ड केवल प्रतिक्रिया में एक बार लौटाए जाते हैं
  - उपयोगकर्ता निर्माण को ऑडिट लॉग में लॉग किया जाता है

### उपयोगकर्ता अपडेट करें - `/api/users/:id` {/* #update-user---apiusersid */}
- **एंडपॉइंट**: `/api/users/:id`
- **विधि**: PATCH

- **प्रमाणीकरण**: व्यवस्थापक विशेषाधिकारों, वैध सत्र और CSRF टोकन की आवश्यकता होती है
- **पैरामीटर**:
  - `id`: अपडेट करने के लिए उपयोगकर्ता आईडी
- **अनुरोध निकाय**:

  ```json
  {
    "username": "updated-username",
    "isAdmin": true,
    "requirePasswordChange": false,
    "resetPassword": true
  }
  ```

- सभी फ़ील्ड्स वैकल्पिक हैं
  - `resetPassword`: यदि सत्य है, तो एक नया अस्थायी पासवर्ड उत्पन्न करता है और `requirePasswordChange` को सत्य पर सेट करता है
- **प्रतिक्रिया** (पासवर्ड रीसेट के साथ):

  ```json
  {
    "user": {
      "id": "user-id",
      "username": "updated-username",
      "isAdmin": true,
      "mustChangePassword": true
    },
    "temporaryPassword": "new-temp-password-456"
  }
  ```

- **प्रतिक्रिया** (पासवर्ड रीसेट के बिना):

  ```json
  {
    "user": {
      "id": "user-id",
      "username": "updated-username",
      "isAdmin": true,
      "mustChangePassword": false
    }
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य इनपुट या सत्यापन त्रुटियाँ
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: निषिद्ध - व्यवस्थापक विशेषाधिकारों की आवश्यकता है
  - `404`: उपयोगकर्ता नहीं मिला
  - `409`: उपयोगकर्ता नाम पहले से मौजूद है (यदि उपयोगकर्ता नाम बदल रहे हैं)
  - `500`: आंतरिक सर्वर त्रुटि
- **नोट्स**:
  - केवल व्यवस्थापक उपयोगकर्ताओं के लिए सुलभ
  - उपयोगकर्ता नाम परिवर्तन की अद्वितीयता के लिए सत्यापन किया जाता है
  - पासवर्ड रीसेट एक सुरक्षित 12-वर्ण अस्थायी पासवर्ड उत्पन्न करता है
  - सभी परिवर्तनों को ऑडिट लॉग में लॉग किया जाता है

- **विधि**: DELETE
- **विवरण**: उपयोगकर्ता खाता हटाता है। अपने आप को या अंतिम व्यवस्थापक खाता को हटाने से रोकता है।
- **प्रमाणीकरण**: व्यवस्थापक विशेषाधिकारों, वैध सत्र और CSRF टोकन की आवश्यकता होती है
- **पैरामीटर**:
  - `id`: हटाने के लिए उपयोगकर्ता आईडी
- **प्रतिक्रिया**:

  ```json
  {
    "success": true,
    "message": "User deleted successfully"
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अपना खाता या अंतिम व्यवस्थापक खाता हटाया नहीं जा सकता
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: निषिद्ध - व्यवस्थापक विशेषाधिकारों की आवश्यकता है
  - `404`: उपयोगकर्ता नहीं मिला
  - `500`: आंतरिक सर्वर त्रुटि
- **नोट्स**:
  - केवल व्यवस्थापक उपयोगकर्ताओं के लिए सुलभ
  - अपना खाता हटाया नहीं जा सकता
  - अंतिम व्यवस्थापक खाता हटाया नहीं जा सकता (कम से कम एक व्यवस्थापक शेष रहना चाहिए)
  - उपयोगकर्ता हटाने को ऑडिट लॉग में लॉग किया जाता है
  - संबद्ध सत्र स्वचालित रूप से हटा दिए जाते हैं (कैस्केड)

## ऑडिट लॉग प्रबंधन {/* #audit-log-management */}

### ऑडिट लॉग सूचीबद्ध करें - `/api/audit-log` {/* #list-audit-logs---apiaudit-log */}
- **एंडपॉइंट**: `/api/audit-log`
- **विधि**: GET
- **विवरण**: फ़िल्टरिंग, पृष्ठांकन और खोज क्षमताओं के साथ ऑडिट लॉग प्रविष्टियाँ पुनर्प्राप्त करता है। पृष्ठ-आधारित और ऑफ़सेट-आधारित पृष्ठांकन दोनों का समर्थन करता है।
- **प्रमाणीकरण**: मान्य सत्र और CSRF टोकन की आवश्यकता है (लॉग इन किए हुए उपयोगकर्ता आवश्यक)
- **क्वेरी पैरामीटर**:
  - `page` (वैकल्पिक): पृष्ठ-आधारित पृष्ठांकन के लिए पृष्ठ संख्या
  - `offset` (वैकल्पिक): ऑफ़सेट-आधारित पृष्ठांकन के लिए ऑफ़सेट (पृष्ठ पर प्राथमिकता लेता है)
  - `limit` (वैकल्पिक): प्रति पृष्ठ वस्तुएँ (डिफ़ॉल्ट: 50)
  - `startDate` (वैकल्पिक): इस तिथि से लॉग फ़िल्टर करें (ISO प्रारूप)
  - `endDate` (वैकल्पिक): इस तिथि तक लॉग फ़िल्टर करें (ISO प्रारूप)
  - `userId` (वैकल्पिक): उपयोगकर्ता आईडी द्वारा फ़िल्टर करें
  - `username` (वैकल्पिक): उपयोगकर्ता नाम द्वारा फ़िल्टर करें
  - `action` (वैकल्पिक): कार्रवाई नाम द्वारा फ़िल्टर करें
  - `category` (वैकल्पिक): श्रेणी द्वारा फ़िल्टर करें (`auth`, `user_management`, `config`, `backup`, `server`)
  - `status` (वैकल्पिक): स्थिति द्वारा फ़िल्टर करें (`success`, `failure`, `error`)
- **प्रतिक्रिया**:

  ```json
  {
    "logs": [
      {
        "id": 1,
        "timestamp": "2024-01-15T10:30:00Z",
        "userId": "user-id",
        "username": "admin",
        "action": "login",
        "category": "auth",
        "targetType": "user",
        "targetId": "user-id",
        "status": "success",
        "ipAddress": "192.168.1.100",
        "userAgent": "Mozilla/5.0...",
        "details": {
          "is_admin": true
        },
        "errorMessage": null
      }
    ],
    "pagination": {
      "page": 1,
      "limit": 50,
      "total": 150,
      "totalPages": 3
    }
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `500`: आंतरिक सर्वर त्रुटि
- **नोट**:
  - पृष्ठ-आधारित (`page`) और ऑफ़सेट-आधारित (`offset`) पृष्ठांकन दोनों का समर्थन करता है
  - `details` फ़ील्ड अतिरिक्त संदर्भ के साथ पार्स किए गए JSON को शामिल करता है
  - सभी ऑडिट लॉग क्वेरी लॉग की जाती हैं

  - Content-Type: `application/json`
  - Content-Disposition: `attachment; filename="audit-log-YYYY-MM-DD.json"`
  - ऑडिट लॉग प्रविष्टियों की JSON सरणी
- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: निर्यात करने के लिए कोई लॉग नहीं
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `500`: आंतरिक सर्वर त्रुटि

  - CSV प्रारूप विशेष वर्णों को ठीक से एस्केप करता है
  - CSV में विवरण फ़ील्ड JSON-स्ट्रिंगीकृत है

### डेटाबेस बैकअप - `/api/database/backup` {/* #backup-database---apidatabasebackup */}
- **एंडपॉइंट**: `/api/database/backup`
- **विधि**: GET
- **विवरण**: बाइनरी (.db) या SQL (.sql) प्रारूप में डेटाबेस का बैकअप बनाता है। बैकअप फ़ाइल को स्वचालित रूप से टाइमस्टैम्प वाले फ़ाइलनाम के साथ डाउनलोड किया जाता है।
- **प्रमाणीकरण**: एडमिन अधिकारों, वैध सत्र और CSRF टोकन की आवश्यकता है
- **क्वेरी पैरामीटर्स**:
  - `format` (वैकल्पिक): बैकअप प्रारूप - `db` (बाइनरी) या `sql` (SQL डम्प)। डिफ़ॉल्ट: `db`
- **प्रतिक्रिया**:
  - Content-Type: `application/octet-stream` (.db के लिए) या `text/plain` (.sql के लिए)
  - Content-Disposition: `attachment; filename="duplistatus-backup-YYYY-MM-DDTHH-MM-SS.db"` या `.sql`
  - बाइनरी फ़ाइल सामग्री (.db के लिए) या SQL टेक्स्ट सामग्री (.sql के लिए)
- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य प्रारूप ("db" या "sql" होना चाहिए)
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `403`: निषिद्ध - एडमिन अधिकार आवश्यक
  - `500`: डेटाबेस बैकअप बनाने में विफल
- **नोट्स**:
  - केवल एडमिन उपयोगकर्ताओं के लिए सुलभ
  - बाइनरी प्रारूप अखंडता के लिए SQLite की बैकअप विधि का उपयोग करता है
  - SQL प्रारूप सभी डेटाबेस सामग्री का टेक्स्ट डम्प बनाता है
  - फ़ाइलनाम में टाइमस्टैम्प सर्वर के स्थानीय समयक्षेत्र का उपयोग करता है
  - ऑडिट लॉग में बैकअप ऑपरेशन लॉग किया जाता है
  - डाउनलोड के बाद अस्थायी फ़ाइलें स्वचालित रूप से साफ़ की जाती हैं

  - फ़ाइल या तो `.db`, `.sqlite`, `.sqlite3` (बाइनरी प्रारूप) या `.sql` (SQL प्रारूप) होनी चाहिए

  - `403`: निषिद्ध - एडमिन अधिकार आवश्यक

  - बाइनरी (.db) और SQL (.sql) दोनों प्रारूपों का समर्थन करता है
  - पुनर्स्थापना के बाद डेटाबेस अखंडता की पुष्टि करता है
  - यदि पुनर्स्थापना विफल होती है, तो स्वचालित रूप से सुरक्षा बैकअप से पुनर्स्थापित करता है
  - सुरक्षा के लिए सफल पुनर्स्थापना के बाद सभी सत्र साफ़ किए जाते हैं
  - उपयोगकर्ता को फिर से लॉग इन करने की आवश्यकता है इसका संकेत देने के लिए `requiresReauth: true` लौटाता है
  - ऑडिट लॉग में पुनर्स्थापना ऑपरेशन लॉग किया जाता है
  - SQL प्रारूप के लिए, निष्पादन से पहले SQL सामग्री की पुष्टि करता है
  - पुनर्स्थापना के बाद डेटाबेस कनेक्शन पुनरारंभ किया जाता है
  - पुनर्स्थापना के बाद सभी कैश अमान्य कर दिए जाते हैं

## बैकअप टाइमस्टैम्प {/* #backup-timestamps */}

### अंतिम बैकअप टाइमस्टैम्प प्राप्त करें - `/api/backups/last-timestamps` {/* #get-last-backup-timestamps---apibackupslast-timestamps */}
- **एंडपॉइंट**: `/api/backups/last-timestamps`
- **विधि**: GET
- **विवरण**: प्रत्येक सर्वर-बैकअप संयोजन के लिए अंतिम बैकअप टाइमस्टैम्प पुनः प्राप्त करता है। आसान खोज के लिए एक मानचित्र लौटाता है।
- **प्रमाणीकरण**: वैध सत्र और CSRF टोकन की आवश्यकता है
- **प्रतिक्रिया**:

  ```json
  {
    "timestamps": {
      "server-id-1:Backup Name 1": "2024-03-20T10:00:00Z",
      "server-id-1:Backup Name 2": "2024-03-20T11:00:00Z",
      "server-id-2:Backup Name 1": "2024-03-20T12:00:00Z"
    },
    "raw": [
      {
        "server_name": "Server Name",
        "server_id": "server-id-1",
        "backup_name": "Backup Name 1",
        "date": "2024-03-20T10:00:00Z"
      }
    ]
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `401`: अनधिकृत - अमान्य सत्र या CSRF टोकन
  - `500`: अंतिम बैकअप टाइमस्टैम्प प्राप्त करने में विफल
- **नोट्स**:
  - आसान खोज के लिए एक मानचित्र (`server_id:backup_name` द्वारा) और रॉ ऐरे प्रारूप दोनों लौटाता है
  - कैशिंग को रोकने के लिए कैश नियंत्रण हेडर शामिल करता है
  - सभी सर्वर-बैकअप संयोजनों में अंतिम बैकअप समय को ट्रैक करने के लिए उपयोगी
  - टाइमस्टैम्प ISO प्रारूप में हैं

## एप्लिकेशन लॉग प्रबंधन {/* #application-logs-management */}

### एप्लिकेशन लॉग प्राप्त करें - `/api/application-logs` {/* #get-application-logs---apiapplication-logs */}
- **एंडपॉइंट**: `/api/application-logs`
- **विधि**: GET
- **विवरण**: लॉग फ़ाइलों से एप्लिकेशन लॉग प्रविष्टियाँ पुनः प्राप्त करता है। टेल कार्यक्षमता के साथ वर्तमान और घुमाए गए लॉग फ़ाइल पढ़ने का समर्थन करता है।
- **प्रमाणीकरण**: एडमिन अधिकारों, वैध सत्र और सीएसआरएफ टोकन की आवश्यकता होती है
- **क्वेरी पैरामीटर**:
  - `file` (वैकल्पिक): पढ़ने के लिए लॉग फ़ाइल का नाम - `application.log`, `application.log.1`, `application.log.2`, आदि। यदि प्रदान नहीं किया गया है, तो उपलब्ध फ़ाइलों की सूची लौटाता है
  - `tail` (वैकल्पिक): फ़ाइल के अंत से लौटाने के लिए पंक्तियों की संख्या (डिफ़ॉल्ट: 1000, न्यूनतम: 1, अधिकतम: 10000)
- **प्रतिक्रिया** (फ़ाइल पैरामीटर के साथ):

  ```json
  {
    "logs": "log content as string...",
    "fileSize": 1024000,
    "lastModified": "2024-03-20T10:00:00Z",
    "lineCount": 5000,
    "currentFile": "application.log",
    "availableFiles": ["application.log", "application.log.1", "application.log.2"]
  }
  ```

- **प्रतिक्रिया** (फ़ाइल पैरामीटर के बिना):

  ```json
  {
    "logs": "",
    "fileSize": 0,
    "lastModified": "2024-03-20T10:00:00Z",
    "lineCount": 0,
    "currentFile": "",
    "availableFiles": ["application.log", "application.log.1", "application.log.2"]
  }
  ```

- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: अमान्य टेल पैरामीटर (1-10000 होना चाहिए) या अमान्य फ़ाइल पैरामीटर प्रारूप
  - `401`: अनधिकृत - अमान्य सत्र या सीएसआरएफ टोकन
  - `403`: निषिद्ध - एडमिन अधिकार आवश्यक हैं
  - `404`: लॉग फ़ाइल नहीं मिली
  - `500`: लॉग फ़ाइल पढ़ने में विफल
- **नोट**:
  - केवल एडमिन उपयोगकर्ताओं के लिए सुलभ
  - वर्तमान लॉग फ़ाइल और घुमाए गए लॉग फ़ाइलों (10 घुमाए गए फ़ाइलों तक) को पढ़ने का समर्थन करता है
  - निर्दिष्ट लॉग फ़ाइल से अंतिम N पंक्तियाँ (टेल) लौटाता है
  - लॉग फ़ाइल का नाम वातावरण चर द्वारा निर्धारित किया जाता है (डिफ़ॉल्ट: `application.log`)
  - जब फ़ाइल पैरामीटर प्रदान नहीं किया गया हो तो उपलब्ध लॉग फ़ाइलों की सूची लौटाता है
  - निर्देशिका पार आक्रमण हमलों को रोकने के लिए फ़ाइल नामों को मान्य किया जाता है
  - घुमाए गए फ़ाइलों को क्रमिक रूप से संख्यांकित किया जाता है (`.1`, `.2`, आदि)

### एप्लिकेशन लॉग निर्यात करें - `/api/application-logs/export` {/* #export-application-logs---apiapplication-logsexport */}
- **एंडपॉइंट**: `/api/application-logs/export`
- **विधि**: GET
- **विवरण**: फ़िल्टर किए गए पाठ प्रारूप में एप्लिकेशन लॉग प्रविष्टियाँ निर्यात करता है। लॉग स्तर और खोज स्ट्रिंग द्वारा फ़िल्टरिंग का समर्थन करता है।
- **प्रमाणीकरण**: एडमिन अधिकारों, वैध सत्र और सीएसआरएफ टोकन की आवश्यकता होती है
- **क्वेरी पैरामीटर**:
  - `file` (आवश्यक): निर्यात करने के लिए लॉग फ़ाइल का नाम - `application.log`, `application.log.1`, `application.log.2`, आदि।
  - `logLevels` (वैकल्पिक): शामिल करने के लिए अल्पविराम से अलग किए गए लॉग स्तरों की सूची - `INFO`, `WARN`, `ERROR` (डिफ़ॉल्ट: `INFO,WARN,ERROR`)
  - `search` (वैकल्पिक): लॉग पंक्तियों को फ़िल्टर करने के लिए खोज स्ट्रिंग (केस-असंवेदनशील)
- **प्रतिक्रिया**:
  - Content-Type: `text/plain`
  - Content-Disposition: `attachment; filename="duplistatus-logs-YYYY-MM-DDTHH-MM-SS.txt"`
  - सादा पाठ के रूप में फ़िल्टर किया गया लॉग सामग्री
- **त्रुटि प्रतिक्रियाएँ**:
  - `400`: फ़ाइल पैरामीटर आवश्यक है या अमान्य फ़ाइल पैरामीटर प्रारूप
  - `401`: अनधिकृत - अमान्य सत्र या सीएसआरएफ टोकन
  - `403`: निषिद्ध - एडमिन अधिकार आवश्यक हैं
  - `500`: लॉग निर्यात करने में विफल
- **नोट**:
  - केवल एडमिन उपयोगकर्ताओं के लिए सुलभ
  - लॉग स्तर और खोज मानदंड के आधार पर फ़िल्टर किए गए लॉग प्रविष्टियाँ निर्यात करता है
  - लॉग स्तरों द्वारा फ़िल्टरिंग का समर्थन करता है: `INFO`, `WARN`, `ERROR`
  - खोज स्ट्रिंग फ़िल्टरिंग केस-असंवेदनशील है
  - रिक्त पंक्तियाँ स्वचालित रूप से फ़िल्टर कर दी जाती हैं
  - लॉग फ़ाइल का नाम वातावरण चर द्वारा निर्धारित किया जाता है (डिफ़ॉल्ट: `application.log`)
  - निर्देशिका पार आक्रमण हमलों को रोकने के लिए फ़ाइल नामों को मान्य किया जाता है
  - निर्यातित फ़ाइल में फ़ाइलनाम में टाइमस्टैम्प शामिल होता है
  - बाहरी विश्लेषण और समस्या निवारण के लिए उपयोगी
