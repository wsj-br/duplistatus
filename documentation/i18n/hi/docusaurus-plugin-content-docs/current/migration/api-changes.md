# बैकवर्ड-असंगत API परिवर्तन {/* #backward-incompatible-api-changes */}

यह दस्तावेज़ duplistatus के विभिन्न संस्करणों में बाहरी API एंडपॉइंट्स के ब्रेकिंग परिवर्तनों की रूपरेखा प्रस्तुत करता है। बाहरी API एंडपॉइंट वे हैं जो अन्य ऐप्लिकेशन और एकीकरण (उदा. होमपेज एकीकरण) द्वारा उपयोग के लिए डिज़ाइन किए गए हैं।

## अवलोकन {/* #overview */}

यह दस्तावेज़ बाहरी API एंडपॉइंट्स के ब्रेकिंग परिवर्तनों को कवर करता है जो इन एंडपॉइंट्स का उपयोग करने वाले एकीकरण, स्क्रिप्ट और ऐप्लिकेशन को प्रभावित करते हैं। वेब इंटरफ़ेस द्वारा उपयोग किए जाने वाले आंतरिक API एंडपॉइंट्स के लिए, परिवर्तन स्वचालित रूप से संभाले जाते हैं और उनके लिए मैन्युअल अपडेट की आवश्यकता नहीं होती है।

:::note
जहाँ संभव हो, बाहरी API एंडपॉइंट्स को बैकवर्ड संगतता के लिए बनाए रखा जाता है। ब्रेकिंग परिवर्तन केवल निरंतरता, सुरक्षा या कार्यक्षमता में सुधार के लिए आवश्यक होने पर ही पेश किए जाते हैं।
:::

### संस्करण 0.9.x {/* #version-09x */}

**बाहरी API एंडपॉइंट में कोई ब्रेकिंग बदलाव नहीं**

संस्करण 0.9.x प्रमाणीकरण पेश करता है और इसके लिए आवश्यक है कि सभी उपयोगकर्ता लॉग इन करें। संस्करण 0.8.x से अपग्रेड करते समय:

1. **प्रमाणीकरण आवश्यक है**: सभी पृष्ठों और आंतरिक API एंडपॉइंट्स के लिए अब प्रमाणीकरण आवश्यक है
2. **डिफ़ॉल्ट एडमिन खाता**: एक डिफ़ॉल्ट एडमिन खाता स्वचालित रूप से बनाई गई है:
   - उपयोगकर्ता नाम: `admin`
   - पासवर्ड: `Duplistatus09` (पहले लॉगिन पर बदला जाना चाहिए)
3. **सत्र अमान्यकरण**: सभी मौजूदा सत्र अमान्य कर दिए जाते हैं
4. **बाहरी API एक्सेस**: एकीकरण और Duplicati के साथ संगतता के लिए बाहरी API एंडपॉइंट्स (`/api/summary`, `/api/lastbackup`, `/api/lastbackups`, `/api/upload`) अप्रमाणित रहते हैं

### संस्करण 0.8.x {/* #version-08x */}

**बाहरी API एंडपॉइंट में कोई ब्रेकिंग बदलाव नहीं**

संस्करण 0.8.x बाहरी API एंडपॉइंट में कोई ब्रेकिंग बदलाव प्रस्तुत नहीं करता है। निम्नलिखित एंडपॉइंट अपरिवर्तित रहते हैं:

- `/api/summary` - रिस्पॉन्स संरचना अपरिवर्तित
- `/api/lastbackup/{serverId}` - रिस्पॉन्स संरचना अपरिवर्तित
- `/api/lastbackups/{serverId}` - रिस्पॉन्स संरचना अपरिवर्तित
- `/api/upload` - अनुरोध/रिस्पॉन्स फ़ॉर्मैट अपरिवर्तित

#### सुरक्षा सुधार {/* #security-enhancements */}

हालाँकि बाहरी API एंडपॉइंट में कोई ब्रेकिंग बदलाव नहीं किए गए थे, लेकिन संस्करण 0.8.x में सुरक्षा सुधार शामिल हैं:

- **CSRF सुरक्षा**: स्थिति बदलने वाले API अनुरोधों के लिए CSRF टोकन सत्यापन अनिवार्य किया गया है, लेकिन बाहरी API संगत बने रहते हैं
- **पासवर्ड सुरक्षा**: सुरक्षा कारणों से पासवर्ड एंडपॉइंट उपयोगकर्ता इंटरफ़ेस तक ही सीमित हैं

:::note
ये सुरक्षा सुधार बैकअप डेटा पढ़ने के लिए उपयोग किए जाने वाले बाहरी API एंडपॉइंट को प्रभावित नहीं करते हैं। यदि आपके पास आंतरिक एंडपॉइंट का उपयोग करने वाली कस्टम स्क्रिप्ट हैं, तो उन्हें CSRF टोकन हैंडलिंग की आवश्यकता हो सकती है।
:::

### संस्करण 0.7.x {/* #version-07x */}

संस्करण 0.7.x बाहरी API एंडपॉइंट में कई ब्रेकिंग बदलाव लाता है जिनके लिए बाहरी एकीकरण में अपडेट की आवश्यकता होती है।

#### ब्रेकिंग बदलाव {/* #breaking-changes */}

##### फ़ील्ड का नाम बदलना {/* #field-renaming */}

- `/api/summary` एंडपॉइंट में `totalMachines` → `totalServers`
- API रिस्पॉन्स ऑब्जेक्ट्स में `machine` → `server`
- `/api/lastbackups/{serverId}` एंडपॉइंट में `backup_types_count` → `backup_jobs_count`

##### एंडपॉइंट पाथ बदलाव {/* #endpoint-path-changes */}

- पहले `/api/machines/...` का उपयोग करने वाले सभी API एंडपॉइंट अब `/api/servers/...` का उपयोग करते हैं
- पैरामीटर नाम `machine_id` से बदलकर `server_id` हो गए हैं (URL एन्कोडिंग अभी भी दोनों के साथ काम करती है)

#### रिस्पॉन्स संरचना बदलाव {/* #response-structure-changes */}

संगतता के लिए कई एंडपॉइंट की रिस्पॉन्स संरचना को अपडेट किया गया है:

##### `/api/summary` {/* #apisummary */}

**पहले (0.6.x और उससे पहले):**

```json
{
  "totalMachines": 3,
  "totalBackupsRuns": 9,
  "totalBackups": 9,
  "totalUploadedSize": 2397229507,
  "totalStorageUsed": 43346796938,
  "totalBackupSize": 126089687807,
  "overdueBackupsCount": 2,
  "secondsSinceLastBackup": 7200
}
```

**बाद में (0.7.x+):**

```json
{
  "totalServers": 3,  // Changed from "totalMachines"
  "totalBackupsRuns": 9,
  "totalBackups": 9,
  "totalUploadedSize": 2397229507,
  "totalStorageUsed": 43346796938,
  "totalBackupSize": 126089687807,
  "overdueBackupsCount": 2,
  "secondsSinceLastBackup": 7200
}
```

##### `/api/lastbackup/{serverId}` {/* #apilastbackupserverid */}

**पहले (0.6.x और उससे पहले):**

```json
{
  "machine": {  // Changed to "server"
    "id": "unique-server-id",
    "name": "Server Name",
    "backup_name": "Backup Name",
    "backup_id": "backup-id",
    "created_at": "2024-03-20T10:00:00Z"
  },

    // ... backup details

**बाद में (0.7.x+):**

    "backup_name": "Backup Name",

```

**पहले (0.6.x और उससे पहले):**

## माइग्रेशन के चरण {/* #migration-steps */}

यदि आप 0.7.x से पुराने संस्करण से अपग्रेड कर रहे हैं, तो इन चरणों का पालन करें:

1. **फ़ील्ड संदर्भ अपडेट करें**: पुराने फ़ील्ड नामों के सभी संदर्भों को नए नामों से बदलें
   - `totalMachines` → `totalServers`
   - `backup_types_count` → `backup_jobs_count`

2. **ऑब्जेक्ट कुंजियाँ अपडेट करें**: रिस्पॉन्स पार्सिंग में `machine` को बदल कर `server` करें
   - `response.machine` को एक्सेस करने वाले किसी भी कोड को अपडेट करके `response.server` करें

3. **एंडपॉइंट पाथ अपडेट करें**: `/api/machines/...` का उपयोग करने वाले किसी भी एंडपॉइंट को बदल कर `/api/servers/...` करें
   - ध्यान दें: पैरामीटर्स अभी भी पुराने आइडेंटिफ़ायर्स स्वीकार कर सकते हैं; पाथ अपडेट किए जाने चाहिए

4. **इंटीग्रेशन की जाँच करें**: सत्यापित करें कि आपका इंटीग्रेशन नए API स्ट्रक्चर के साथ काम करता है
   - आपका एप्लिकेशन जिन भी एंडपॉइंट्स का उपयोग करता है उन सभी की जाँच करें
   - सत्यापित करें कि रिस्पॉन्स पार्सिंग नए फ़ील्ड नामों को सही ढंग से हैंडल करती है

5. **दस्तावेज़ अपडेट करें**: पुराने API का संदर्भ देने वाले किसी भी आंतरिक दस्तावेज़ को अपडेट करें
   - API उदाहरणों और फ़ील्ड नाम संदर्भों को अपडेट करें

## कम्पैटिबिलिटी {/* #compatibility */}

### बैकवर्ड कम्पैटिबिलिटी {/* #backward-compatibility */}

- **संस्करण 1.2.1**: 1.1.x API स्ट्रक्चर के साथ पूरी तरह से बैकवर्ड कम्पैटिबल
- **संस्करण 1.1.x**: 1.0.x API स्ट्रक्चर के साथ पूरी तरह से बैकवर्ड कम्पैटिबल
- **संस्करण 1.0.x**: 0.9.x API स्ट्रक्चर के साथ पूरी तरह से बैकवर्ड कम्पैटिबल
- **संस्करण 0.9.x**: 0.8.x API स्ट्रक्चर के साथ पूरी तरह से बैकवर्ड कम्पैटिबल
- **संस्करण 0.8.x**: 0.7.x API स्ट्रक्चर के साथ पूरी तरह से बैकवर्ड कम्पैटिबल
- **संस्करण 0.7.x**: 0.7.x से पहले के संस्करणों के साथ बैकवर्ड कम्पैटिबल नहीं
  - पुराने फ़ील्ड नाम काम नहीं करेंगे
  - पुराने एंडपॉइंट पाथ काम नहीं करेंगे

### भविष्य का समर्थन {/* #future-support */}

- 0.7.x से पहले के संस्करणों के पुराने फ़ील्ड नाम समर्थित नहीं हैं
- 0.7.x से पहले के संस्करणों के पुराने एंडपॉइंट पाथ समर्थित नहीं हैं
- भविष्य के संस्करण वर्तमान API स्ट्रक्चर को बनाए रखेंगे जब तक कि ब्रेकिंग बदलाव आवश्यक न हों

## एक्सटर्नल API एंडपॉइंट्स का सारांश {/* #summary-of-external-api-endpoints */}

निम्नलिखित एक्सटर्नल API एंडपॉइंट्स बैकवर्ड कम्पैटिबिलिटी के लिए बनाए रखे गए हैं और अनऑथेंटिकेटेड रहते हैं:

| Endpoint | Method | विवरण | Breaking Changes |
|----------|--------|-------------|------------------|
| `/api/summary` | GET | बैकअप ऑपरेशन्स का समग्र सारांश | 0.7.x: `totalMachines` → `totalServers` |
| `/api/lastbackup/{serverId}` | GET | सर्वर के लिए नवीनतम बैकअप | 0.7.x: `machine` → `server` |
| `/api/lastbackups/{serverId}` | GET | सभी बैकअप जॉब्स के लिए नवीनतम बैकअप | 0.7.x: `machine` → `server`, `backup_types_count` → `backup_jobs_count` |
| `/api/upload` | POST | Duplicati से बैकअप डेटा अपलोड करें | कोई ब्रेकिंग बदलाव नहीं |

## सहायता चाहिए? {/* #need-help */}

यदि आपको अपने एकीकरण (इंटीग्रेशन) को अपडेट करने में सहायता चाहिए:

- **API संदर्भ**: वर्तमान एंडपॉइंट दस्तावेज़ के लिए [API संदर्भ](../api-reference/overview.md) जांचें
- **बाहरी API**: विस्तृत एंडपॉइंट दस्तावेज़ के लिए [बाहरी API](../api-reference/external-apis.md) देखें
- **माइग्रेशन गाइड**: सामान्य माइग्रेशन जानकारी के लिए [माइग्रेशन गाइड](version_upgrade.md) की समीक्षा करें
- **रिलीज़ नोट्स**: अतिरिक्त संदर्भ के लिए संस्करण-विशिष्ट [रिलीज़ नोट्स](../release-notes/0.8.x.md) की समीक्षा करें
- **सहायता (सपोर्ट)**: सहायता के लिए [GitHub](https://github.com/wsj-br/duplistatus/issues) पर एक इश्यू खोलें
