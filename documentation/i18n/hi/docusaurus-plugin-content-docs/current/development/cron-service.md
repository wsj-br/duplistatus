# Cron सर्विस {/* #cron-service */}

एप्लिकेशन में शेड्यूल किए गए कार्यों (टास्क्स) को संभालने के लिए एक अलग cron सर्विस शामिल है:

## डेवलपमेंट मोड में cron सर्विस शुरू करें {/* #start-cron-service-in-development-mode */}

`pnpm dev` पहले से ही Next.js के साथ cron सर्विस शुरू करता है। cron को अकेले चलाने के लिए (उदाहरण के लिए दूसरे टर्मिनल में):

```bash
pnpm cron:dev
```

## प्रोडक्शन मोड में cron सर्विस शुरू करें {/* #start-cron-service-in-production-mode */}

```bash
pnpm cron:start
```

## स्थानीय रूप से cron सर्विस शुरू करें (परीक्षण के लिए) {/* #start-cron-service-locally-for-testing */}

```bash
pnpm cron:start-local
```

cron सर्विस एक अलग पोर्ट पर चलती है (डेवलपमेंट में 8667, प्रोडक्शन में 9667) और बकाया बैकअप सूचनाएं जैसे शेड्यूल किए गए कार्यों को संभालती है। पोर्ट को `CRON_PORT` एनवायरनमेंट वेरिएबल का उपयोग करके कॉन्फ़िगर किया जा सकता है।

cron सर्विस में शामिल हैं:
- **हेल्थ चेक एंडपॉइंट**: `/health` - सर्विस स्थिति और सक्रिय कार्यों को लौटाता है
- **मैन्युअल टास्क ट्रिगरिंग**: `POST /trigger/:taskName` - शेड्यूल किए गए कार्यों को मैन्युअल रूप से निष्पादित करें। इस रूट पर `daily-summary-dispatch` टास्क को अस्वीकार कर दिया जाता है; इसके बजाय सेटिंग्स → दैनिक सारांश **अभी सारांश भेजें** का उपयोग करें
- **टास्क प्रबंधन**: `POST /start/:taskName` और `POST /stop/:taskName` - अलग-अलग कार्यों को नियंत्रित करें
- **कॉन्फ़िगरेशन पुनः लोड**: `POST /reload-config` - डेटाबेस से कॉन्फ़िगरेशन को पुनः लोड करें
- **स्वचालित पुनरारंभ**: यदि सर्विस क्रैश हो जाती है तो यह स्वचालित रूप से पुनरारंभ हो जाती है (Docker डिप्लॉयमेंट में `docker-entrypoint.sh` द्वारा प्रबंधित)
- **वॉच मोड**: डेवलपमेंट मोड में कोड परिवर्तनों पर स्वचालित रूप से पुनरारंभ करने के लिए फ़ाइल वॉचिंग शामिल है
- **बकाया बैकअप निगरानी**: बकाया बैकअप की स्वचालित जांच और सूचना (डिफ़ॉल्ट रूप से हर 5 मिनट में चलता है)
- **दैनिक सारांश प्रेषण**: संग्रहीत दैनिक सारांश UTC समय (`minute hour * * *`) पर दिन में एक बार वर्तमान-स्थिति का स्नैपशॉट भेजता है। नए इंस्टॉलेशन के लिए डिफ़ॉल्ट 01:00 UTC है। भेजने का समय बदलने से यह शेड्यूल पुनः लोड हो जाता है। यदि दैनिक सारांश सक्षम है तो कार्य भेजा जाता है और यह घड़ी की दोबारा जांच नहीं करता है।
- **ऑडिट लॉग क्लीनअप**: पुरानी ऑडिट लॉग प्रविष्टियों की स्वचालित सफाई (प्रतिदिन 2 AM UTC पर चलता है)
- **डेटाबेस कॉम्पैक्ट**: साप्ताहिक रविवार 04:00 UTC। उन बैकअप पंक्तियों को हटाता है जिनका सर्वर अब मौजूद नहीं है, बिना किसी शेष बैकअप वाली सर्वर पंक्तियों को, बची हुई `backup_settings` और `overdue_notifications` कुंजियों को हटाता है, पुरानी दैनिक सारांश डिलीवरी पंक्तियों को साफ़ करता है, और SQLite `VACUUM` चलाता है
- **Duplicati संस्करण रीफ्रेश करें**: GitHub Releases से कैश्ड नवीनतम Duplicati चैनल संस्करणों को अपडेट करता है। डिफ़ॉल्ट प्रतिदिन 3 AM UTC है; व्यवस्थापक [सेटिंग्स → Duplicati संस्करण](../user-guide/settings/duplicati-versions.md) में अंतराल और प्रारंभ समय बदल सकते हैं।
- **लचीला शेड्यूलिंग**: विभिन्न कार्यों के लिए कॉन्फ़िगर करने योग्य cron एक्सप्रेशन
- **डेटाबेस एकीकरण**: मुख्य एप्लिकेशन के साथ समान SQLite डेटाबेस साझा करता है
- **RESTful API**: सर्विस प्रबंधन और निगरानी के लिए पूर्ण API
- **लोकल बाइंड**: डिफ़ॉल्ट रूप से `127.0.0.1` (`CRON_BIND_HOST`) पर सुनता है। गैर-लूपबैक बाइंड के लिए `CRON_SERVICE_SECRET` आवश्यक है
