# कार्यस्थान प्रशासन स्क्रिप्ट और कमांड {#workspace-admin-scripts-commands}

## डेटाबेस साफ़ करें {#clean-database}

```bash
./scripts/clean-db.sh
```

डेटाबेस को साफ़ करता है, जिसमें सभी डेटा को हटाया जाता है जबकि डेटाबेस स्कीमा और संरचना को संरक्षित रखा जाता है।

>[!CAUTION]
> सावधान रहें क्योंकि यह सभी मौजूदा डेटा को हटा देगा।

## बिल्ड आर्टिफैक्ट और निर्भरताओं को साफ़ करें {#clean-build-artefacts-and-dependencies}

```bash
scripts/clean-workspace.sh
```

सभी बिल्ड आर्टिफैक्ट, node_modules डायरेक्टरी, और अन्य उत्पन्न फ़ाइलें को हटाता है ताकि एक साफ़ स्थिति सुनिश्चित की जा सके। यह तब उपयोगी होता है जब आपको एक ताज़ा इंस्टॉलेशन करने की आवश्यकता होती है या निर्भरता समस्याओं को हल करने की। कमांड निम्नलिखित को हटा देगा:
- `node_modules/` डायरेक्टरी
- `.next/` बिल्ड डायरेक्टरी
- `dist/` डायरेक्टरी
- `out/` डायरेक्टरी
- `.turbo/` डायरेक्टरी
- `pnpm-lock.yaml`
- `data/*.json` (विकास JSON बैकअप फ़ाइलें)
- `public/documentation`
- `documentation/.docusaurus`, `.cache`, `.cache-*`, `build`, `node_modules`, `pnpm-lock.yaml`
- `.genkit/` डायरेक्टरी
- `*.tsbuildinfo` फ़ाइलें
- pnpm स्टोर कैश (via `pnpm store prune`)
- Docker बिल्ड कैश और सिस्टम प्रून (इमेज, नेटवर्क, वॉल्यूम)

## Docker Compose और Docker पर्यावरण को साफ़ करें {#clean-docker-compose-and-docker-environment}

```bash
scripts/clean-docker.sh
```

एक पूर्ण Docker साफ़-चुपाई, जो निम्नलिखित के लिए उपयोगी है:
- डिस्क स्पेस को मुक्त करना
- पुराने/अनुपयोगित Docker आर्टिफैक्ट को हटाना
- विकास या परीक्षण सत्रों के बाद साफ़-चुपाई करना
- एक साफ डॉकर पर्यावरण बनाए रखना

## पैकेजों को नवीनतम संस्करण में अपडेट करें {#update-the-packages-to-the-latest-version}

आप पैकेजों को मैन्युअल रूप से अपडेट कर सकते हैं:

```bash
ncu --upgrade
pnpm update
```

या स्वचालित स्क्रिप्ट का उपयोग करें (`source` का प्राथमिकता दें ताकि **nvm** आपके वर्तमान शेल पर लागू हो; **CI** या गैर-इंटरैक्टिव रन के लिए `CI=1` या `UPGRADE_ALLOW_EXEC=1` का उपयोग करें):

```bash
source ./scripts/upgrade-dependencies.sh
```

The `upgrade-dependencies.sh` स्क्रिप्ट पूरे निर्भरता अपग्रेड प्रक्रिया को स्वचालित करता है। यह परियोजना-अनिश्चित है: पैकेज मैनेजर, कार्यस्थान पैकेज, और प्रत्येक पैकेज का सत्यापन कमांड स्वचालित रूप से पता लगाया जाता है (इसलिए रूट और `documentation/` पैकेज दोनों अपग्रेड किए जाते हैं, बिना किसी हार्डकोड पथ के)। यह:
- `upgrade-tools.sh` के माध्यम से टूल सेटअप स्रोत करता है (nvm / Node LTS, ग्लोबल `pnpm`, `npm-check-updates`, `doctoc`)
- प्रत्येक पैकेज के लिए **बिल्ड-सुरक्षित** अपग्रेड करता है: `npm-check-updates` नवीनतम संस्करणों को हल करता है, फिर इंस्टॉल और `typecheck`/`lint` रन कार्यस्थान रूट से। सत्यापन विफल होने वाले अपग्रेड को `package.json` संपादित करके बाइसेक्ट किया जाता है (न `pnpm add`, जिसे pnpm कार्यस्थान रूट पर अस्वीकार करता है)। एम्बेडेड पीयर गेट्स `eslint` और `typescript` को पिन करते हैं जब `eslint-plugin-react` / `typescript-eslint` अभी तक नवीनतम मेजर को अनुमति नहीं देते।
- कार्यस्थान pnpm लॉकफ़ाइल को अपडेट करता है और निर्भरताओं को इंस्टॉल करता है
- ब्राउज़रस्‍लिस्ट डेटाबेस को अपडेट करता है
- कमजोरियों की जाँच करता है (`pnpm audit`) और गैर-ब्रेकिंग फिक्स लागू करता है (`pnpm audit --fix`)
- **सुरक्षा को प्राथमिकता देता है**: यदि एक कमजोर सीधा निर्भरता केवल बिल्ड-ब्रेकिंग अपग्रेड द्वारा ही ठीक की जा सकती है, तो सुरक्षित संस्करण को बलपूर्वक लागू किया जाता है और बिल्ड त्रुटियाँ रिपोर्ट की जाती हैं ताकि कोड संगतता के लिए अपडेट किया जा सके
- एक सारांश प्रिंट करता है (अपग्रेड किए गए बनाम बिल्ड-ब्रेकिंग पैकेजों को छोड़ दिया गया, कमजोरियाँ ठीक/बाकी, और मैन्युअल रोलबैक के लिए एक मैनिफेस्ट स्नैपशॉट पथ)

यह स्क्रिप्ट निर्भरताओं को नवीनतम और सुरक्षित रखने के लिए एक पूर्ण वर्कफ़्लो प्रदान करता है।

## संस्करण सूचना को अपडेट करें {#update-version-information}

```bash
./scripts/update-version.sh
```

यह स्क्रिप्ट संस्करण सूचना को कई फ़ाइलों में स्वचालित रूप से अपडेट करती है ताकि उन्हें सिंक्रनाइज़ किया जा सके। यह:
- `package.json` से संस्करण निकालता है
- `.env` फ़ाइल को `VERSION` चर के साथ अपडेट करता है (यदि यह मौजूद नहीं है तो इसे बनाता है)
- `Dockerfile` को `VERSION` चर के साथ अपडेट करता है (यदि यह मौजूद है)
- `documentation/package.json` संस्करण फ़ील्ड को अपडेट करता है (यदि यह मौजूद है)
- केवल तब अपडेट करता है जब संस्करण बदल गया हो
- प्रत्येक ऑपरेशन पर प्रतिक्रिया प्रदान करता है

## प्री-चेक स्क्रिप्ट {#pre-checks-script}

```bash
./scripts/pre-checks.sh
```

यह स्क्रिप्ट विकास सर्वर शुरू करने, बिल्ड करने, या उत्पादन सर्वर शुरू करने से पहले प्री-चेक चलाता है। यह:
- `.duplistatus.key` फ़ाइल का अस्तित्व सुनिश्चित करता है (`ensure-key-file.sh` के माध्यम से)
- संस्करण जानकारी को अपडेट करता है (`update-version.sh` के माध्यम से)

यह स्क्रिप्ट स्वचालित रूप से `pnpm dev`, `pnpm build`, और `pnpm start-local` द्वारा कॉल की जाती है।

## मुख्य फ़ाइल का अस्तित्व सुनिश्चित करें {#ensure-key-file-exists}

```bash
./scripts/ensure-key-file.sh
```

यह स्क्रिप्ट `data` निर्देशिका में `.duplistatus.key` फ़ाइल का अस्तित्व सुनिश्चित करती है। यह:
- `data` निर्देशिका बनाता है यदि यह मौजूद नहीं है
- नई 32-बाइट रैंडम की फ़ाइल उत्पन्न करता है यदि यह गायब है
- फ़ाइल अनुमतियाँ 0400 पर सेट करता है (मालिक के लिए केवल पढ़ने योग्य)
- अनुमतियाँ ठीक करता है यदि वे गलत हैं

कुंजी फ़ाइल एप्लिकेशन में क्रिप्टोग्राफिक ऑपरेशन के लिए उपयोग की जाती है।

## एडमिन खाता पुनर्प्राप्ति {#admin-account-recovery}

```bash
./admin-recovery <username> <new-password>
```

यह स्क्रिप्ट एडमिन खातों की पुनर्प्राप्ति की अनुमति देता है यदि वे लॉक आउट हो गए हैं या पासवर्ड भूल गए हैं। यह:
- निर्दिष्ट उपयोगकर्ता के लिए पासवर्ड रीसेट करता है
- खाता अनलॉक करता है यदि यह लॉक था
- असफल लॉगिन प्रयासों की गिनती रीसेट करता है
- "पासवर्ड बदलना है" फ़्लैग को साफ़ करता है
- पासवर्ड सुरक्षा आवश्यकताओं को पूरा करता है
- ऑडिट लॉग में एक्शन को लॉग करता है

**उदाहरण:**

```bash
./admin-recovery admin NewPassword123
```

>[!CAUTION]
> यह स्क्रिप्ट डेटाबेस को सीधे संशोधित करती है। केवल खाता पुनर्प्राप्ति के लिए उपयोग करें।

## विकास और डॉकर के बीच संस्करणों की तुलना {#compare-versions-between-development-and-docker}

```bash
./scripts/compare-versions.sh
```

यह स्क्रिप्ट आपके विकास पर्यावरण और एक चल रहे डॉकर कंटेनर के बीच संस्करणों की तुलना करती है। यह:
- SQLite संस्करणों को केवल प्रमुख संस्करण द्वारा तुलना करता है (उदाहरण के लिए, 3.45.1 और 3.51.1 को संगत माना जाता है, "✅ (मेजर)" के रूप में दिखाया जाता है)
- Node, npm, और Duplistatus संस्करणों को बिल्कुल एक्सैक्ट रूप से तुलना करता है (बिल्कुल मिलना चाहिए)
- सभी संस्करण तुलनाओं को दिखाने वाला एक स्वरूपित तालिका प्रदर्शित करता है
- रंग-कोडेड परिणामों के साथ एक सारांश प्रदान करता है (✅ मैच के लिए, ❌ असमंजस के लिए)
- सभी संस्करण मैच होने पर कोड 0 से बाहर निकलता है, असमंजस होने पर कोड 1 से बाहर निकलता है

**आवश्यकताएँ:**
- `duplistatus` नामक डॉकर कंटेनर चल रहा होना चाहिए
- स्क्रिप्ट डॉकर कंटेनर लॉग्स से संस्करण जानकारी पढ़ती है

**उदाहरण आउटपुट:**

```
┌─────────────────────────┬──────────────────────────────┬──────────────────────────────┬──────────────┐
│ Component               │ Development                  │ Docker                       │   Match      │
├─────────────────────────┼──────────────────────────────┼──────────────────────────────┼──────────────┤
│ SQLite                  │ 3.45.1                       │ 3.51.1                       │ ✅ (major)   │
│ Node                    │ 24.12.0                      │ 24.12.0                      │ ✅           │
│ npm                     │ 10.9.2                       │ 10.9.2                       │ ✅           │
│ Duplistatus             │ 1.2.1                        │ 1.2.1                        │ ✅           │
└─────────────────────────┴──────────────────────────────┴──────────────────────────────┴──────────────┘
```

**Note:** SQLite संस्करणों को केवल प्रमुख संस्करण के आधार पर तुलना की जाती है क्योंकि एक ही प्रमुख संस्करण के भीतर विभिन्न पैच संस्करण आमतौर पर संगत होते हैं। स्क्रिप्ट बताएगी कि SQLite संस्करण प्रमुख स्तर पर मैच करते हैं लेकिन पैच संस्करण में भिन्न हैं।

## डेटाबेस में कॉन्फ़िगरेशन देखने {#viewing-the-configurations-in-the-database}

```bash
sqlite3 data/backups.db "SELECT key, value FROM configurations;" | awk -F'|' '
  {print "\n" $1 ": "; 
   if(index($2,"{")>0) {print $2 |"jq -C ."; close("jq -C .")} 
   else {print $2;}}' | less -R
```

## बैकअप सेटिंग्स दिखाएँ {#show-backup-settings}

```bash
./scripts/show-backup-settings.sh [database_path]
```

कॉन्फ़िगरेशन टेबल में `backup_settings` मान की सामग्री को एक स्वरूपित टेबल में प्रदर्शित करता है। नोटिफिकेशन कॉन्फ़िगरेशन डीबग करने के लिए उपयोगी है। डिफ़ॉल्ट डेटाबेस पथ: `data/backups.db`।
