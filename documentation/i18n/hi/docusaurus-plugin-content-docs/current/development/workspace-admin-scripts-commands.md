## बिल्ड आर्टिफ़ैक्ट्स और डिपेंडेंसी साफ़ करें {/* #clean-build-artefacts-and-dependencies */}

```bash
scripts/clean-workspace.sh
```

एक साफ़ स्थिति सुनिश्चित करने के लिए सभी बिल्ड आर्टिफ़ैक्ट्स, node_modules डायरेक्टरी, और अन्य जनरेट की गई फ़ाइलों को हटाता है। यह तब उपयोगी होता है जब आपको एक नया इंस्टॉलेशन करने या डिपेंडेंसी से जुड़ी समस्याओं को हल करने की आवश्यकता होती है। यह कमांड इन्हें हटा देगा:
- `node_modules/` डायरेक्टरी
- `.next/` बिल्ड डायरेक्टरी
- `dist/` डायरेक्टरी
- `out/` डायरेक्टरी
- `.turbo/` डायरेक्टरी
- `pnpm-lock.yaml`
- `data/*.json` (डेवलपमेंट JSON बैकअप फ़ाइलें)
- `public/documentation`
- `documentation/.docusaurus`, `.cache`, `.cache-*`, `build`, `node_modules`, `pnpm-lock.yaml`
- `.genkit/` डायरेक्टरी
- `*.tsbuildinfo` फ़ाइलें
- pnpm स्टोर कैश (`pnpm store prune` के माध्यम से)
- Docker बिल्ड कैश और सिस्टम प्रून (इमेज, नेटवर्क, वॉल्यूम)

## Docker Compose और Docker परिवेश साफ़ करें {/* #clean-docker-compose-and-docker-environment */}

- एक स्वच्छ Docker परिवेश बनाए रखना

## पैकेजों को नवीनतम संस्करण में अपडेट करें {/* #update-the-packages-to-the-latest-version */}

आप निम्न का उपयोग करके पैकेजों को मैन्युअल रूप से अपडेट कर सकते हैं:

```bash
ncu --upgrade
pnpm update
```

या स्वचालित स्क्रिप्ट का उपयोग करें (`source` को प्राथमिकता दें ताकि **nvm** आपके वर्तमान शेल पर लागू हो; **CI** या नॉन-इंटरैक्टिव रन के लिए `CI=1` या `UPGRADE_ALLOW_EXEC=1` का उपयोग करें):

```bash
source ./scripts/upgrade-dependencies.sh
```

`upgrade-dependencies.sh` स्क्रिप्ट संपूर्ण डिपेंडेंसी अपग्रेड प्रक्रिया को स्वचालित करती है। यह प्रोजेक्ट-एग्नॉस्टिक है: पैकेज मैनेजर, वर्कस्पेस पैकेज, और प्रत्येक पैकेज के सत्यापन कमांड का स्वतः पता लगाया जाता है (ताकि रूट और `documentation/` दोनों पैकेज बिना किसी हार्डकोडेड पाथ के अपग्रेड हो जाएं)। यह:
- `upgrade-tools.sh` (nvm / Node LTS, ग्लोबल `pnpm`, `npm-check-updates`, `doctoc`) के माध्यम से टूल सेटअप सोर्स करता है
- प्रत्येक पैकेज के लिए **बिल्ड-सुरक्षित** अपग्रेड निष्पादित करता है: `npm-check-updates` नवीनतम संस्करणों को हल करता है, फिर इंस्टॉल और `typecheck`/`lint` वर्कस्पेस रूट से चलते हैं। सत्यापन में विफल होने वाले अपग्रेड्स को `package.json` को संपादित करके द्विभाजित (bisect) किया जाता है (`pnpm add` को नहीं, जिसे pnpm वर्कस्पेस रूट पर अस्वीकार करता है)। एम्बेडेड पीयर गेट्स `eslint` और `typescript` को पिन करते हैं जब `eslint-plugin-react` / `typescript-eslint` अभी तक नवीनतम मेजर की अनुमति नहीं देते हैं।
- वर्कस्पेस pnpm लॉकफ़ाइल को अपडेट करता है और डिपेंडेंसी इंस्टॉल करता है
- browserslist डेटाबेस को अपडेट करता है
- सुरक्षा कमियों (vulnerabilities) की जांच करता है (`pnpm audit`) और गैर-ब्रेकिंग फिक्स लागू करता है (`pnpm audit --fix`)
- **सुरक्षा को प्राथमिकता देता है**: यदि किसी असुरक्षित सीधी डिपेंडेंसी को केवल बिल्ड-ब्रेकिंग अपग्रेड द्वारा ही ठीक किया जा सकता है, तो सुरक्षित संस्करण को बाध्यकारी रूप से लागू किया जाता है और बिल्ड त्रुटियाँ रिपोर्ट की जाती हैं ताकि अनुकूलता के लिए कोड को अपडेट किया जा सके
- एक सारांश प्रिंट करता है (अपग्रेड किए गए बनाम छोड़े गए बिल्ड-ब्रेकिंग पैकेज, ठीक की गई/शेष कमियां, और मैन्युअल रोलबैक के लिए एक मैनिफ़ेस्ट स्नैपशॉट पाथ)
- `package.json` और लॉकफ़ाइलों को `/usr/bin/cp` के साथ कॉपी करता है ताकि एक सोर्स्ड इंटरैक्टिव `cp` उपनाम (उदाहरण के लिए `cp -i`) उन फ़ाइलों को ओवरराइट करने के लिए संकेत न दे

यह स्क्रिप्ट डिपेंडेंसी को अद्यतित और सुरक्षित रखने के लिए एक संपूर्ण वर्कफ़्लो प्रदान करती है।

## संस्करण जानकारी अपडेट करें {/* #update-version-information */}

```bash
./scripts/update-version.sh
```

यह स्क्रिप्ट कई फ़ाइलों में संस्करण जानकारी को सिंक्रनाइज़ रखने के लिए स्वचालित रूप से अपडेट करती है। यह:
- `package.json` से संस्करण निकालती है
- `VERSION` वैरिएबल के साथ `.env` फ़ाइल को अपडेट करती है (यदि यह मौजूद नहीं है तो इसे बनाती है)
- `VERSION` वैरिएबल के साथ `Dockerfile` को अपडेट करती है (यदि यह मौजूद है)
- `documentation/package.json` संस्करण फ़ील्ड को अपडेट करती है (यदि यह मौजूद है)
- केवल तभी अपडेट करती है यदि संस्करण बदल गया हो
- प्रत्येक कार्रवाई पर फीडबैक प्रदान करती है

## प्री-चेक स्क्रिप्ट {/* #pre-checks-script */}

```bash
./scripts/pre-checks.sh
```

यह स्क्रिप्ट डेवलपमेंट सर्वर शुरू करने, निर्माण करने, या प्रोडक्शन सर्वर शुरू करने से पहले प्री-चेक चलाती है। यह:
- सुनिश्चित करती है कि `.duplistatus.key` फ़ाइल मौजूद है (`ensure-key-file.sh` के माध्यम से)
- संस्करण जानकारी को अपडेट करती है (`update-version.sh` के माध्यम से)

यह स्क्रिप्ट `pnpm dev`, `pnpm build`, और `pnpm start-local` द्वारा स्वचालित रूप से कॉल की जाती है।

## सुनिश्चित करें कि कुंजी फ़ाइल मौजूद है {/* #ensure-key-file-exists */}

```bash
./scripts/ensure-key-file.sh
```

यह स्क्रिप्ट सुनिश्चित करती है कि `.duplistatus.key` फ़ाइल `data` निर्देशिका में मौजूद है। यह:
- यदि यह मौजूद नहीं है, तो `data` निर्देशिका बनाती है
- यदि गायब है, तो एक नई 32-बाइट रैंडम कुंजी फ़ाइल उत्पन्न करती है
- फ़ाइल अनुमतियों को 0400 पर सेट करती है (स्वामी के लिए केवल-पढ़ने योग्य)
- यदि अनुमतियाँ गलत हैं तो उन्हें ठीक करती है

कुंजी फ़ाइल का उपयोग एप्लिकेशन में क्रिप्टोग्राफ़िक संचालन के लिए किया जाता है।

## एडमिन खाता रिकवरी {/* #admin-account-recovery */}

```bash
./admin-recovery <username> <new-password>
```

यह स्क्रिप्ट लॉक आउट होने या पासवर्ड भूल जाने पर एडमिन खातों की रिकवरी की अनुमति देती है। यह:
- निर्दिष्ट उपयोगकर्ता के लिए पासवर्ड रीसेट करती है
- खाते को अनलॉक करती है यदि वह लॉक किया गया था
- विफल लॉगिन प्रयासों के काउंटर को रीसेट करती है
- "पासवर्ड बदलना आवश्यक है" फ़्लैग को साफ़ करती है
- पुष्टि करती है कि पासवर्ड सुरक्षा आवश्यकताओं को पूरा करता है
- ऑडिट लॉग में कार्रवाई को लॉग करती है

**उदाहरण:**

```bash
./admin-recovery admin NewPassword123
```

>[!CAUTION]
> यह स्क्रिप्ट सीधे डेटाबेस को संशोधित करती है। केवल खाता रिकवरी के लिए आवश्यक होने पर ही उपयोग करें।

## डेवलपमेंट और Docker के बीच संस्करणों की तुलना करें {/* #compare-versions-between-development-and-docker */}

```bash
./scripts/compare-versions.sh
```

यह स्क्रिप्ट आपके डेवलपमेंट परिवेश और चल रहे Docker कंटेनर के बीच संस्करणों की तुलना करती है। यह:
- केवल मुख्य संस्करण द्वारा SQLite संस्करणों की तुलना करती है (उदाहरण के लिए, 3.45.1 बनाम 3.51.1 को संगत माना जाता है, जिसे "✅ (major)" के रूप में दिखाया गया है)
- Node, npm, और duplistatus संस्करणों की सटीक तुलना करती है (सटीक रूप से मेल खाना चाहिए)
- सभी संस्करण तुलनाओं को प्रदर्शित करने वाली एक स्वरूपित तालिका दिखाती है
- रंग-कोडित परिणामों के साथ एक सारांश प्रदान करता है (✅ मिलान के लिए, ❌ बेमेल के लिए)
- यदि सभी संस्करण मेल खाते हैं तो कोड 0 के साथ बाहर निकलता है, और यदि बेमेल हैं तो 1 के साथ

**आवश्यकताएँ:**
- `duplistatus` नाम वाला Docker कंटेनर चल रहा होना चाहिए
- यह स्क्रिप्ट Docker कंटेनर लॉग से संस्करण जानकारी पढ़ती है

**उदाहरण आउटपुट:**

```
┌─────────────────────────┬──────────────────────────────┬──────────────────────────────┬──────────────┐
│ Component               │ Development                  │ Docker                       │   Match      │
├─────────────────────────┼──────────────────────────────┼──────────────────────────────┼──────────────┤
│ SQLite                  │ 3.45.1                       │ 3.51.1                       │ ✅ (major)   │
│ Node                    │ 24.12.0                      │ 24.12.0                      │ ✅           │
│ npm                     │ 10.9.2                       │ 10.9.2                       │ ✅           │
│ Duplistatus             │ 1.2.1                        │ 1.2.1                        │ ✅           │
└─────────────────────────┴──────────────────────────────┴──────────────────────────────┴──────────────┘
```

**नोट:** SQLite संस्करणों की तुलना केवल मुख्य संस्करण के आधार पर की जाती है क्योंकि एक ही मुख्य संस्करण के अंतर्गत विभिन्न पैच संस्करण आमतौर पर संगत होते हैं। यदि SQLite संस्करण मुख्य स्तर पर मेल खाते हैं लेकिन पैच संस्करणों में भिन्न हैं, तो स्क्रिप्ट इसे इंगित करेगी।

कॉन्फ़िगरेशन तालिका में `backup_settings` मान की सामग्री को एक फ़ॉर्मेटेड तालिका में प्रदर्शित करता है। नोटिफ़िकेशन कॉन्फ़िगरेशन को डीबग करने के लिए उपयोगी है। डिफ़ॉल्ट डेटाबेस पाथ: `data/backups.db`।
