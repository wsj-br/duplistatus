# परीक्षण स्क्रिप्ट {#test-scripts}

इस परियोजना में विकास और परीक्षण के लिए कई परीक्षण स्क्रिप्ट शामिल हैं:

> [!NOTE]
> विलंबित डीबगिंग, SMTP मैट्रिक्स परीक्षण और क्रॉन पोर्ट चेक के लिए पुराने रिपॉजिटरी-रूट `pnpm` हेल्पर हटाए गए थे। नीचे दस्तावेज़ किए गए अनुसार एप्लिकेशन UI (**सेटिंग्स → बैकअप मॉनिटरिंग**), प्रमाणित HTTP APIs, और क्रॉन सेवा के खिलाफ `curl` का उपयोग करें।

## परीक्षण डेटा जनरेट करें {#generate-test-data}

```bash
pnpm generate-test-data --servers=N
```

यह स्क्रिप्ट कई सर्वरों और बैकअप्स के लिए परीक्षण बैकअप डेटा जनरेट करती है।

`--servers=N` पैरामीटर **अनिवार्य** है और यह जनरेट करने वाले सर्वरों की संख्या निर्दिष्ट करता है (1-30)।

`--upload` विकल्प का उपयोग जनरेट किए गए डेटा को `/api/upload` पर भेजने के लिए करें।

```bash
pnpm generate-test-data --servers=N --upload
```

**उदाहरण:**

```bash
# Generate data for 5 servers
pnpm generate-test-data --servers=5

# Generate data for 1 server with upload mode
pnpm generate-test-data --upload --servers=1

# Generate data for all 30 servers
pnpm generate-test-data --servers=30
```

>[!CAUTION]
> यह स्क्रिप्ट डेटाबेस में सभी पिछले डेटा को हटा देती है और इसे परीक्षण डेटा से बदल देती है।
> इस स्क्रिप्ट को चलाने से पहले अपने डेटाबेस का बैकअप लें।

## विलंबित चेक और क्रॉन कनेक्टिविटी (विकास) {#overdue-checks-and-cron-connectivity-development}

- **UI (अनुशंसित):** **सेटिंग्स → बैकअप मॉनिटरिंग** खोलें और **टेस्ट विलंबित बैकअप्स** का उपयोग करें। यह निर्धारित कार्य की उसी लॉजिक को चलाता है जो प्रमाणित `POST /api/notifications/check-overdue` के माध्यम से चलाया जाता है।

### एक विशिष्ट तिथि या समय को सिम्युलेट करना {#simulating-a-specific-date-or-time}

सिम्युलेटेड “वर्तमान” समय को इंजेक्ट करने के लिए कोई बंडल्ड CLI नहीं है। एल्गोरिदम और मैनुअल परीक्षण के विचार के लिए, रिपॉजिटरी फ़ाइल `dev/OVERDUE_DETECTION_ALGORITHM.md` और `src/lib/overdue-backup-checker.ts` में कार्यान्वयन देखें।

## CSV निर्यात की वैधता {#validate-csv-export}

```bash
pnpm validate-csv-export
```

यह स्क्रिप्ट CSV निर्यात कार्यक्षमता की वैधता की जाँच करती है। यह:
- CSV निर्यात जनरेशन का परीक्षण करता है
- डेटा प्रारूप और संरचना की पुष्टि करता है
- निर्यात की गई फ़ाइलों में डेटा एकीकरण की जाँच करता है

रिलीज़ से पहले CSV निर्यात सही ढंग से काम करते हैं यह सुनिश्चित करने के लिए उपयोगी है।

## NTFY सर्वर को अस्थायी रूप से ब्लॉक करें (परीक्षण के लिए) {#temporarily-block-ntfy-server-for-testing}

```bash
sudo ./scripts/temporary_ntfy.sh_block.sh
```

यह स्क्रिप्ट NTFY सर्वर (`ntfy.sh`) के आउटगोइंग नेटवर्क एक्सेस को परीक्षण करने के लिए अस्थायी रूप से ब्लॉक करती है। यह:
- NTFY सर्वर का IP पता हासिल करता है
- आउटगोइंग ट्रैफिक को ब्लॉक करने के लिए iptables नियम जोड़ता है
- 10 सेकंड के लिए ब्लॉक करता है (कॉन्फ़िगर करने योग्य)
- स्क्रिप्ट से बाहर निकलते समय स्वचालित रूप से ब्लॉक नियम हटा देता है
- रूट विशेषाधिकार (sudo) की आवश्यकता होती है

>[!CAUTION]
> यह स्क्रिप्ट iptables नियमों को संशोधित करती है और रूट विशेषाधिकार की आवश्यकता होती है। इसका उपयोग केवल नोटिफिकेशन रिट्राई मेकानिज्म का परीक्षण करने के लिए करें।

## डेटाबेस माइग्रेशन परीक्षण {#database-migration-testing}

प्रोजेक्ट में डेटाबेस माइग्रेशन का परीक्षण करने के लिए स्क्रिप्ट शामिल हैं, जो पुराने संस्करणों से वर्तमान संस्करण तक। ये स्क्रिप्ट सुनिश्चित करती हैं कि डेटाबेस माइग्रेशन सही ढंग से काम करते हैं और डेटा एकीकरण बनाए रखते हैं।

### माइग्रेशन परीक्षण डेटा जनरेट करें {#generate-migration-test-data}

```bash
./scripts/generate-migration-test-data.sh
```

यह स्क्रिप्ट एप्लिकेशन के कई ऐतिहासिक संस्करणों के लिए परीक्षण डेटाबेस जनरेट करती है। यह:

1. **रोकता और हटा देता है** किसी भी मौजूदा Docker कंटेनर
2. **प्रत्येक संस्करण के लिए** (v0.4.0, v0.5.0, v0.6.1, 0.7.27, 0.8.21):
   - मौजूदा डेटाबेस फ़ाइलें हटा देता है
   - एक संस्करण टैग फ़ाइल बनाता है
   - विशिष्ट संस्करण के साथ एक Docker कंटेनर शुरू करता है
   - कंटेनर तैयार होने की प्रतीक्षा करता है
   - `pnpm generate-test-data` का उपयोग करके परीक्षण डेटा जनरेट करता है
   - परीक्षण डेटा के साथ UI का स्क्रीनशॉट लेता है
   - कंटेनर को रोकता और हटा देता है
   - WAL फ़ाइलें फ़्लश करता है और डेटाबेस स्कीमा सहेजता है
   - डेटाबेस फ़ाइल को `scripts/migration_test_data/` पर कॉपी करता है

**आवश्यकताएँ:**
- Docker स्थापित और कॉन्फ़िगर किया जाना चाहिए
- Chromium (Playwright के माध्यम से) स्थापित होना चाहिए
- Docker ऑपरेशन के लिए रूट/सुडो एक्सेस की आवश्यकता होती है
- Docker वॉल्यूम `duplistatus_data` मौजूद होना चाहिए

**आउटपुट:**
- डेटाबेस फ़ाइलें: `scripts/migration_test_data/backups_<VERSION>.db`
- स्कीमा फ़ाइलें: `scripts/migration_test_data/backups_<VERSION>.schema`
- स्क्रीनशॉट: `scripts/migration_test_data/duplistatus_test_data_<VERSION>.png`

**कॉन्फ़िगरेशन:**
- सर्वर की संख्या: `SERVERS` वरिएबल के माध्यम से सेट की जाती है (डिफ़ॉल्ट: 3)
- डेटा डायरेक्टरी: `/var/lib/docker/volumes/duplistatus_data/_data`
- पोर्ट: 9666 (Docker कंटेनर पोर्ट)

>[!CAUTION]
> यह स्क्रिप्ट Docker की आवश्यकता होती है और मौजूदा कंटेनर को रोक देगा/हटाएगा। इसमें Docker ऑपरेशन और फ़ाइल सिस्टम एक्सेस के लिए सुडो एक्सेस की आवश्यकता होती है। अगर आपने पहले ही Playwright Chromium ब्राउज़र स्थापित नहीं किया है, तो पहले `pnpm take-screenshots:install` चलाएं।

>[!IMPORTANT]
> यह स्क्रिप्ट केवल एक बार चलानी चाहिए, क्योंकि नए संस्करणों के लिए डेवलपर डेटाबेस फ़ाइल और स्क्रीनशॉट को सीधे `scripts/migration_test_data/` डायरेक्टरी पर कॉपी कर सकते हैं। विकास के दौरान, माइग्रेशन का परीक्षण करने के लिए केवल `./scripts/test-migrations.sh` स्क्रिप्ट चलाएं।

## परीक्षण Docker एंट्रीपॉइंट स्क्रिप्ट {#test-docker-entrypoint-script}

```bash
pnpm test-entrypoint
```

यह स्क्रिप्ट स्थानीय विकास में `docker-entrypoint.sh` के लिए एक परीक्षण रैपर प्रदान करती है। यह एंट्रीपॉइंट लॉगिंग कार्यक्षमता का परीक्षण करने के लिए वातावरण सेटअप करता है और सुनिश्चित करता है कि लॉग्स `data/logs/` में लिखे जाते हैं ताकि एप्लिकेशन उन्हें एक्सेस कर सके।

**यह क्या करता है:**

1. **हमेशा एक नया संस्करण बनाता है**: परीक्षण से पहले स्वचालित रूप से `pnpm build-local` चलाता है एक नया बिल्ड बनाने के लिए (पहले मैन्युअल रूप से बिल्ड करने की आवश्यकता नहीं है)
2. **क्रॉन सेवा का बिल्ड करता है**: सुनिश्चित करता है कि क्रॉन सेवा का बिल्ड किया जाता है (`dist/cron-service.cjs`)
3. **Docker-जैसे संरचना सेटअप करता है**: Docker वातावरण को मॉडल करने के लिए आवश्यक सिमलिंक और डायरेक्टरी संरचना बनाता है
4. **एंट्रीपॉइंट स्क्रिप्ट चलाता है**: उचित पर्यावरण चर के साथ `docker-entrypoint.sh` चलाता है
5. **साफ़ करता है**: बाहर निकलते समय अस्थायी फ़ाइलें स्वचालित रूप से हटा देता है

**उपयोग:**

```bash
# Run the test (builds fresh version automatically)
pnpm test-entrypoint
```

**पर्यावरण चर:**
- `PORT=8666` - Next.js सर्वर के लिए पोर्ट (`start-local` से मेल खाता है)
- `CRON_PORT=8667` - क्रॉन सेवा के लिए पोर्ट
- `VERSION` - स्वचालित रूप से `test-YYYYMMDD-HHMMSS` प्रारूप में सेट किया जाता है

**आउटपुट:**
- लॉग्स `data/logs/application.log` में लिखे जाते हैं (एप्लिकेशन द्वारा एक्सेस योग्य)
- कंसोल आउटपुट में एंट्रीपॉइंट स्क्रिप्ट का निष्पादन दिखाता है
- लॉग फ्लशिंग का परीक्षण करने के लिए Ctrl+C दबाएं

**आवश्यकताएँ:**
- स्क्रिप्ट को रिपॉजिटरी रूट डायरेक्टरी से चलाया जाना चाहिए (pnpm स्वचालित रूप से यह संभालता है)
- स्क्रिप्ट स्वचालित रूप से सभी पूर्वापेक्षाएँ संभालती है (बिल्ड, क्रॉन सेवा, आदि)

**उपयोग मामले:**
- Docker डिप्लॉयमेंट से पहले स्थानीय रूप से एंट्रीपॉइंट स्क्रिप्ट परिवर्तनों का परीक्षण
- लॉग रोटेशन और लॉगिंग कार्यक्षमता का सत्यापन
- शांत शटडाउन और सिग्नल हैंडलिंग का परीक्षण
- स्थानीय वातावरण में एंट्रीपॉइंट स्क्रिप्ट व्यवहार को डीबग करना
