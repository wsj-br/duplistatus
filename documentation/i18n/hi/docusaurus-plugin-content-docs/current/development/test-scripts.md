# जाँचें स्क्रिप्ट {/* #test-scripts */}

इस प्रोजेक्ट में विकास और परीक्षण में सहायता के लिए कई जाँचें स्क्रिप्ट शामिल हैं:

> [!NOTE]
> अतिदेय डीबगिंग, SMTP मैट्रिक्स परीक्षण, और क्रॉन पोर्ट जांचें के लिए लीगेसी रिपॉजिटरी-रूट `pnpm` हेल्पर्स को हटा दिया गया था। नीचे प्रलेखित किए अनुसार एप्लिकेशन UI (**सेटिंग्स → बैकअप निगरानी**), प्रमाणित HTTP APIs, और क्रॉन सर्विस के विरुद्ध `curl` का उपयोग करें।

## जाँचें डेटा जनरेट करें {/* #generate-test-data */}

```bash
pnpm generate-test-data --servers=N
```

यह स्क्रिप्ट कई सर्वर और बैकअप के लिए जाँचें बैकअप डेटा जनरेट करती है।

`--servers=N` पैरामीटर **अनिवार्य** है और यह जनरेट किए जाने वाले सर्वर की संख्या (1-30) निर्दिष्ट करता है।

जनरेट किए गए डेटा को `/api/upload` पर भेजने के लिए `--upload` विकल्प का उपयोग करें

```bash
pnpm generate-test-data --servers=N --upload
pnpm generate-test-data --servers=N --upload --api-key=YOUR_UPLOAD_KEY
```

जब सेटिंग्स → API कुंजियाँ को कुंजियों की आवश्यकता के लिए सेट किया गया हो, तो `--api-key` आवश्यक होता है। स्क्रिप्ट HTTP 429 पर एक बार पुनः प्रयास करती है ताकि एक बड़ा `--upload` रन डिफ़ॉल्ट दर सीमाओं के भीतर रहे।

**उदाहरण:**

```bash
# Generate data for 5 servers
pnpm generate-test-data --servers=5

# Generate data for 1 server with upload mode
pnpm generate-test-data --upload --servers=1

# Generate data for all 30 servers
pnpm generate-test-data --servers=30
```

स्क्रिप्ट Duplicati संस्करण **प्रति सर्वर** असाइन करती है (उस सर्वर के प्रत्येक बैकअप में समान रिपोर्ट स्ट्रिंग लिखी जाती है):

- **70–80% वर्तमान**: उपलब्ध होने पर `configurations.duplicati_versions` से नवीनतम कैश्ड स्थिर रिलीज़ का उपयोग करता है, अन्यथा एक पिन किया गया फ़ॉलबैक (`2.1.0.5_stable`)।
- **शेष पुराने**: पूरी तरह से पिछला स्थिर संस्करण ताकि डैशबोर्ड बैज पुराना (पीला) के रूप में तुलना करे।
- Direct-DB मोड पहले `configurations` को वाइप करता है, फिर संस्करण कैश को पुनर्स्थापित या सीड करता है ताकि वर्तमान/पुराना तुलना तुरंत काम करे।
- छोटी संख्या हमेशा 70–80% में नहीं आ सकती: `--servers=1` 100% वर्तमान है; `--servers=2` या `3` कम से कम एक पुराना सर्वर रखता है; `--servers=6` 5 वर्तमान (83%) है। `--servers=12` (`pnpm take-screenshots` द्वारा प्रयुक्त) **9 वर्तमान / 3 पुराने** है।
- जब `pnpm take-screenshots` बाद में डेटासेट को घटाकर तीन सर्वर कर देता है, तो यह सुरक्षित अतिदेय सर्वर और **कम से कम एक पुराने-संस्करण वाले सर्वर** को बनाए रखता है।

>[!CAUTION]
> यह स्क्रिप्ट डेटाबेस में सभी पिछले डेटा को हटा देती है और इसे जाँचें डेटा से बदल देती है।
> इस स्क्रिप्ट को चलाने से पहले अपने डेटाबेस का बैकअप लें (ताकि डेटा वापस मिल सके)।

## CSV एक्सपोर्ट मान्य करें {/* #validate-csv-export */}

```bash
pnpm validate-csv-export
```

यह स्क्रिप्ट CSV एक्सपोर्ट कार्यक्षमता को मान्य करती है। यह:
- CSV एक्सपोर्ट जनरेशन की जाँच करती है
- डेटा फ़ॉर्मैट और संरचना को सत्यापित करती है
- एक्सपोर्ट की गई फ़ाइलों में डेटा अखंडता की जाँच करती है

रिलीज़ से पहले यह सुनिश्चित करने के लिए उपयोगी है कि CSV एक्सपोर्ट ठीक से काम कर रहे हैं।

## NTFY सर्वर को अस्थायी रूप से ब्लॉक करें (जाँच के लिए) {/* #temporarily-block-ntfy-server-for-testing */}

```bash
sudo ./scripts/temporary_ntfy.sh_block.sh
```

यह स्क्रिप्ट नोटिफ़िकेशन पुनः प्रयास (retry) व्यवस्था की जाँच करने के लिए NTFY सर्वर (`ntfy.sh`) के आउटगोइंग नेटवर्क एक्सेस को अस्थायी रूप से ब्लॉक करती है। यह:
- NTFY सर्वर का आईपी पता रिज़ॉल्व करती है
- आउटगोइंग ट्रैफ़िक को ब्लॉक करने के लिए एक iptables नियम जोड़ती है
- 10 सेकंड के लिए ब्लॉक करती है (कॉन्फ़िगर करने योग्य)
- बाहर निकलने पर ब्लॉक नियम को स्वचालित रूप से हटा देती है
- इसके लिए रूट विशेषाधिकारों (sudo) की आवश्यकता होती है

>[!CAUTION]
> यह स्क्रिप्ट iptables नियमों को संशोधित करती है और इसके लिए रूट विशेषाधिकारों की आवश्यकता होती है। केवल नोटिफ़िकेशन पुनः प्रयास तंत्र की जाँच के लिए उपयोग करें।

## डेटाबेस माइग्रेशन टेस्टिंग {/* #database-migration-testing */}

परियोजना में पुराने संस्करणों से वर्तमान संस्करण में डेटाबेस माइग्रेशन की जाँच करने के लिए स्क्रिप्ट शामिल हैं। ये स्क्रिप्ट सुनिश्चित करती हैं कि डेटाबेस माइग्रेशन ठीक से काम करते हैं और डेटा अखंडता बनाए रखते हैं।

### माइग्रेशन जाँच डेटा जनरेट करें {/* #generate-migration-test-data */}

```bash
./scripts/generate-migration-test-data.sh
```

यह स्क्रिप्ट एप्लिकेशन के कई पुराने संस्करणों के लिए जाँच डेटाबेस जनरेट करती है। यह:

1. किसी भी मौजूदा Docker कंटेनर को **रोकती और हटाती** है
2. **प्रत्येक संस्करण के लिए** (v0.4.0, v0.5.0, v0.6.1, 0.7.27, 0.8.21):
   - मौजूदा डेटाबेस फ़ाइलों को हटाती है
   - एक संस्करण टैग फ़ाइल बनाती है
   - विशिष्ट संस्करण के साथ एक Docker कंटेनर शुरू करती है
   - कंटेनर के तैयार होने की प्रतीक्षा करती है
   - `pnpm generate-test-data` का उपयोग करके जाँच डेटा जनरेट करती है
   - जाँच डेटा के साथ UI का स्क्रीनशॉट लेती है
   - कंटेनर को रोकती और हटाती है
   - WAL फ़ाइलों को फ़्लश करती है और डेटाबेस स्कीमा को सहेजती है
   - डेटाबेस फ़ाइल को `scripts/migration_test_data/` में कॉपी करती है

**आवश्यकताएँ:**
- Docker स्थापित और कॉन्फ़िगर होना चाहिए
- Chromium (Playwright के माध्यम से) स्थापित होना चाहिए
- Docker संचालन के लिए Root/sudo एक्सेस
- Docker वॉल्यूम `duplistatus_data` मौजूद होना चाहिए

**आउटपुट:**
- डेटाबेस फ़ाइलें: `scripts/migration_test_data/backups_<VERSION>.db`
- स्कीमा फ़ाइलें: `scripts/migration_test_data/backups_<VERSION>.schema`
- स्क्रीनशॉट: `scripts/migration_test_data/duplistatus_test_data_<VERSION>.png`

**कॉन्फ़िगरेशन:**
- सर्वर की संख्या: `SERVERS` वैरिएबल के माध्यम से सेट करें (डिफ़ॉल्ट: 3)
- डेटा डायरेक्टरी: `/var/lib/docker/volumes/duplistatus_data/_data`
- पोर्ट: 9666 (Docker कंटेनर पोर्ट)

>[!CAUTION]
> इस स्क्रिप्ट के लिए Docker की आवश्यकता होती है और यह मौजूदा कंटेनरों को रोक/हटा देगी। इसके लिए Docker संचालन और फ़ाइल सिस्टम एक्सेस के लिए sudo एक्सेस की भी आवश्यकता होती है। यदि आपने पहले से नहीं किया है, तो Playwright Chromium ब्राउज़र स्थापित करने के लिए पहले `pnpm take-screenshots:install` चलाएँ।

>[!IMPORTANT]
> यह स्क्रिप्ट केवल एक बार चलाने के लिए थी, क्योंकि नए संस्करणों के लिए डेवलपर सीधे `scripts/migration_test_data/` डायरेक्टरी में डेटाबेस फ़ाइल और स्क्रीनशॉट कॉपी कर सकते हैं। विकास के दौरान, माइग्रेशन की जाँच करने के लिए बस `./scripts/test-migrations.sh` स्क्रिप्ट चलाएँ।

## Docker एंट्रीपॉइंट स्क्रिप्ट की जाँच करें {/* #test-docker-entrypoint-script */}

```bash
pnpm test-entrypoint
```

यह स्क्रिप्ट स्थानीय डेवलपमेंट में `docker-entrypoint.sh` के लिए एक टेस्ट रैपर प्रदान करती है। यह एंट्रीपॉइंट लॉगिंग कार्यक्षमता का परीक्षण करने के लिए परिवेश सेट करती है और यह सुनिश्चित करती है कि लॉग `data/logs/` में लिखे जाएँ ताकि एप्लिकेशन उन्हें एक्सेस कर सके।

**यह क्या करता है:**

1. **हमेशा एक नया संस्करण बनाता है**: परीक्षण से पहले एक नया बिल्ड बनाने के लिए स्वचालित रूप से `pnpm build-local` चलाता है (पहले मैन्युअल रूप से बिल्ड करने की आवश्यकता नहीं है)
2. **क्रॉन सर्विस बनाता है**: यह सुनिश्चित करता है कि क्रॉन सर्विस बिल्ड हो (`dist/cron-service.cjs`)
3. **Docker जैसी संरचना सेट करता है**: Docker परिवेश की नकल करने के लिए आवश्यक सिमलिनक्स और डायरेक्टरी संरचना बनाता है
4. **एंट्रीपॉइंट स्क्रिप्ट चलाता है**: उपयुक्त परिवेश चरों के साथ `docker-entrypoint.sh` को निष्पादित करता है
5. **सफ़ाई करता है**: बाहर निकलने पर अस्थायी फ़ाइलों को स्वचालित रूप से हटा देता है

**उपयोग:**

```bash
# Run the test (builds fresh version automatically)
pnpm test-entrypoint
```

**एनवायरनमेंट वैरियेबल्स:**
- `PORT=8666` - Next.js सर्वर के लिए पोर्ट (`start-local` से मेल खाता है)
- `CRON_PORT=8667` - cron सर्विस के लिए पोर्ट
- `VERSION` - स्वचालित रूप से `test-YYYYMMDD-HHMMSS` फ़ॉर्मेट पर सेट हो जाता है

**आउटपुट:**
- लॉग `data/logs/application.log` में लिखे जाते हैं (एप्लिकेशन द्वारा एक्सेस किए जा सकते हैं)
- कंसोल आउटपुट एंट्रीपॉइंट स्क्रिप्ट निष्पादन को दिखाता है
- रोकने और लॉग फ्लशिंग को जाँचने के लिए Ctrl+C दबाएँ

**आवश्यकताएँ:**
- स्क्रिप्ट को रिपॉजिटरी रूट डायरेक्टरी से चलाया जाना चाहिए (pnpm इसे स्वचालित रूप से संभालता है)
- स्क्रिप्ट स्वचालित रूप से सभी पूर्व-आवश्यकताओं (बिल्ड, cron सर्विस, आदि) को संभालती है

**उपयोग के मामले (Use Cases):**
- Docker परिनियोजन (डिप्लॉयमेंट) से पहले स्थानीय रूप से एंट्रीपॉइंट स्क्रिप्ट परिवर्तनों की जाँच करना
- लॉग रोटेशन और लॉगिंग कार्यक्षमता का सत्यापन करना
- ग्रेसफुल शटडाउन और सिग्नल हैंडलिंग की जाँच करना
- स्थानीय वातावरण में एंट्रीपॉइंट स्क्रिप्ट के व्यवहार को डीबग करना
