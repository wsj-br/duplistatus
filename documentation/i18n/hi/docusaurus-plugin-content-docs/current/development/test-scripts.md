# जांच स्क्रिप्ट {/* #test-scripts */}

प्रोजेक्ट में डेवलपमेंट और टेस्टिंग में सहायता के लिए कई टेस्ट स्क्रिप्ट शामिल हैं:

> [!NOTE]
> अतिदेय डीबगिंग, एसएमटीपी मैट्रिक्स टेस्टिंग और क्रॉन पोर्ट चेक के लिए लीगेसी रिपॉजिटरी-रूट `pnpm` सहायकों को हटा दिया गया। ऐप्लिकेशन यूआई (**सेटिंग्स → बैकअप निगरानी**), प्रमाणित HTTP APIs और क्रॉन सेवा के खिलाफ `curl` का उपयोग करें जैसा कि नीचे दस्तावेज़ीकृत है।

## टेस्ट डेटा उत्पन्न करें {/* #generate-test-data */}

```bash
pnpm generate-test-data --servers=N
```

यह स्क्रिप्ट कई सर्वर और बैकअप के लिए टेस्ट बैकअप डेटा उत्पन्न करती है।

`--servers=N` पैरामीटर **अनिवार्य** है और उत्पन्न करने के लिए सर्वर की संख्या निर्दिष्ट करता है (1-30)।

`/api/upload` को `--upload` विकल्प का उपयोग करके भेजने के लिए उपयोग करें

```bash
pnpm generate-test-data --servers=N --upload
pnpm generate-test-data --servers=N --upload --api-key=YOUR_UPLOAD_KEY
```

`--api-key` आवश्यक है जब सेटिंग्स → API कुंजियाँ कुंजियों की आवश्यकता रखने के लिए सेट हो। स्क्रिप्ट HTTP 429 पर एक बार पुन: प्रयास करती है ताकि बड़ा `--upload` डिफ़ॉल्ट दर सीमा के भीतर रहे।

**उदाहरण:**

```bash
# Generate data for 5 servers
pnpm generate-test-data --servers=5

# Generate data for 1 server with upload mode
pnpm generate-test-data --upload --servers=1

# Generate data for all 30 servers
pnpm generate-test-data --servers=30
```

स्क्रिप्ट Duplicati संस्करणों को **प्रति सर्वर** असाइन करती है (उस सर्वर के लिए प्रत्येक बैकअप में एक ही रिपोर्ट स्ट्रिंग लिखी जाती है):

- **70–80% वर्तमान**: उपलब्ध होने पर `configurations.duplicati_versions` से नवीनतम कैश्ड स्थिर रिलीज का उपयोग करता है, अन्यथा एक पिन किया गया फ़ॉलबैक (`2.1.0.5_stable`)।
- **शेष पुराना**: एक सख्त पिछला स्थिर संस्करण ताकि डैशबोर्ड बैज पुराने के रूप में तुलना करे (पीला)।
- डायरेक्ट-DB मोड पहले `configurations` को मिटा देता है, फिर संस्करण कैश को पुनर्स्थापित या सीड करता है ताकि वर्तमान/पुराना तुलना तुरंत काम करे।
- छोटी संख्या हमेशा 70–80% में नहीं आ सकती: `--servers=1` 100% वर्तमान है; `--servers=2` या `3` कम से कम एक पुराना सर्वर रखता है; `--servers=6` 5 वर्तमान (83%) है। `--servers=12` (`pnpm take-screenshots` द्वारा उपयोग किया गया) **9 वर्तमान / 3 पुराना** है।
- जब `pnpm take-screenshots` बाद में डेटासेट को तीन सर्वर तक कम करता है, तो यह संरक्षित अतिदेय सर्वर और **कम से कम एक पुराने-संस्करण वाला सर्वर** रखता है।

>[!CAUTION]
> यह स्क्रिप्ट डेटाबेस में सभी पिछला डेटा को हटा देती है और इसे टेस्ट डेटा से बदल देती है।
> इस स्क्रिप्ट को चलाने से पहले अपने डेटाबेस का बैकअप लें।

## CSV निर्यात का सत्यापन करें {/* #validate-csv-export */}

```bash
pnpm validate-csv-export
```

यह स्क्रिप्ट CSV निर्यात कार्यक्षमता का सत्यापन करती है। यह:
- CSV निर्यात जनरेशन का परीक्षण करता है
- डेटा प्रारूप और संरचना को सत्यापित करता है
- निर्यातित फ़ाइलों में डेटा अखंडता की जाँच करता है

रिलीज़ से पहले सुनिश्चित करने के लिए उपयोगी कि CSV निर्यात सही ढंग से काम करता है।

## NTFY सर्वर को अस्थायी रूप से ब्लॉक करें (परीक्षण के लिए) {/* #temporarily-block-ntfy-server-for-testing */}

```bash
sudo ./scripts/temporary_ntfy.sh_block.sh
```

यह स्क्रिप्ट नोटिफिकेशन पुन: प्रयास तंत्र का परीक्षण करने के लिए NTFY सर्वर (`ntfy.sh`) पर आउटगोइंग नेटवर्क एक्सेस को अस्थायी रूप से ब्लॉक करती है। यह:
- NTFY सर्वर का आईपी पता समाधान करता है
- आउटगोइंग ट्रैफ़िक को ब्लॉक करने के लिए एक iptables नियम जोड़ता है
- 10 सेकंड के लिए ब्लॉक करता है (कॉन्फ़िगर करने योग्य)
- बाहर निकलने पर स्वचालित रूप से ब्लॉक नियम निकालता है
- रूट विशेषाधिकारों (sudo) की आवश्यकता है

>[!CAUTION]
> यह स्क्रिप्ट iptables नियमों को संशोधित करती है और रूट विशेषाधिकारों की आवश्यकता है। केवल नोटिफिकेशन पुन: प्रयास तंत्र का परीक्षण करने के लिए उपयोग करें।

## डेटाबेस माइग्रेशन परीक्षण {/* #database-migration-testing */}

पुराने संस्करणों से वर्तमान संस्करण पर डेटाबेस माइग्रेशन का परीक्षण करने के लिए प्रोजेक्ट में स्क्रिप्ट शामिल हैं। ये स्क्रिप्ट सुनिश्चित करती हैं कि डेटाबेस माइग्रेशन सही ढंग से काम करता है और डेटा अखंडता को बनाए रखता है।

### माइग्रेशन परीक्षण डेटा उत्पन्न करें {/* #generate-migration-test-data */}

```bash
./scripts/generate-migration-test-data.sh
```

यह स्क्रिप्ट एप्लिकेशन के कई ऐतिहासिक संस्करणों के लिए परीक्षण डेटाबेस उत्पन्न करती है। यह:

1. **कोई मौजूदा डॉकर कंटेनर को रोकता है और हटा देता है**
2. **प्रत्येक संस्करण के लिए** (v0.4.0, v0.5.0, v0.6.1, 0.7.27, 0.8.21):
   - मौजूदा डेटाबेस फ़ाइलों को हटा देता है
   - एक संस्करण टैग फ़ाइल बनाता है
   - विशिष्ट संस्करण के साथ एक डॉकर कंटेनर शुरू करता है
   - कंटेनर के तैयार होने की प्रतीक्षा करता है
   - `pnpm generate-test-data` का उपयोग करके परीक्षण डेटा उत्पन्न करता है
   - परीक्षण डेटा के साथ यूआई का एक स्क्रीनशॉट लेता है
   - कंटेनर को रोकता है और हटा देता है
   - WAL फ़ाइलों को फ्लश करता है और डेटाबेस स्कीमा सहेजता है
   - डेटाबेस फ़ाइल को `scripts/migration_test_data/` में कॉपी करता है

**आवश्यकताएँ:**
- डॉकर स्थापित और कॉन्फ़िगर किया जाना चाहिए
- क्रोमियम (प्लेव्राइट के माध्यम से) स्थापित किया जाना चाहिए
- डॉकर ऑपरेशन के लिए रूट/सुडो एक्सेस
- डॉकर वॉल्यूम `duplistatus_data` मौजूद होना चाहिए

**आउटपुट:**
- डेटाबेस फ़ाइलें: `scripts/migration_test_data/backups_<VERSION>.db`
- स्कीमा फ़ाइलें: `scripts/migration_test_data/backups_<VERSION>.schema`
- स्क्रीनशॉट: `scripts/migration_test_data/duplistatus_test_data_<VERSION>.png`

**कॉन्फ़िगरेशन:**
- सर्वर की संख्या: `SERVERS` चर के माध्यम से सेट करें (डिफ़ॉल्ट: 3)
- डेटा निर्देशिका: `/var/lib/docker/volumes/duplistatus_data/_data`
- पोर्ट: 9666 (डॉकर कंटेनर पोर्ट)

>[!CAUTION]
> इस स्क्रिप्ट को डॉकर की आवश्यकता है और मौजूदा कंटेनर को रोकेगा/हटा देगा। यह डॉकर ऑपरेशन और फ़ाइल सिस्टम एक्सेस के लिए सुडो एक्सेस की भी आवश्यकता है। यदि आपने पहले से ऐसा नहीं किया है तो प्लेव्राइट क्रोमियम ब्राउज़र स्थापित करने के लिए `pnpm take-screenshots:install` पहले चलाएँ।

>[!IMPORTANT]
> इस स्क्रिप्ट को केवल एक बार चलाना था, क्योंकि नए संस्करणों में डेवलपर सीधे डेटाबेस फ़ाइल और स्क्रीनशॉट को `scripts/migration_test_data/` निर्देशिका में कॉपी कर सकता है। विकास के दौरान, माइग्रेशन का परीक्षण करने के लिए केवल `./scripts/test-migrations.sh` स्क्रिप्ट चलाएँ।

## परीक्षण डॉकर एंट्रीपॉइंट स्क्रिप्ट {/* #test-docker-entrypoint-script */}

```bash
pnpm test-entrypoint
```

यह स्क्रिप्ट स्थानीय विकास में `docker-entrypoint.sh` के लिए एक परीक्षण व्रापर प्रदान करती है। यह एंट्रीपॉइंट लॉगिंग कार्यक्षमता का परीक्षण करने के लिए पर्यावरण सेट करती है और सुनिश्चित करती है कि लॉग `data/logs/` में लिखे जाएं ताकि एप्लिकेशन उन तक पहुँच सके।

**यह क्या करता है:**

1. **हमेशा एक ताज़ा संस्करण बनाता है**: परीक्षण से पहले एक ताज़ा बिल्ड बनाने के लिए स्वचालित रूप से `pnpm build-local` चलाता है (पहले मैन्यल रूप से बिल्ड करने की आवश्यकता नहीं है)
2. **क्रॉन सेवा बनाता है**: सुनिश्चित करता है कि क्रॉन सेवा बनाई गई है (`dist/cron-service.cjs`)
3. **डॉकर जैसी संरचना सेट करता है**: डॉकर वातावरण को नकल करने के लिए आवश्यक सिम्लिंक्स और निर्देशिका संरचना बनाता है
4. **एंट्रीपॉइंट स्क्रिप्ट चलाता है**: उचित पर्यावरण चर के साथ `docker-entrypoint.sh` निष्पादित करता है
5. **सफाई करता है**: बाहर निकलते समय स्वचालित रूप से अस्थायी फ़ाइलें हटा देता है

**उपयोग:**

```bash
# Run the test (builds fresh version automatically)
pnpm test-entrypoint
```

**पर्यावरण चर:**
- `PORT=8666` - नेक्स्ट.जेएस सर्वर के लिए पोर्ट (`start-local` से मेल खाता है)
- `CRON_PORT=8667` - क्रॉन सेवा के लिए पोर्ट
- `VERSION` - स्वचालित रूप से `test-YYYYMMDD-HHMMSS` प्रारूप पर सेट किया गया

**आउटपुट:**
- लॉग `data/logs/application.log` में लिखे जाते हैं (एप्लिकेशन द्वारा पहुँच योग्य)
- कंसोल आउटपुट एंट्रीपॉइंट स्क्रिप्ट निष्पादन दिखाता है
- स्टॉप करने और लॉग फ्लशिंग का परीक्षण करने के लिए Ctrl+C दबाएँ

**आवश्यकताएँ:**
- स्क्रिप्ट को रिपॉजिटरी रूट निर्देशिका से चलाना चाहिए (पीएनपीएम इसे स्वचालित रूप से संभालता है)
- स्क्रिप्ट स्वचालित रूप से सभी पूर्वापेक्षाओं को संभालती है (बिल्ड, क्रॉन सेवा, आदि)

**उपयोग के मामले:**
- डॉकर डिप्लॉयमेंट से पहले स्थानीय रूप से एंट्रीपॉइंट स्क्रिप्ट परिवर्तनों का परीक्षण करना
- लॉग रोटेशन और लॉगिंग कार्यक्षमता को सत्यापित करना
- ग्रेसफुल शटडाउन और सिग्नल हैंडलिंग का परीक्षण करना
- स्थानीय वातावरण में एंट्रीपॉइंट स्क्रिप्ट व्यवहार को डीबग करना
