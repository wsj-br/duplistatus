# Version 0.9.x {/* #version-09x */}

## Aperçu {/* #overview */}

La version 0.9.x est une version majeure qui introduit un système complet de **Contrôle d'accès utilisateur et de sécurité**. Cette version transforme **duplistatus** d'une application en accès libre en un système sécurisé multi-utilisateurs avec contrôle d'accès basé sur les rôles, journalisation d'audit complète et fonctionnalités de sécurité de niveau entreprise. Toutes les fonctionnalités existantes sont désormais protégées par authentification, garantissant que seuls les utilisateurs autorisés peuvent accéder et gérer la surveillance des sauvegardes.

## Modifications incompatibles {/* #breaking-changes */}

### Authentification requise {/* #authentication-required */}

- **Toutes les pages nécessitent désormais une authentification** - Les utilisateurs doivent se connecter pour accéder à l'application
- Le **compte administrateur par défaut** est créé automatiquement :
  - Nom d'utilisateur : `admin`
  - Mot de passe : `Duplistatus09` (doit être modifié lors de la première connexion)
- **Les sessions existantes sont invalidées** - Tous les utilisateurs doivent se connecter après la mise à niveau
- **Les points de terminaison de l'API nécessitent désormais une authentification** - Les intégrations externes doivent inclure des cookies de session ou utiliser des requêtes authentifiées

:::warning
**Tous les utilisateurs doivent se connecter après la mise à jour vers la version 0.9.x.** Les identifiants administrateur par défaut sont admin/Duplistatus09. Modifiez le mot de passe immédiatement après la première connexion.
:::

### Migration du schéma de base de données {/* #database-schema-migration */}

- **Migration automatique de v3.1 à v4.0** pour les installations existantes
- **Nouvelles tables ajoutées** : `users`, `sessions`, `audit_log`
- **Sauvegarde de la base de données créée automatiquement** avant la migration
- **Les nouvelles installations** commencent directement avec le schéma v4.0 (aucune migration nécessaire)

## Nouvelles fonctionnalités {/* #new-features */}

### Système de contrôle d'accès utilisateur et de sécurité {/* #user-access-control--security-system */}

#### Système d'authentification {/* #authentication-system */}

- **Fonctionnalité de connexion/déconnexion utilisateur** avec gestion sécurisée des sessions
- **Authentification par mot de passe** avec hachage bcrypt (facteur de coût 12)
- **Mécanisme de verrouillage de compte** (5 tentatives échouées, verrouillage de 15 minutes)
- **Changement de mot de passe forcé** à la première connexion
- **Application de la politique de mot de passe** :
  - Minimum 8 caractères
  - Au moins une lettre majuscule
  - Au moins une lettre minuscule
  - Au moins un chiffre
  - Caractères spéciaux facultatifs
- **Fonctionnalité « Se souvenir de moi »** avec persistance du nom d'utilisateur dans le stockage local
- **Authentification basée sur les sessions** avec sessions gérées par la base de données (remplace la mémoire)
- **Protection CSRF** intégrée à l'authentification
- **Cookies HTTP uniquement** pour la sécurité des sessions
- **Suivi des adresses IP et des agents utilisateurs** pour la surveillance de sécurité

#### Gestion des utilisateurs (Admin uniquement) {/* #user-management-admin-only */}

- **Création d'utilisateur** avec génération automatique de mot de passe temporaire
- **Liste des utilisateurs** avec recherche, pagination et filtrage
- **Édition d'utilisateur** (nom d'utilisateur, statut administrateur, exigence de changement de mot de passe)
- **Fonctionnalité de réinitialisation du mot de passe** avec affichage du mot de passe temporaire
- **Suppression d'utilisateur** avec protections (empêche la suppression du dernier administrateur)
- **Contrôle d'accès basé sur les rôles** (rôles Admin/Utilisateur)
- **Indicateurs de statut** (Actif, Verrouillé, Doit changer de mot de passe)
- **Suivi et affichage de la dernière connexion**

#### Système de journalisation d'audit {/* #audit-logging-system */}

- **Piste d'audit complète** pour tous les changements système et actions des utilisateurs
- **Visionneuse de journaux d'audit** avec filtrage avancé :
  - Filtrage par plage de dates
  - Filtrage par utilisateur
  - Filtrage par action
  - Filtrage par catégorie
  - Filtrage par statut
- **Fonctionnalité d'exportation** (formats CSV et JSON)
- **Statistiques** et analyses des journaux d'audit
- **Période de rétention configurable** (30-365 jours, valeur par défaut : 90 jours)
- **Tâche planifiée de nettoyage automatique** (s'exécute quotidiennement à 2h UTC)
- **API de nettoyage manuel** avec prise en charge de l'exécution test
- **Journalisation d'audit pour** :
  - Événements d'authentification (connexion, déconnexion, changement de mot de passe, verrouillage de compte)
  - Opérations de gestion des utilisateurs (création, mise à jour, suppression, réinitialisation de mot de passe)
  - Modifications de configuration (e-mail, NTFY, modèles, tolérance des retards, paramètres de sauvegarde)
  - Opérations de sauvegarde (collecte, suppression, nettoyage)
  - Gestion des serveurs (ajout, mise à jour, suppression)
  - Opérations système (migrations, nettoyage, notifications)

### Refonte de la page Paramètres {/* #settings-page-redesign */}

### Améliorations de l'interface utilisateur {/* #user-interface-enhancements */}

- **Page de connexion autonome** avec design moderne
- **Case à cocher « Se souvenir de moi »** sur le formulaire de connexion pour la persistance du nom d'utilisateur
- **Boutons Afficher/Masquer le mot de passe** sur les formulaires de connexion et de changement de mot de passe
- **Modal Changer de mot de passe** avec liste de contrôle de validation en temps réel

- **Validation du jeton CSRF** pour toutes les opérations modifiant l'état
- **Outil CLI de récupération administrateur** pour la réinitialisation du mot de passe en cas de verrouillage

## 🚀 Notes de migration {/* #-migration-notes */}

### À partir de la version 0.8.x {/* #from-version-08x */}

Cette version introduit l'authentification et nécessite que tous les utilisateurs se connectent. Lors de la mise à niveau à partir de la version 0.8.x :

1. **Migration automatique de la base de données** : L'application migrera automatiquement votre schéma de base de données de la version v3.1 à v4.0
2. **Sauvegarde de la base de données** : Une sauvegarde automatique est créée avant la migration
3. **Compte administrateur par défaut** : Un compte administrateur par défaut est créé :
   - Nom d'utilisateur : `admin`
   - Mot de passe : `Duplistatus09`
   - **Vous devez modifier ce mot de passe lors de la première connexion**
4. **Invalidation des sessions** : Toutes les sessions existantes sont invalidées
5. **Connexion utilisateur requise** : Tous les utilisateurs doivent se connecter après la mise à niveau
6. **Authentification de l'API** : Les intégrations externes doivent être mises à jour pour inclure l'authentification

### Considérations de sécurité {/* #security-considerations */}

- **Changer le mot de passe par défaut** : Changez le mot de passe admin par défaut immédiatement après la première connexion
- **Créer des comptes utilisateur** : Créez des comptes utilisateur individuels pour chaque personne qui a besoin d'accès
- **Examiner les journaux d'audit** : Vérifiez régulièrement les journaux d'audit pour la surveillance de la sécurité
- **Configurer la conservation** : Définissez une période de conservation appropriée du journal d'audit en fonction de vos exigences de conformité
- **Sauvegarder la clé maître** : Si vous effectuez une mise à niveau à partir de 0.8.x, assurez-vous que le fichier `.duplistatus.key` est sauvegardé

### Étapes de première connexion {/* #first-login-steps */}

1. **Connectez-vous** avec les identifiants par défaut (`admin` / `Duplistatus09`)
2. **Changez le mot de passe** quand vous y êtes invité (forcé à la première connexion)
3. **Créez des comptes utilisateur** pour les autres utilisateurs (Paramètres → Utilisateurs)
4. **Configurez la conservation du journal d'audit** si nécessaire (Paramètres → Journal d'audit)
5. **Examinez les journaux d'audit** pour vérifier que le système fonctionne correctement

## Points de terminaison API {/* #api-endpoints */}

### Points de terminaison d'authentification {/* #authentication-endpoints */}

- `POST /api/auth/login` - Authentification utilisateur
- `POST /api/auth/logout` - Terminaison de session
- `GET /api/auth/me` - Informations sur l'utilisateur actuel
- `POST /api/auth/change-password` - Changement de mot de passe

### Points de terminaison de gestion des utilisateurs (Admin uniquement) {/* #user-management-endpoints-admin-only */}

- `GET /api/users` - Lister les utilisateurs
- `POST /api/users` - Créer un utilisateur
- `PATCH /api/users/{id}` - Mettre à jour l'utilisateur
- `DELETE /api/users/{id}` - Supprimer l'utilisateur

### Points de terminaison du journal d'audit {/* #audit-log-endpoints */}

- `GET /api/audit-log` - Interroger les journaux d'audit
- `GET /api/audit-log/download` - Exporter les journaux d'audit
- `GET /api/audit-log/stats` - Statistiques du journal d'audit
- `POST /api/audit-log/cleanup` - Nettoyage manuel (admin uniquement)
- `GET /api/audit-log/retention` - Obtenir le paramètre de rétention
- `PATCH /api/audit-log/retention` - Mettre à jour la rétention (admin uniquement)

:::note
Tous les points de terminaison API nécessitent maintenant une authentification. Consultez la [Référence API](../api-reference/authentication-security.md) pour plus de détails sur l'authentification.
:::
