# Version 1.1.x {/* #version-11x */}

## Aperçu {/* #overview */}

La version 1.1.x est une version mineure qui corrige des problèmes critiques liés à la détection des sauvegardes en retard, améliore la compatibilité des conteneurs Podman et introduit des améliorations d'architecture des conteneurs. Cette version se concentre sur la correction de la précision de la détection des sauvegardes en retard et la résolution des problèmes de réseau dans les environnements Podman.

## Nouvelles fonctionnalités {/* #new-features */}

### Améliorations de l'interface utilisateur {/* #user-interface-enhancements */}

- **Menu contextuel par clic droit sur le bouton d'actualisation automatique** - Un clic droit sur le bouton d'actualisation automatique dans la barre d'outils de l'application ouvre la page des paramètres d'affichage pour un accès rapide aux préférences d'affichage
- **Amélioration de la fenêtre modale de collecte des sauvegardes** - Le champ de mot de passe indique maintenant clairement "(à remplir uniquement si le mot de passe a changé)" lorsqu'un serveur est sélectionné, ce qui rend plus clair quand le champ est nécessaire

### Améliorations de la documentation {/* #documentation-improvements */}

- **Migration de l'hébergement de la documentation** - La documentation a été déplacée de l'image du conteneur Docker vers GitHub Pages à l'adresse https://wsj-br.github.io/duplistatus/user-guide/overview pour une meilleure accessibilité et des mises à jour plus faciles
- Le lien du guide de l'utilisateur dans l'en-tête de l'application pointe maintenant vers le site de documentation externe

## 🐛 Correctifs de bogues {/* #-bug-fixes */}

### Critique : Détection des sauvegardes en retard - Réimplémentation complète {/* #critical-overdue-backup-detection---complete-reimplementation */}

- **Correction de la détection des sauvegardes en retard** - Système de détection des sauvegardes en retard complètement réimplémenté avec un nouvel algorithme qui suit correctement les dates de sauvegarde attendues :
  - L'algorithme garantit que les sauvegardes manuelles ne changent pas les heures de sauvegarde planifiées (par exemple, une sauvegarde manuelle à 22h ne changera pas une planification à 14h)
  - Correction de la colonne "Prochaine exécution" dans les paramètres de surveillance des sauvegardes affichant des dates incorrectes
  - Les paramètres de sauvegarde sont maintenant immédiatement mis à jour après la réception des sauvegardes via `/api/upload` ou `/api/backups/collect`
  - Pour les nouveaux serveurs sans synchronisation Duplicati, utilise la première sauvegarde comme référence pour l'heure de la journée
  - Pour plus de détails, voir la documentation sur l'[Algorithme de détection des sauvegardes en retard](https://github.com/wsj-br/duplistatus/blob/main/dev/OVERDUE_DETECTION_ALGORITHM.md)

### Corrections des conteneurs Podman {/* #podman-container-fixes */}

- **Correction du réseau des pods Podman** - Résolution du problème empêchant l'accès externe à l'application lors de l'exécution dans des pods Podman. Le serveur se lie maintenant correctement à toutes les interfaces (`0.0.0.0:9666`) dans les modes pod Podman et conteneur autonome
- **Correction de la résolution DNS pour les noms d'hôtes Tailscale** - Résolution des problèmes de résolution DNS dans les conteneurs Podman qui empêchaient la connexion aux noms d'hôtes Tailscale ou aux serveurs DNS personnalisés. Mise à jour de la documentation d'installation avec des instructions.

### Corrections de la configuration des e-mails {/* #email-configuration-fixes */}

- **Correction de la gestion des noms d'utilisateur/mots de passe SMTP vides** - Résolution du problème où le vidage des champs de nom d'utilisateur ou de mot de passe dans la configuration des e-mails stockait toujours des valeurs chiffrées dans la base de données. Les champs vides sont maintenant correctement stockés comme des chaînes vides et peuvent être effacés correctement

### Améliorations du système {/* #system-improvements */}

- **Réduction de la journalisation console** - AuditLogger ne journalise plus que les tentatives de connexion échouées dans la console ; toutes les autres entrées d'audit sont écrites uniquement dans la base de données

## 🚀 Notes de migration {/* #-migration-notes */}

### Depuis la version 1.0.x {/* #from-version-10x */}

Lors de la mise à niveau vers la version 1.1.0 :

1. **Changement de l'emplacement de la documentation** - La documentation est maintenant hébergée sur GitHub Pages au lieu d'être incluse dans le conteneur Docker. Le lien du guide de l'utilisateur dans l'en-tête de l'application pointe maintenant vers le site de documentation externe

2. **Configuration des conteneurs Podman** - Si vous utilisez des pods Podman, assurez-vous que la configuration DNS est définie au niveau du pod en utilisant les indicateurs `--dns` et `--dns-search`. L'application fonctionne maintenant correctement dans les pods Podman et les conteneurs autonomes

3. **Détection des sauvegardes en retard** - Le système de détection des sauvegardes en retard a été complètement réimplémenté avec un nouvel algorithme qui préserve l'heure de la journée de la planification. Les configurations existantes de surveillance des sauvegardes continueront à fonctionner, mais vous pourriez remarquer des dates "Prochaine exécution" plus précises dans les paramètres de surveillance des sauvegardes. Le nouvel algorithme garantit que les sauvegardes manuelles ne décalent pas les heures de sauvegarde planifiées

4. **Aucune migration de base de données requise** - Cette version ne nécessite aucun changement de schéma de base de données
