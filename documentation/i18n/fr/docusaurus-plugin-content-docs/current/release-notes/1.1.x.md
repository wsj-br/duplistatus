# Version 1.1.x {/* #version-11x */}

## Aperçu {/* #overview */}

La version 1.1.x est une version mineure qui résout les problèmes critiques de détection des sauvegardes en retard, améliore la compatibilité des conteneurs Podman et introduit des améliorations de l'architecture des conteneurs. Cette version se concentre sur la correction de la précision de la détection des sauvegardes en retard et la résolution des problèmes de réseau dans les environnements Podman.

## Nouvelles fonctionnalités {/* #new-features */}

### Améliorations de l'interface utilisateur {/* #user-interface-enhancements */}

- **Menu contextuel au clic droit sur le bouton d'actualisation automatique** - Un clic droit sur le bouton d'actualisation automatique dans la barre d'outils de l'application ouvre la page Paramètres d'affichage pour un accès rapide aux préférences d'affichage
- **Fenêtre modale Collecter les sauvegardes améliorée** - L'étiquette du champ Mot de passe indique maintenant clairement « (à remplir uniquement si le mot de passe a changé) » quand un serveur est sélectionné, ce qui rend plus clair quand le champ est nécessaire

### Améliorations de la documentation {/* #documentation-improvements */}

- **Migration de l'hébergement de la documentation** - La documentation a été déplacée de l'image du conteneur Docker vers GitHub Pages à https://wsj-br.github.io/duplistatus/user-guide/overview pour une meilleure accessibilité et des mises à jour plus faciles
- Le lien Guide de l'utilisateur dans l'en-tête de l'application pointe maintenant vers le site de documentation externe

## 🐛 Corrections de bogues {/* #-bug-fixes */}

### Critique : Détection des sauvegardes en retard - Réimplémentation complète {/* #critical-overdue-backup-detection---complete-reimplementation */}

- **Détection des sauvegardes en retard corrigée** - Système de détection des sauvegardes en retard complètement réimplémenté avec un nouvel algorithme qui suit correctement les dates de sauvegarde attendues :
  - L'algorithme garantit que les sauvegardes manuelles ne modifient pas les heures de sauvegarde programmées (par exemple, une sauvegarde manuelle à 22h ne modifiera pas une programmation à 14h)
  - Correction de la colonne « Prochaine exécution » dans les paramètres de surveillance des sauvegardes affichant des dates incorrectes
  - Les paramètres de sauvegarde sont maintenant immédiatement mis à jour après la réception des sauvegardes via `/api/upload` ou `/api/backups/collect`
  - Pour les nouveaux serveurs sans synchronisation Duplicati, utilise l'heure du jour de la première sauvegarde comme référence de programmation
  - Pour plus de détails, consultez la documentation [Algorithme de détection des retards](https://github.com/wsj-br/duplistatus/blob/main/dev/OVERDUE_DETECTION_ALGORITHM.md)

### Corrections des conteneurs Podman {/* #podman-container-fixes */}

- **Réseau des pods Podman corrigé** - Résolution du problème empêchant l'accès externe à l'application lors de l'exécution dans les pods Podman. Le serveur se lie maintenant correctement à toutes les interfaces (`0.0.0.0:9666`) en mode pod Podman et conteneur autonome
- **Résolution DNS corrigée pour les noms d'hôtes Tailscale** - Résolution des problèmes de résolution DNS dans les conteneurs Podman qui empêchaient la connexion aux noms d'hôtes Tailscale ou aux serveurs DNS personnalisés. Documentation d'installation mise à jour avec les instructions.

### Corrections de la configuration des e-mails {/* #email-configuration-fixes */}

- **Gestion corrigée du nom d'utilisateur/mot de passe SMTP vides** - Résolution du problème où l'effacement des champs nom d'utilisateur ou mot de passe dans la configuration des e-mails stockait toujours des valeurs chiffrées dans la base de données. Les champs vides sont maintenant correctement stockés sous forme de chaînes vides et peuvent être effacés correctement

### Améliorations du système {/* #system-improvements */}

- **Réduction de la journalisation de la console** - AuditLogger enregistre maintenant uniquement les tentatives de connexion échouées dans la console ; toutes les autres entrées d'audit sont écrites uniquement dans la base de données

## 🚀 Notes de migration {/* #-migration-notes */}

### À partir de la version 1.0.x {/* #from-version-10x */}

Lors de la mise à niveau vers la version 1.1.0 :

1. **Changement d'emplacement de la documentation** - La documentation est maintenant hébergée sur GitHub Pages au lieu d'être incluse dans le conteneur Docker. Le lien Guide de l'utilisateur dans l'en-tête de l'application pointe maintenant vers le site de documentation externe

2. **Configuration du conteneur Podman** - Si vous utilisez des pods Podman, assurez-vous que la configuration DNS est définie au niveau du pod à l'aide des drapeaux `--dns` et `--dns-search`. L'application fonctionne maintenant correctement dans les pods Podman et les conteneurs autonomes

3. **Détection des sauvegardes en retard** - Le système de détection des sauvegardes en retard a été complètement réimplémenté avec un nouvel algorithme qui préserve l'heure du jour de la programmation. Les configurations de surveillance des sauvegardes existantes continueront à fonctionner, mais vous remarquerez peut-être des dates « Prochaine exécution » plus précises dans les paramètres de surveillance des sauvegardes. Le nouvel algorithme garantit que les sauvegardes manuelles ne décalent pas les heures de sauvegarde programmées

4. **Aucune migration de base de données requise** - Cette version ne nécessite aucune modification du schéma de base de données
