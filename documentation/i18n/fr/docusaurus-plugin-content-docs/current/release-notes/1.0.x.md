# Version 1.0.x {/* #version-10x */}

## Aperçu {/* #overview */}

La version 1.0.x est une version de fonctionnalités qui introduit des améliorations significatives à la configuration de la messagerie, aux capacités de gestion des serveurs et aux outils de maintenance de la base de données. Cette version se concentre sur l'amélioration de la fiabilité des notifications par courriel, l'expansion des options de connexion SMTP et la fourniture de meilleurs outils pour gérer les serveurs et l'intégrité de la base de données.

## Nouvelles fonctionnalités {/* #new-features */}

### Améliorations de la gestion des serveurs {/* #server-management-enhancements */}

- **Fonctionnalité de changement de mot de passe du serveur** - Les utilisateurs peuvent maintenant modifier les mots de passe du serveur directement à partir de la page de détails du serveur en cliquant sur l'icône de clé
- **Détection et fusion des serveurs en double** - Nouvelle fonction dans le formulaire de maintenance de la base de données pour détecter les serveurs en double et les fusionner en une seule entrée de serveur

### Améliorations de la journalisation d'audit {/* #audit-logging-enhancements */}

- **Journalisation d'audit du téléchargement de sauvegarde** - Tous les téléchargements de journaux de sauvegarde via le point de terminaison `/api/upload` sont maintenant automatiquement enregistrés dans le journal d'audit. Chaque entrée inclut les détails de la sauvegarde (ID du serveur, nom du serveur, nom de la sauvegarde, statut, date, durée, nombre de fichiers, tailles, avertissements et erreurs) ainsi que l'adresse IP du client et les informations de l'agent utilisateur à des fins de suivi et de sécurité

### Améliorations de la configuration de la messagerie {/* #email-configuration-enhancements */}

- **Avis de configuration incomplète** - Alerte visuelle affichée lorsque les paramètres de messagerie ne sont pas correctement configurés
- **Indicateurs d'état du service** - Étiquettes « (désactivé) » affichées sur les cases à cocher des notifications lorsque les services de messagerie ne sont pas configurés
- **Informations d'expéditeur personnalisables** :
  - Champ `Sender Name` pour personnaliser le nom d'affichage figurant comme expéditeur dans les notifications par e-mail
  - Champ `From Address` pour spécifier l'adresse e-mail figurant comme expéditeur
  - Remarque : Certains fournisseurs de messagerie remplaceront le `From Address` par le `SMTP Server Username`
- **Activation/désactivation de l'authentification SMTP** - Option permettant d'activer ou désactiver l'authentification SMTP, prenant en charge les serveurs qui ne nécessitent pas d'authentification
- **Validation du format de l'e-mail** - Validation des champs d'adresse du destinataire et de l'expéditeur afin de garantir un format d'adresse e-mail correct
- **E-mail de test amélioré** - L'e-mail de test affiche désormais des détails complets sur la connexion, notamment le nom d'hôte du serveur SMTP, le port, le type de connexion, l'état de l'authentification, le nom d'utilisateur (le cas échéant), l'e-mail du destinataire, l'adresse de l'expéditeur, le nom de l'expéditeur et l'horodatage du test

### Support du type de connexion SMTP {/* #smtp-connection-type-support */}

- **Plusieurs types de connexion** - Prise en charge de trois types de connexion :
  - `Plain SMTP` (pas de chiffrement) sur le port 25
  - `STARTTLS` (mise à niveau vers TLS) sur le port 587
  - `Direct SSL/TLS` (chiffré dès le début) sur le port 465
- **Type de connexion par défaut** - Modifié en `Direct SSL/TLS` pour les nouvelles configurations
- **Exigences spécifiques à la connexion** - Le champ `From Address` est requis pour les connexions `Plain SMTP` afin de garantir une identification correcte de l'expéditeur de l'e-mail et la conformité avec la norme RFC 5322

## 🐛 Corrections de bogues {/* #-bug-fixes */}

### Corrections du système de messagerie {/* #email-system-fixes */}

- **En-tête `From` manquant corrigé** - Résolution des erreurs de conformité RFC 5322 en s'assurant que tous les messages e-mail incluent les en-têtes `From` appropriés
- **Chiffrement de la messagerie corrigé pour STARTTLS** - Gestion du chiffrement corrigée pour les connexions `STARTTLS` (port 587)
- **Connexions SMTP simple corrigées** - Résolution des erreurs de négociation TLS qui causaient l'échec des connexions `Plain SMTP`
- **Perte de configuration non enregistrée corrigée** - Prévention de l'effacement de la configuration de messagerie non enregistrée lors du changement de mot de passe
- **Configuration SMTP obsolète corrigée** - Résolution du problème où le point de terminaison d'e-mail de test utilisait une configuration SMTP obsolète

### Corrections de l'interface utilisateur {/* #user-interface-fixes */}

- **Basculement de visibilité du mot de passe corrigé** - Comportement corrigé de la fonction d'affichage du mot de passe dans le formulaire de changement de mot de passe ; cliquer sur l'icône d'œil affiche maintenant le mot de passe pour les deux champs de mot de passe simultanément

### Corrections du système {/* #system-fixes */}

- **Journalisation du point d'entrée Docker corrigée** - Résolution du problème où le script de point d'entrée Docker supprimait les messages de journal
- **Calcul de la date de prochaine exécution corrigé** - Recalcul automatique ajouté de la date `Next Run` après la collecte des journaux de sauvegarde, en s'assurant que la date est mise à jour correctement après la collecte des journaux

## 🚀 Notes de migration {/* #-migration-notes */}

### À partir de la version 0.9.x {/* #from-version-09x */}

Cette version inclut des améliorations de la configuration de la messagerie et de la gestion des serveurs. Lors de la mise à niveau à partir de la version 0.9.x :

1. **Aucune migration de base de données requise** - Cette version ne nécessite aucune modification du schéma de base de données
2. **Mises à jour de la configuration de messagerie** - Les configurations de messagerie existantes continueront de fonctionner, mais vous pouvez les revoir et les mettre à jour pour profiter des nouvelles fonctionnalités :
   - Envisagez de définir un `Sender Name` personnalisé pour une meilleure identification des e-mails
   - Vérifiez que votre `From Address` est correctement défini, surtout si vous utilisez des connexions `Plain SMTP`
   - Testez votre configuration de messagerie à l'aide de la fonction d'e-mail de test améliorée
3. **Type de connexion par défaut** - Les nouvelles configurations de messagerie utiliseront par défaut le type de connexion `Direct SSL/TLS`
4. **Gestion des mots de passe serveur** - Vous pouvez désormais modifier les mots de passe serveur directement depuis la page de détails du serveur sans avoir besoin de recueillir à nouveau les sauvegardes

### Recommandations de configuration de la messagerie {/* #email-configuration-recommendations */}

- **Pour une utilisation en production** : Utilisez les connexions `STARTTLS` ou `Direct SSL/TLS` pour une livraison sécurisée de la messagerie
- **Pour les tests locaux** : Les connexions `Plain SMTP` sont disponibles pour les réseaux locaux de confiance
- **Exigence d'adresse d'expéditeur** : Lors de l'utilisation de `Plain SMTP` ou lorsque l'authentification est désactivée, assurez-vous que le champ `From Address` est correctement configuré
- **Testez votre configuration** : Utilisez toujours le bouton « Envoyer un e-mail de test » pour vérifier que votre configuration de messagerie fonctionne correctement

## Points de terminaison API {/* #api-endpoints */}

### Points de terminaison de configuration de la messagerie {/* #email-configuration-endpoints */}

- `GET /api/email/config` - Obtenir la configuration de la messagerie
- `POST /api/email/config` - Mettre à jour la configuration de la messagerie
- `POST /api/email/test` - Envoyer un e-mail de test
- `DELETE /api/email/config` - Supprimer la configuration de la messagerie

### Points de terminaison de gestion des serveurs {/* #server-management-endpoints */}

- `PATCH /api/servers/{id}/password` - Mettre à jour le mot de passe du serveur
- `POST /api/database/maintenance/merge-duplicate-servers` - Fusionner les serveurs en double
