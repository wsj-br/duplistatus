# Version 0.7.x {/* #version-07x */}

## Aperçu {/* #overview */}

La version 0.7.x est une version majeure qui introduit des améliorations significatives dans le schéma de la base de données, la structure de l'API et l'interface utilisateur. Cette version inclut des changements incompatibles avec les versions antérieures qui nécessitent des mises à jour des intégrations externes.

## Changements incompatibles {/* #breaking-changes */}

### Modifications du schéma de la base de données {/* #database-schema-changes */}
- **Renommage des tables** : table `machines` renommée en `servers`
- **Nouveaux champs** : ajout des champs `alias`, `notes`, `created_at` et `updated_at`
- **Modifications des réponses de l'API** : mise à jour des noms de champs pour plus de cohérence

### Modifications incompatibles de l'API {/* #backward-incompatible-api-changes */}
- **Renommage des champs** : `totalMachines` → `totalServers`
- **Renommage des objets** : `machine` → `server` dans les réponses de l'API
- **Renommage des champs** : `backup_types_count` → `backupJobsCount`

:::warning
**Les intégrations externes utilisant l'API doivent être mises à jour** pour fonctionner avec la version 0.7.x. Consultez le guide [Modifications incompatibles de l'API](../migration/api-changes) pour plus de détails.
:::

## Guide de migration {/* #migration-guide */}

### Migration automatique {/* #automatic-migration */}
La migration de 0.6.x à 0.7.x se fait automatiquement :

1. **Création de sauvegarde** : Une sauvegarde automatique de la base de données est créée
2. **Mise à jour du schéma** : Le schéma de la base de données est mis à jour automatiquement
3. **Migration des données** : Les données existantes sont préservées et migrées
4. **Vérification** : La migration est vérifiée et enregistrée

### Étapes manuelles requises {/* #manual-steps-required */}
- **Mise à jour des intégrations externes** : Mettre à jour les outils externes utilisant l'API
- **Tester la fonctionnalité** : Vérifier que toutes les fonctionnalités fonctionnent correctement
- **Mettre à jour la documentation** : Mettre à jour toute documentation personnalisée

## Modifications de configuration {/* #configuration-changes */}

### Nouvelles options de configuration {/* #new-configuration-options */}

```yaml
# Server management
servers:
  defaultAlias: true
  showNotes: true
  sortBy: "name" # name, status, lastBackup

# API settings
api:
  version: "1.0"
  rateLimit: 100
  timeout: 30000

# Database settings
database:
  backupRetention: 7
  autoVacuum: true
  optimizeInterval: 24
```

### Options obsolètes {/* #deprecated-options */}
- Configuration `machines` (utiliser `servers` à la place)
- Anciens noms de champs API (utiliser les nouveaux noms de champs)

```yaml

    image: wsjbr/duplistatus:0.7.x
```

## Instructions de mise à niveau {/* #upgrade-instructions */}

### À partir de la version 0.6.x {/* #from-version-06x */}
1. **Sauvegardez vos données** (sauvegarde automatique créée pendant la mise à niveau)
2. **Mettre à jour l'image Docker** : `docker pull wsjbr/duplistatus:0.7.x`
3. **Redémarrer le conteneur** : `docker-compose down && docker-compose up -d`
4. **Surveiller les journaux** : `docker logs -f duplistatus`
5. **Mettre à jour les intégrations** : Mettre à jour tous les outils externes utilisant l'API
6. **Vérifier la mise à niveau** : Vérifier que toutes les fonctionnalités fonctionnent correctement

### À partir de la version 0.5.x ou antérieure {/* #from-version-05x-or-earlier */}
1. **Mettre d'abord à niveau vers 0.6.x** (si disponible)
2. **Ensuite, mettre à niveau vers 0.7.x** en utilisant les étapes ci-dessus

## Problèmes connus {/* #known-issues */}

### Problèmes de migration {/* #migration-issues */}
- **Bases de données volumineuses** : La migration peut prendre plus de temps pour les grandes bases de données
- **Espace disque** : Assurez-vous qu'il y a suffisamment d'espace disque pour la sauvegarde de migration
- **Permissions** : Vérifier les permissions de fichier pour l'accès à la base de données

### Compatibilité de l'API {/* #api-compatibility */}
- **Outils externes** : Les outils externes utilisant l'API ont besoin de mises à jour
- **Noms de champs** : Certains noms de champs ont changé
- **Format de réponse** : Certains formats de réponse ont changé

### Solutions de contournement {/* #workarounds */}
- **Migration** : Assurez-vous qu'il y a suffisamment d'espace disque et de temps pour la migration
- **API** : Mettre à jour les intégrations externes pour utiliser le nouveau format d'API
- **Test** : Tester toutes les fonctionnalités après la mise à niveau
