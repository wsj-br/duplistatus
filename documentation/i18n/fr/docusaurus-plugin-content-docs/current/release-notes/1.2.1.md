# Version 1.2.1 {/* #version-121 */}

## Aperçu {/* #overview */}

La version 1.2.1 est une version mineure qui introduit des améliorations significatives à la gestion des notifications de sauvegarde, améliore les capacités de journalisation d'audit, corrige la détection de la prochaine exécution/en retard dans les cas limites et ajoute la fonctionnalité de sauvegarde et de restauration de la base de données. Cette version se concentre sur l'amélioration de l'expérience utilisateur avec les paramètres de notification.

## Nouvelles fonctionnalités {/* #new-features */}

### Gestion améliorée des notifications de sauvegarde {/* #enhanced-backup-notifications-management */}

- **Paramètres par défaut au niveau du serveur et système d'héritage** : Configurez les destinations supplémentaires par défaut (événements de notification, e-mails et sujets NTFY) au niveau du serveur que toutes les sauvegardes héritent automatiquement. Les sauvegardes peuvent remplacer ces valeurs par défaut lorsque nécessaire, avec des indicateurs visuels clairs montrant l'état d'héritage.
- **Hiérarchie visuelle améliorée** : Les sauvegardes sont maintenant regroupées par serveur avec des lignes d'en-tête distinctes pour chaque serveur. Les valeurs héritées sont clairement marquées avec des icônes de lien, et les valeurs remplacées peuvent être facilement réinitialisées à l'héritage.
- **Opérations groupées** : Le bouton "Synchroniser à tout" efface toutes les surcharges de sauvegarde pour que toutes les sauvegardes héritent des valeurs par défaut du serveur. Le bouton "Tout effacer" efface toutes les destinations supplémentaires tout en conservant la structure d'héritage.
- **Fonctionnalité de test** : Ajout de boutons de test d'e-mail et de test de notification directement dans la page des paramètres de notification de sauvegarde. Les boutons de test sont disponibles pour les paramètres de sauvegarde individuelle et les opérations d'édition groupée, permettant de vérifier la livraison des notifications avant d'appliquer les modifications.
- **Prise en charge des codes QR** : Ajout d'un bouton de code QR pour les sujets NTFY afin de partager facilement les sujets de notification avec les appareils mobiles.

### Améliorations des modèles de notification {/* #notification-template-enhancements */}

- **Nouvelle variable `{log_text}`** : Ajout de la variable `{log_text}` aux modèles de notification, permettant d'accéder aux messages de journalisation de texte pour les utiliser dans les messages de notification. La variable contient le texte complet des avertissements et des erreurs combinés, formaté en texte brut avec un élément par ligne.
- **Migration automatique des modèles** : Le système inclut un mécanisme de mise à niveau paresseux qui détecte automatiquement et met à jour les anciens modèles par défaut lorsqu'ils sont lus pour la première fois après une mise à jour. Les modèles personnalisés sont conservés inchangés.

### Gestion de la base de données {/* #database-management */}

- **Fonctionnalité de sauvegarde de la base de données** : Les administrateurs peuvent maintenant créer des sauvegardes de l'ensemble de la base de données à partir de la page des paramètres de maintenance de la base de données. Prise en charge des formats binaire (.db) et texte SQL (.sql) pour plus de flexibilité.
- **Fonctionnalité de restauration de la base de données** : Restaurez la base de données à partir de fichiers de sauvegarde précédemment créés avec création automatique de sauvegarde de sécurité, validation d'intégrité et retour en arrière en cas d'échec. Toutes les sessions sont effacées après la restauration pour des raisons de sécurité.

### Détection de la clé principale {/* #master-key-detection */}

- **Détection automatique du changement de clé principale** : Après la connexion, le système vérifie automatiquement si le fichier `.duplistatus.key` a changé. En cas de détection, tous les mots de passe chiffrés sont effacés et une fenêtre contextuelle informe les utilisateurs que les mots de passe doivent être reconfigurés. Cela évite les erreurs lors de la restauration à partir de sauvegardes ou de la migration vers un nouveau système.

### Améliorations de la surveillance des sauvegardes {/* #backup-monitoring-improvements */}

- **Export CSV amélioré** : Ajout de la colonne "Horodatage de la dernière sauvegarde (BDD)" dans le fichier CSV généré par le bouton "Télécharger CSV" dans les paramètres de surveillance des sauvegardes. Cela permet aux utilisateurs de comparer l'horodatage de la dernière sauvegarde réelle de la base de données avec l'horodatage "Dernière sauvegarde" configuré.
- **Info-bulle "Prochaine exécution"** : Survoler la valeur "Prochaine exécution" dans chaque ligne affiche maintenant une info-bulle montrant l'horodatage de la dernière sauvegarde de la base de données, formaté de la même manière que l'affichage "Prochaine exécution".

### Améliorations du journal d'audit {/* #audit-logging-enhancements */}

- **Entrées de journal d'audit de notification individuelles** : Chaque notification et e-mail envoyé génère maintenant une entrée de journal d'audit distincte avec des détails sur la chaîne, la configuration et le résultat (succès ou échec). Cela inclut les notifications de test, ce qui améliore la traçabilité de la livraison des notifications.
- **Journalisation robuste des échecs** : Toutes les opérations de journalisation d'audit pour les échecs de notification sont maintenant encapsulées dans des blocs try-catch pour empêcher les erreurs de journalisation d'audit de rompre les flux de notification. Le système tente de récupérer la configuration SMTP si elle n'est pas immédiatement disponible lors de la journalisation des échecs d'e-mail.
- **Journalisation d'audit améliorée pour les mises à jour de configuration** : Les entrées de journal d'audit pour `email_config_updated` et `ntfy_config_updated` ne s'enregistrent plus que lorsqu'il y a des modifications réelles de la configuration. Lorsqu'une modification est détectée, le journal d'audit inclut les anciennes et nouvelles valeurs pour chaque champ modifié, facilitant ainsi le suivi des changements spécifiques.

### Améliorations de la documentation {/* #documentation-improvements */}

- Le style de la documentation a été mis à jour pour s'aligner sur l'apparence de l'application. La barre latérale a également été révisée pour améliorer la visibilité et faciliter la navigation.

## 🐛 Correctifs de bogues {/* #-bug-fixes */}

- **Horodatages du journal d'audit corrigés** : Les horodatages dans la visionneuse de journaux d'audit s'affichent maintenant correctement dans le fuseau horaire du navigateur de l'utilisateur au lieu de GMT. Les horodatages SQLite (stockés en UTC) sont maintenant correctement analysés en UTC et convertis dans le fuseau horaire local du navigateur pour l'affichage.
- **Calcul et détection des retards corrigés** : La colonne "Prochaine exécution" dans les paramètres de surveillance des sauvegardes calcule et affiche maintenant correctement la prochaine date de sauvegarde prévue, en tenant compte à la fois de l'horaire de sauvegarde et de l'horodatage de la dernière sauvegarde. Cela s'applique à la fois aux tâches de sauvegarde programmées et exécutées manuellement, ce qui entraîne une détection plus fiable des retards.

## 🚀 Notes de migration {/* #-migration-notes */}

### Depuis la version 1.1.x {/* #from-version-11x */}

Lors de la mise à niveau vers la version 1.2.1 :

1. **Modèles de notification** : Le système mettra automatiquement à jour les modèles de notification par défaut pour inclure la nouvelle variable `{log_text}` la première fois qu'ils seront accédés après la mise à niveau. Les modèles personnalisés resteront inchangés. Si vous souhaitez utiliser la nouvelle variable `{log_text}` dans vos propres modèles, vous devrez les mettre à jour ou restaurer les modèles par défaut manuellement.

2. **Changements de clé principale** : Si vous restaurez à partir d'une sauvegarde ou migrez vers un nouveau système avec un fichier `.duplistatus.key` différent, le système détectera automatiquement cela et vous invitera à reconfigurer les mots de passe chiffrés (mots de passe SMTP et mots de passe du serveur Duplicati).

3. **Sauvegarde et restauration de la base de données** : La nouvelle fonctionnalité de sauvegarde et de restauration de la base de données est disponible dans la page des paramètres de maintenance de la base de données. Il est recommandé de créer une sauvegarde avant la mise à niveau, bien qu'aucune modification du schéma de la base de données ne soit requise pour cette version.

4. **Aucune migration de base de données requise** : Cette version ne nécessite aucune modification du schéma de la base de données.

## Points de terminaison API {/* #api-endpoints */}

Les points de terminaison d'API suivants ont été introduits dans cette version.

### Points de terminaison d'authentification et de sécurité {/* #authentication--security-endpoints */}

- `GET /api/auth/admin-must-change-password` - Vérifier si l'utilisateur administrateur doit changer de mot de passe

### Points de terminaison de gestion de la base de données {/* #database-management-endpoints */}

- `GET /api/database/backup` - Créer une sauvegarde de la base de données (format binaire ou SQL)
- `POST /api/database/restore` - Restaurer la base de données à partir d'un fichier de sauvegarde

### Points de terminaison de gestion des sauvegardes {/* #backup-management-endpoints */}

- `GET /api/backups/last-timestamps` - Obtenir les horodatages des dernières sauvegardes pour toutes les combinaisons serveur-sauvegarde
