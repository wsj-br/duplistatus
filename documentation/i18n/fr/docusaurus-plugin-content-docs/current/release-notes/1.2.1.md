# Version 1.2.1 {/* #version-121 */}

## Aperçu {/* #overview */}

La version 1.2.1 est une mise à jour mineure qui introduit des améliorations significatives dans la gestion des notifications de sauvegarde, améliore les capacités de journalisation des audits, corrige la détection de la prochaine exécution/en retard dans des cas particuliers et ajoute des fonctionnalités de sauvegarde et de restauration de base de données. Cette version se concentre sur l'amélioration de l'expérience utilisateur avec les paramètres de notification.

## Nouvelles fonctionnalités {/* #new-features */}

### Améliorations de la gestion des notifications de sauvegarde {/* #enhanced-backup-notifications-management */}

- **Valeurs par défaut au niveau du serveur et système d'héritage** : Configurer des destinations supplémentaires par défaut (événements de notification, e-mails et sujets NTFY) au niveau du serveur que toutes les sauvegardes héritent automatiquement. Les sauvegardes peuvent remplacer ces valeurs par défaut si nécessaire, avec des indicateurs visuels clairs montrant l'état de l'héritage.
- **Hiérarchie visuelle améliorée** : Les sauvegardes sont désormais regroupées par serveur avec des lignes d'en-tête de serveur distinctes. Les valeurs héritées sont clairement marquées avec des icônes de lien, et les valeurs remplacées peuvent être facilement rétablies à l'héritage.
- **Opérations groupées** : Le bouton "Synchroniser à tout" efface tous les remplacements de sauvegarde pour que toutes les sauvegardes héritent des valeurs par défaut du serveur. Le bouton "Tout effacer" efface toutes les destinations supplémentaires tout en maintenant la structure d'héritage.
- **Fonctionnalité de test** : Ajout de boutons de test par e-mail et de test de notification directement sur la page des paramètres de Notifications de sauvegarde. Les boutons de test sont disponibles pour les paramètres de sauvegarde individuels et les opérations d'édition groupée, vous permettant de vérifier la livraison des notifications avant d'appliquer les modifications.
- **Support des codes QR** : Ajout d'un bouton de code QR pour les sujets NTFY afin de partager facilement les sujets de notification avec des appareils mobiles.

### Améliorations des modèles de notification {/* #notification-template-enhancements */}

- **Nouvelle variable `{log_text}`** : Ajout de la variable `{log_text}` aux modèles de notification, fournissant un accès aux messages texte des journaux à utiliser dans les messages de notification. La variable contient le texte complet des avertissements et des erreurs combinés, formaté en texte brut avec un élément par ligne.
- **Migration automatique des modèles** : Le système comprend un mécanisme de mise à niveau paresseux qui détecte et met automatiquement à jour les anciens modèles par défaut lorsqu'ils sont lus pour la première fois après une mise à niveau. Les modèles personnalisés sont préservés sans changement.

### Gestion de la base de données {/* #database-management */}

- **Fonctionnalité de sauvegarde de la base de données** : Les administrateurs peuvent désormais créer des sauvegardes de l'ensemble de la base de données depuis la page des paramètres de Maintenance de la base de données. Prend en charge les formats binaire (.db) et texte SQL (.sql) pour plus de flexibilité.
- **Fonctionnalité de restauration de la base de données** : Restaurer la base de données à partir de fichiers de sauvegarde précédemment créés avec création automatique de sauvegarde de sécurité, validation de l'intégrité et retour en arrière en cas d'échec. Toutes les sessions sont effacées après la restauration pour des raisons de sécurité.

### Détection de la clé maître {/* #master-key-detection */}

- **Détection automatique des changements de clé maître** : Après la connexion, le système vérifie automatiquement si le fichier `.duplistatus.key` a changé. Si un changement est détecté, tous les mots de passe chiffrés sont effacés et une fenêtre modale informe les utilisateurs que les mots de passe doivent être reconfigurés. Cela empêche les erreurs lors de la restauration à partir de sauvegardes ou de la migration vers un nouveau système.

### Améliorations de la surveillance des sauvegardes {/* #backup-monitoring-improvements */}

- **Exportation CSV améliorée** : Ajout de la colonne "Horodatage de la dernière sauvegarde (DB)" au fichier CSV généré par le bouton "Télécharger CSV" dans les paramètres de surveillance des sauvegardes. Cela permet aux utilisateurs de comparer l'horodatage de la dernière sauvegarde réelle de la base de données avec l'horodatage de "Dernière sauvegarde" configuré.
- **Info-bulle Prochaine exécution** : Survoler la valeur "Prochaine exécution" dans chaque ligne affiche désormais une info-bulle montrant l'horodatage de la dernière sauvegarde de la base de données, formaté de la même manière que l'affichage de "Prochaine exécution".

### Améliorations de la journalisation d'audit {/* #audit-logging-enhancements */}

- **Entrées de journal d'audit de notification individuelle** : Chaque notification et e-mail envoyé génère désormais une entrée de journal d'audit distincte avec des détails sur la chaîne, la configuration et le résultat (succès ou échec). Cela inclut les notifications de test, offrant une meilleure traçabilité pour la livraison des notifications.
- **Journalisation des échecs robuste** : Toutes les opérations de journalisation d'audit pour les échecs de notification sont désormais enveloppées dans des blocs try-catch pour empêcher les erreurs de journalisation d'audit de casser les flux de notification. Le système tente de récupérer la configuration SMTP si elle n'est pas immédiatement disponible lors de la journalisation des échecs d'e-mail.
- **Amélioration de la journalisation d'audit pour les mises à jour de configuration** : Les entrées de journal d'audit `email_config_updated` et `ntfy_config_updated` enregistrent désormais uniquement lorsqu'il y a des changements réels dans la configuration. Lorsque des changements sont détectés, le journal d'audit inclut les anciennes et nouvelles valeurs pour chaque champ modifié, facilitant le suivi de ce qui a spécifiquement changé.

### Améliorations de la documentation {/* #documentation-improvements */}

- Le style de documentation a été mis à jour pour s'aligner sur l'apparence et la convivialité de l'application. La barre latérale a également été révisée pour améliorer la visibilité et faciliter la navigation.

## 🐛 Corrections de bogues {/* #-bug-fixes */}

- **Horodatages de journal d'audit corrigés** : Les horodatages dans la visionneuse de journaux d'audit affichent désormais correctement dans le fuseau horaire du navigateur de l'utilisateur au lieu de GMT. Les horodatages SQLite (stockés en UTC) sont désormais correctement analysés en tant qu'UTC et convertis au fuseau horaire local du navigateur pour l'affichage.
- **Calcul de "Prochaine exécution" corrigé et détection des retards** : La colonne "Prochaine exécution" dans les paramètres de surveillance des sauvegardes calcule et affiche désormais avec précision la prochaine date de sauvegarde attendue, en tenant compte à la fois du calendrier de sauvegarde et de l'horodatage de la dernière sauvegarde. Cela s'applique aux tâches de sauvegarde planifiées et exécutées manuellement, ce qui entraîne une détection des retards plus fiable.

## 🚀 Notes de migration {/* #-migration-notes */}

### À partir de la version 1.1.x {/* #from-version-11x */}

Lors de la mise à niveau vers la version 1.2.1 :

1. **Modèles de notification** : Le système mettra automatiquement à jour les modèles de notification par défaut pour inclure la nouvelle variable `{log_text}` la première fois qu'ils sont accessibles après la mise à niveau. Les modèles personnalisés resteront inchangés. Si vous souhaitez utiliser la nouvelle variable `{log_text}` dans vos propres modèles, vous devrez les mettre à jour ou restaurer les modèles par défaut manuellement.

2. **Changements de clé maîtresse** : Si vous restaurez à partir d'une sauvegarde ou migrez vers un nouveau système avec un fichier `.duplistatus.key` différent, le système détectera automatiquement cela et vous invitera à reconfigurer les mots de passe cryptés (mots de passe SMTP et mots de passe du serveur Duplicati).

3. **Sauvegarde/Restauration de base de données** : De nouvelles fonctionnalités de sauvegarde et de restauration de base de données sont disponibles dans la page des paramètres de maintenance de la base de données. Il est recommandé de créer une sauvegarde avant la mise à niveau, bien qu'aucun changement de schéma de base de données ne soit requis pour cette version.

4. **Aucune migration de base de données requise** : Cette version ne nécessite aucun changement de schéma de base de données.

## Points de terminaison API {/* #api-endpoints */}

Les points de terminaison API suivants ont été introduits dans cette version.

### Points de terminaison d'authentification et de sécurité {/* #authentication--security-endpoints */}

- `GET /api/auth/admin-must-change-password` - Vérifier si l'utilisateur administrateur doit changer de mot de passe

### Points de terminaison de gestion de base de données {/* #database-management-endpoints */}

- `GET /api/database/backup` - Créer une sauvegarde de la base de données (format binaire ou SQL)
- `POST /api/database/restore` - Restaurer la base de données à partir d'un fichier de sauvegarde

### Points de terminaison de gestion des sauvegardes {/* #backup-management-endpoints */}

- `GET /api/backups/last-timestamps` - Obtenir les horodatages de la dernière sauvegarde pour toutes les combinaisons serveur-sauvegarde
