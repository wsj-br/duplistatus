# Version 0.9.x {/* #version-09x */}

## Übersicht {/* #overview */}

Version 0.9.x ist eine Hauptversion, die ein umfassendes **Benutzerzugriffskontroll- und Sicherheitsystem** einführt. Diese Version wandelt **duplistatus** von einer Open-Access-Anwendung in ein sicheres, mehrbenutzerfähiges System mit rollenbasierter Zugriffskontrolle, umfassender Prüfprotokollierung und Sicherheitsfunktionen für Unternehmen um. Alle bestehenden Funktionen sind jetzt durch Authentifizierung geschützt und stellen sicher, dass nur autorisierte Benutzer auf die Backup-Überwachung zugreifen und verwalten können.

## Rückwärts-inkompatible Änderungen {/* #breaking-changes */}

### Authentifizierung erforderlich {/* #authentication-required */}

- **Alle Seiten erfordern jetzt Authentifizierung** - Benutzer müssen sich anmelden, um auf die Anwendung zugreifen zu können
- **Standard-Admin-Konto** wird automatisch erstellt:
  - Benutzername: `admin`
  - Passwort: `Duplistatus09` (muss beim ersten Anmelden geändert werden)
- **Bestehende Sitzungen werden ungültig gemacht** - Alle Benutzer müssen sich nach dem Upgrade anmelden
- **API-Endpunkte erfordern jetzt Authentifizierung** - Externe Integrationen müssen Sitzungs-Cookies enthalten oder authentifizierte Anfragen verwenden

:::warning
**Alle Benutzer müssen sich nach dem Upgrade auf Version 0.9.x anmelden.** Die Standard-Admin-Anmeldedaten sind admin/Duplistatus09. Ändern Sie das Passwort sofort nach der ersten Anmeldung.
:::

### Datenbankschema-Migration {/* #database-schema-migration */}

- **Automatische Migration von v3.1 zu v4.0** für bestehende Installationen
- **Neue Tabellen hinzugefügt**: `users`, `sessions`, `audit_log`
- **Datenbank-Backup wird automatisch erstellt** vor der Migration
- **Neue Installationen** starten direkt mit Schema v4.0 (keine Migration erforderlich)

## Neue Funktionen {/* #new-features */}

### Benutzerzugriffskontrolle & Sicherheitsystem {/* #user-access-control--security-system */}

#### Authentifizierungssystem {/* #authentication-system */}

- **Benutzer-Anmelde-/Abmeldefunktionen** mit sicherer Sitzungsverwaltung
- **Passwortbasierte Authentifizierung** mit bcrypt-Hashing (Kostenfaktor 12)
- **Kontosperrmechanismus** (5 fehlgeschlagene Versuche, 15-minütige Sperre)
- **Erzwungene Passwortänderung** beim ersten Anmelden
- **Passwortrichtlinien**:
  - Mindestens 8 Zeichen
  - Mindestens ein Großbuchstabe
  - Mindestens ein Kleinbuchstabe
  - Mindestens eine Zahl
  - Sonderzeichen optional
- **"Angemeldet bleiben"-Funktion** mit Benutzernamen-Persistenz in localStorage
- **Sitzungsbasierte Authentifizierung** mit datenbankgestützten Sitzungen (ersetzt in-memory)
- **CSRF-Schutz** integriert mit der Authentifizierung
- **HTTP-only-Cookies** für Sitzungssicherheit
- **IP-Adresse und Benutzer-Agent-Tracking** für Sicherheitsüberwachung

#### Benutzerverwaltung (nur Admin) {/* #user-management-admin-only */}

- **Benutzererstellung** mit automatischer temporärer Passwortgenerierung
- **Benutzerliste** mit Suche, Paginierung und Filterung
- **Benutzerbearbeitung** (Benutzername, Admin-Status, Passwortänderungspflicht)
- **Passwortzurücksetzfunktion** mit temporärem Passwortanzeige
- **Benutzerlöschung** mit Sicherheitsvorkehrungen (verhindert Löschung des letzten Admins)
- **Rollenbasierte Zugriffskontrolle** (Admin-/Benutzerrollen)
- **Statusanzeigen** (Aktiv, Gesperrt, Passwort muss geändert werden)
- **Letzte Anmeldung** und Anzeige

#### Prüfprotokollierungssystem {/* #audit-logging-system */}

- **Umfassende Prüfprotokollierung** für alle Systemänderungen und Benutzeraktionen
- **Prüfprotokoll-Viewer** mit erweiterter Filterung:
  - Datumsbereichsfilterung
  - Benutzerfilterung
  - Aktionsfilterung
  - Kategoriefilterung
  - Statusfilterung
- **Exportfunktion** (CSV- und JSON-Formate)
- **Audit-Protokoll-Statistiken** und Analysen
- **Konfigurierbare Aufbewahrungsdauer** (30–365 Tage, Standard: 90 Tage)
- **Automatische Bereinigung durch Cron-Job** (läuft täglich um 2 Uhr UTC)
- **Manuelle Bereinigungs-API** mit Dry-Run-Unterstützung
- **Audit-Protokollierung für**:
  - Authentifizierungsereignisse (Anmeldung, Abmeldung, Passwortänderungen, Sperrungen)
  - Benutzerverwaltungsoperationen (Erstellen, Aktualisieren, Löschen, Passwort-Zurücksetzungen)
  - Konfigurationsänderungen (E-Mail, NTFY, Vorlagen, Überfällig-Toleranz, Backup-Einstellungen)
  - Backup-Operationen (Sammeln, Löschen, Bereinigen)
  - Serververwaltung (Hinzufügen, Aktualisieren, Löschen)
  - Systemoperationen (Migrationen, Bereinigung, Benachrichtigungen)

### Neu designte Einstellungsseite {/* #settings-page-redesign */}

- **Moderne Seitenleisten-Navigation** mit einklappbarer Seitenleiste
- **Benutzerspezifische Seitenleisten-Zustands-Persistenz** (Zusammengeklappt/Erweitert-Einstellung gespeichert pro Benutzer)
- **Gruppierte Einstellungsabschnitte**:
  - **Benachrichtigungen**: Backup-Benachrichtigungen, Backup-Überwachung, Vorlagen
  - **Integrationen**: NTFY, E-Mail
  - **System**: Server, Benutzer (nur Admin), Audit-Protokoll
- **Feste Seitenleiste**, die beim Scrollen sichtbar bleibt
- **Responsive Design** mit optimiertem Abstand
- **Einstellungs-Symbol und "Systemeinstellungen"-Titel** im Seitenleisten-Header
- **Zurück-Button** in der App-Leiste integriert

### Benutzeroberflächenverbesserungen {/* #user-interface-enhancements */}

- **Eigenständige Anmeldeseite** mit modernem Design
- **"Angemeldet bleiben"-Checkbox** im Anmeldeformular für Benutzernamen-Persistenz
- **Anzeigen/Ausblenden-Buttons für Passwörter** in Anmelde- und Passwortänderungsformularen
- **Passwortänderungs-Modal** mit Echtzeit-Validierungs-Checkliste
- **Benutzerindikator und Abmelde-Button** in der App-Leiste
- **Rollenbasierte UI-Sichtbarkeit** (Admin-Funktionen vor regulären Benutzern versteckt)
- **Status-Badges und -Indikatoren** in der gesamten UI
- **Benutzerspezifische Einstellungen** in localStorage gespeichert (z. B. Zustand der Seitenleiste)

### Sicherheitsfunktionen {/* #security-features */}

- **Passworthashing** mit bcrypt (Branchenstandard)
- **Sensible Daten-Bereinigung** in Audit-Protokollen (Passwörter, Token, Geheimnisse werden nicht protokolliert)
- **Rate Limiting** für Anmeldeversuche
- **Sitzungsablauf** (24 Stunden)
- **CSRF-Token-Validierung** für alle statusändernden Operationen
- **Admin-Wiederherstellungs-CLI-Tool** für Passwort-Zurücksetzung bei Sperrung

### Entwickler-Tools {/* #developer-tools */}

- **Admin-Wiederherstellungs-CLI-Skript** (`admin-recovery`) für einfache Ausführung in Docker-Containern
- **Funktioniert sowohl lokal als auch in Docker** mit automatischer Pfad-Erkennung
- **Umfassende TypeScript-Schnittstellen** (keine `any`-Typen)
- **Authentifizierungs-Middleware** für Routen-Schutz
- **Audit-Protokollierer-Utility-Klasse** mit Bequemlichkeitsmethoden

## 🚀 Migrationshinweise {/* #-migration-notes */}

### Von Version 0.8.x {/* #from-version-08x */}

Diese Version führt Authentifizierung ein und erfordert, dass alle Benutzer sich anmelden. Beim Upgrade von Version 0.8.x:

1. **Automatische Datenbank-Migration**: Die Anwendung migriert automatisch das Datenbankschema von v3.1 auf v4.0
2. **Datenbank-Backup**: Ein automatisches Backup wird vor der Migration erstellt
3. **Standard-Admin-Konto**: Ein Standard-Admin-Konto wird erstellt:
   - Benutzername: `admin`
   - Passwort: `Duplistatus09`
   - **Sie müssen dieses Passwort beim ersten Anmelden ändern**
4. **Sitzungsinvalidierung**: Alle bestehenden Sitzungen werden ungültig gemacht
5. **Benutzer-Anmeldung erforderlich**: Alle Benutzer müssen sich nach dem Upgrade anmelden
6. **API-Authentifizierung**: Externe Integrationen müssen aktualisiert werden, um Authentifizierung einzuschließen

### Sicherheitsaspekte {/* #security-considerations */}

- **Standardpasswort ändern**: Ändern Sie das Standard-Admin-Passwort sofort nach der ersten Anmeldung
- **Benutzerkonten erstellen**: Erstellen Sie individuelle Benutzerkonten für jede Person, die Zugriff benötigt
- **Audit-Protokolle überprüfen**: Prüfen Sie die Audit-Protokolle regelmäßig zur Sicherheitsüberwachung
- **Aufbewahrung konfigurieren**: Legen Sie eine geeignete Prüfprotokoll-Aufbewahrungsdauer basierend auf Ihren Compliance-Anforderungen fest
- **Master-Schlüssel sichern**: Bei einem Upgrade von 0.8.x müssen Sie sicherstellen, dass die `.duplistatus.key`-Datei gesichert ist

### Erste Anmelde-Schritte {/* #first-login-steps */}

1. **Anmelden** mit Standardanmeldeinformationen (`admin` / `Duplistatus09`)
2. **Passwort ändern**, wenn Sie dazu aufgefordert werden (erzwungen bei der ersten Anmeldung)
3. **Benutzerkonten erstellen** für andere Benutzer (Einstellungen → Benutzer)
4. **Prüfprotokoll-Aufbewahrung konfigurieren**, falls nötig (Einstellungen → Prüfprotokoll)
5. **Prüfprotokolle überprüfen**, um zu überprüfen, ob das System korrekt funktioniert

## API-Endpunkte {/* #api-endpoints */}

### Authentifizierungs-Endpunkte {/* #authentication-endpoints */}

- `POST /api/auth/login` - Benutzerauthentifizierung
- `POST /api/auth/logout` - Sitzungsbeendigung
- `GET /api/auth/me` - Informationen zum aktuellen Benutzer
- `POST /api/auth/change-password` - Passwort ändern

### Benutzerverwaltungs-Endpunkte (nur Admin) {/* #user-management-endpoints-admin-only */}

- `GET /api/users` - Benutzer auflisten
- `POST /api/users` - Benutzer erstellen
- `PATCH /api/users/{id}` - Benutzer aktualisieren
- `DELETE /api/users/{id}` - Benutzer löschen

### Prüfprotokoll-Endpunkte {/* #audit-log-endpoints */}

- `GET /api/audit-log` - Prüfprotokolle abfragen
- `GET /api/audit-log/download` - Prüfprotokolle exportieren
- `GET /api/audit-log/stats` - Prüfprotokoll-Statistiken
- `POST /api/audit-log/cleanup` - Manuelle Bereinigung (nur Admin)
- `GET /api/audit-log/retention` - Aufbewahrungseinstellung abrufen
- `PATCH /api/audit-log/retention` - Aufbewahrung aktualisieren (nur Admin)

:::note
Alle API-Endpunkte erfordern jetzt Authentifizierung. Weitere Details zur Authentifizierung finden Sie in der [API-Referenz](../api-reference/authentication-security.md).
:::
