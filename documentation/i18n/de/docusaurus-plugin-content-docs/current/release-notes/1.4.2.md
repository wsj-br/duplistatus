# Version 1.4.2 {/* #version-142 */}

## Übersicht {/* #overview */}

Version 1.4.2 ist ein Wartungsrelease, das sich auf eine breitere Sprachunterstützung, Zuverlässigkeit und Abhängigkeitsverwaltung konzentriert. Es führt eine vollständig lokalisierte Benutzeroberfläche in vereinfachtem Chinesisch und Hindi ein, erweitert die Dokumentation auf sieben Sprachen und behebt einen wichtigen Absturz beim Start von Docker sowie mehrere Probleme beim Zusammenführen von Dashboards und Servern. Abhängigkeiten wurden ebenfalls aktualisiert, einschließlich eines großen Upgrades auf `nodemailer`.

---

## Neue Funktionen {/* #new-features */}

### Sprachunterstützung {/* #language-support */}

- **Benutzeroberfläche in vereinfachtem Chinesisch und Hindi**: Die Anwendungsoberfläche ist jetzt vollständig in vereinfachtem Chinesisch und Hindi verfügbar, neben Englisch, Französisch, Deutsch, Spanisch und Brasilianischem Portugiesisch. Wählen Sie diese im Sprachmenü in den Einstellungen aus.
- **Erweiterte Dokumentationssprachen**: Die Online-Dokumentation wird jetzt in sieben Sprachen veröffentlicht, wobei Hindi und vereinfachtes Chinesisch zu den bestehenden Übersetzungen hinzugefügt werden.

---

## Verbesserungen {/* #improvements */}

### Sicherungssammlung {/* #backup-collection */}

- **Stabile Serveridentität beim Sammeln von Protokollen**: Beim Sammeln von Sicherungsprotokollen stimmt duplistatus jetzt den Duplicati-Maschinenname mit Ihren vorhandenen Servern ab und verwendet den Datensatz dieses Servers erneut, anstatt sich auf die Maschinen-ID von Duplicati zu verlassen. Dadurch bleibt der Sicherungsverlauf dem gleichen Server zugeordnet, selbst wenn sich die Maschinen-ID von Duplicati ändert (zum Beispiel nach einer Neuinstallation), was doppelte Servereinträge reduziert.

### Dokumentation {/* #documentation */}

- **Aktuelle Sprachliste**: Die README und die Dokumentation beschreiben jetzt alle sieben unterstützten Sprachen und verlinken auf jede übersetzte Version.
- **Dokumentationssprachensymbolflaggen**: Hinzugefügte Flaggen-Icons für die neue Hindi- und vereinfachte Chinesisch-Dokumentation und die portugiesische Flagge wurde auf die Flagge von Portugal für Konsistenz umgeschaltet. Flaggen werden jetzt zuverlässig unter Windows, Linux und Chromium ohne externe Schriftarten-Downloads angezeigt.
- **Erweiterte Anleitung zu doppelten Servern**: Der Benutzerleitfaden erklärt jetzt beide Ursachen für doppelte Server (eine geänderte Duplicati-Maschinen-ID und einen Duplicati-API-Fehler, der die Identitäts-ID und die Maschinen-ID vermischt) und dokumentiert die Duplicati-seitige Umgehung zusammen mit dem Schritt zum Zusammenführen von duplistatus.

### Dashboard-Leistung {/* #dashboard-performance */}

- **Weniger Anmeldeprüfungen beim Laden**: Das Dashboard ruft jetzt Ihren aktuellen Benutzer einmal ab und teilt ihn über die Seite (Kopfzeile, Einstellungen, Design und Widgets) anstatt, dass jede Komponente ihn separat anfordert, wodurch redundante Anfragen beim Laden einer Seite reduziert werden.

---

## Fehlerbehebungen {/* #bug-fixes */}

- **Docker-Startabsturz**: Ein Absturz beim Start des Containers wurde behoben, der `Cannot find module '.../@swc/helpers/...'` meldete, was das Starten der Anwendung verhindern konnte. Container starten jetzt zuverlässig.
- **Doppelte Dashboard-Einträge**: Das Dashboard zeigt keine mehreren Zeilen für dasselbe Backup mehr an, wenn mehrere Datensätze dasselbe letzte Sicherungsdatum teilen.
- **Zusammenführen doppelter Server**: Das Zusammenführen von Servern konsolidiert jetzt auch doppelte Duplicati-Sicherungs-IDs, die denselben Sicherungsnamen teilen, wobei die ID von der letzten Sicherung beibehalten wird. Zusammenführungsoperationen werden jetzt im Audit-Protokoll aufgezeichnet.

---

## Sicherheit {/* #security */}

### Abhängigkeitsupdates {/* #dependency-updates */}

- **`nodemailer` auf 9.x aktualisiert**: Die E-Mail-Bibliothek wurde auf die neueste Hauptversion aktualisiert. Die einzige breaking change in v9 (striktere TLS-Validierung beim Abrufen von Remote-Anhängen, OAuth2 oder Proxy-Inhalten) betrifft nicht duplistatus, das nur Inline-Text und HTML-E-Mails sendet.
- **Weitere Abhängigkeitsupdates**: Mehrere Build- und Typabhängigkeiten wurden auf ihre neuesten kompatiblen Versionen aktualisiert.

## Migrationshinweise {/* #migration-notes */}

### Von Version 1.4.1 {/* #from-version-141 */}

Beim Upgrade auf Version 1.4.2:

1. **Keine Datenbankmigration erforderlich**: Dieses Release erfordert keine Änderungen am Datenbankschema.
2. **Abhängigkeiten**: Führen Sie `pnpm install` aus, um die aktualisierte Sperrdatei und Überschreibungen anzuwenden.
3. **Keine Konfigurationsänderungen erforderlich**: Bestehende Einstellungen, einschließlich Ihrer gewählten Sprache, werden beibehalten.

## Changelog {/* #changelog */}

### Änderungen in Version 1.4.2 {/* #version-142-changes */}

- **Hinzugefügt**: Vollständige chinesische (vereinfacht) und Hindi-Benutzeroberfläche.
- **Hinzugefügt**: Dokumentation jetzt in sieben Sprachen verfügbar, darunter Hindi und Chinesisch (vereinfacht).
- **Geändert**: Die Sicherungsprotokoll-Sammlung identifiziert Server nun über den Duplicati-Maschinenname (wiederverwendung bestehender Datensätze), wodurch die Historie erhalten bleibt, auch wenn die Maschinen-ID geändert wird.
- **Geändert**: Das Sprachmenü der Dokumentation enthält nun Flaggen für die neuen Standorte und verwendet die portugiesische Flagge für Portugiesisch.
- **Geändert**: Dokumentation und README aktualisiert, um die vollständige Liste der unterstützten Sprachen zu beschreiben, und die Problembehandlung bei doppelten Servern erweitert.
- **Geändert**: `nodemailer` auf 9.x aktualisiert und andere Build/Type-Abhängigkeiten aktualisiert.
- **Behoben**: Docker-Startabsturz durch ein fehlendes `@swc/helpers`-Modul.
- **Behoben**: Doppelte Dashboard-Einträge, wenn mehrere Sicherungen dasselbe letzte Datum teilen.
- **Behoben**: Zusammenführen doppelter Server konsolidiert nun doppelte Sicherungs-IDs und wird im Audit-Protokoll dokumentiert.
- **Behoben**: Reduzierte redundante Anmeldeprüfungen beim Laden des Dashboards.
