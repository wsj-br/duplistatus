Do zero ao monitoramento em quatro etapas

A implantação em contêineres significa que você está pronto e funcionando em minutos — não horas.

Passo 1

Implantar o contêiner

Baixe a imagem do Docker Hub ou GitHub, defina seu fuso horário e monte um volume de dados. A interface web escuta na porta 9666. As migrações de esquema são aplicadas automaticamente na inicialização. 

wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
docker compose -f duplistatus.yml up -d
Guia de instalação
Passo 2

Apontar o Duplicati para o duplistatus

Configure cada servidor Duplicati para enviar relatórios JSON via POST para /api/upload. Em seguida, colete logs históricos para que os intervalos de monitoramento sejam preenchidos automaticamente. 

--send-http-json-urls=http://host:9666/api/upload
--send-http-log-level=Information
--send-http-max-log-lines=500
Configuração do Duplicati
Passo 3

Configurar alertas

Defina filtros de notificação por tarefa (desativado / todos / avisos / erros), ative verificações de atraso e escolha notificações push ntfy ou e-mail SMTP. O Resumo Diário é opcional e apenas pausa e-mails para o destinatário padrão. 

Notifications:
  ntfy:   enabled
  email:  enabled
  filter: warnings + errors
  overdue: every 5 minutes
Configurações de notificação
Passo 4

Monitorar e solucionar problemas

Acompanhe o painel para verificar alterações de status, examine detalhadamente qualquer log de backup e use gráficos de tendências interativos para identificar anomalias. O serviço cron gerencia verificações de atraso, atualizações de versão e limpeza de logs em segundo plano. 

Dashboard:  all servers · all jobs
Last check: 2 min ago
Overdue:    0
Failures:   0

O duplistatus é um projeto independente e não é afiliado à equipe do Duplicati.

Comece em minutos

Faça o pull da imagem, monte um volume de dados e abra a porta 9666. As migrações de schema são executadas automaticamente na inicialização. 

# download the compose file
wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
# start the container
docker compose -f duplistatus.yml up -d
# duplistatus production compose.yml
services:
  duplistatus:
    image: ghcr.io/wsj-br/duplistatus:latest
    container_name: duplistatus
    restart: unless-stopped
    environment:
      - TZ=Europe/London
      - PWD_ENFORCE=true
      - PWD_MIN_LEN=8
    ports:
      - "9666:9666"
    volumes:
      - duplistatus_data:/app/data
    networks:
      - duplistatus_network

networks:
  duplistatus_network:
    driver: bridge

volumes:
  duplistatus_data:
    name: duplistatus_data
# Create the volume
docker volume create duplistatus_data

# Start the container
docker run -d \
  --name duplistatus \
  -p 9666:9666 \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -v duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest
mkdir -p ~/duplistatus_data
# Start the container (standalone)
podman run -d \
  --name duplistatus \
  --userns=keep-id \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -p 9666:9666 \
  -v ~/duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest

Depois que o contêiner iniciar:

  1. 1 Abra http://localhost:9666 no seu navegador
  2. 2 Entre com a conta de administrador padrão descrita no guia de instalação
  3. 3 Configure os seus servidores Duplicati para enviar relatórios de backup para /api/upload
  4. 4 Use Coletar Logs de Backup para importar o histórico e, em seguida, configure o ntfy ou SMTP se desejar alertas
  5. 5 Opcionalmente, ative as chaves de API e listas de permissões de IP para instalações expostas publicamente
