Conçu pour ceux qui exécutent Duplicati sur plusieurs machines

Qu'il s'agisse d'un NAS, d'un ordinateur portable, d'un VPS et de deux serveurs domestiques — duplistatus vous offre un endroit unique pour répondre à la seule question qui compte.

De zéro à opérationnel en quatre étapes

Le déploiement conteneurisé vous permet d'être opérationnel en quelques minutes, et non en plusieurs heures.

Étape 1

Déployer le conteneur

Récupérez l'image depuis Docker Hub ou GitHub, définissez votre fuseau horaire et montez un volume de données. L'interface utilisateur Web écoute sur le port 9666. Les migrations de schéma s'appliquent automatiquement au démarrage. 

wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
docker compose -f duplistatus.yml up -d
Guide d'installation
Étape 2

Pointez Duplicati vers duplistatus

Configurez chaque serveur Duplicati pour envoyer des rapports JSON via POST vers /api/upload. Ensuite, collectez l'historique des journaux afin que les intervalles de surveillance soient renseignés automatiquement. 

--send-http-json-urls=http://host:9666/api/upload
--send-http-log-level=Information
--send-http-max-log-lines=500
Configuration de Duplicati
Étape 3

Configurer les alertes

Définissez des filtres de notification par tâche (désactivé / tout / avertissements / erreurs), activez les vérifications d'éléments en retard et choisissez les notifications push ntfy ou les e-mails SMTP. Le Résumé quotidien est facultatif et suspend uniquement les e-mails envoyés au destinataire par défaut. 

Notifications:
  ntfy:   enabled
  email:  enabled
  filter: warnings + errors
  overdue: every 5 minutes
Paramètres de notification
Étape 4

Surveiller et dépanner

Surveillez les changements d'état sur le tableau de bord, examinez le journal de n'importe quelle sauvegarde et utilisez des graphiques de tendances interactifs pour repérer les anomalies. Le service cron gère les vérifications des éléments en retard, l'actualisation des versions et le nettoyage des journaux en arrière-plan. 

Dashboard:  all servers · all jobs
Last check: 2 min ago
Overdue:    0
Failures:   0

Démarrez en quelques minutes

Récupérez l'image, montez un volume de données et ouvrez le port 9666. Les migrations de schéma s'exécutent automatiquement au démarrage. 

# download the compose file
wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
# start the container
docker compose -f duplistatus.yml up -d
# duplistatus production compose.yml
services:
  duplistatus:
    image: ghcr.io/wsj-br/duplistatus:latest
    container_name: duplistatus
    restart: unless-stopped
    environment:
      - TZ=Europe/London
      - PWD_ENFORCE=true
      - PWD_MIN_LEN=8
    ports:
      - "9666:9666"
    volumes:
      - duplistatus_data:/app/data
    networks:
      - duplistatus_network

networks:
  duplistatus_network:
    driver: bridge

volumes:
  duplistatus_data:
    name: duplistatus_data
# Create the volume
docker volume create duplistatus_data

# Start the container
docker run -d \
  --name duplistatus \
  -p 9666:9666 \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -v duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest
mkdir -p ~/duplistatus_data
# Start the container (standalone)
podman run -d \
  --name duplistatus \
  --userns=keep-id \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -p 9666:9666 \
  -v ~/duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest

Une fois le conteneur démarré :

  1. 1 Ouvrez http://localhost:9666 dans votre navigateur
  2. 2 Connectez-vous avec le compte admin par défaut décrit dans le guide d'installation
  3. 3 Configurez vos serveurs Duplicati pour envoyer les rapports de sauvegarde vers /api/upload
  4. 4 Utilisez Collecter les journaux de sauvegarde pour importer l'historique, puis configurez ntfy ou SMTP si vous souhaitez des alertes
  5. 5 Activez éventuellement les clés API et les listes d'adresses IP autorisées pour les installations exposées publiquement
