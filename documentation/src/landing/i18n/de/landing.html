Die einzige Frage, auf die es ankommt

Sind alle meine Sicherungen in Ordnung? Ein Bildschirm beantwortet es – über jeden Server, jeden Auftrag, jeden Durchlauf hinweg.

Entwickelt für alle, die Duplicati auf mehreren Rechnern ausführen

In vier Schritten von null zur Überwachung

Dank containerisierter Bereitstellung sind Sie in wenigen Minuten startklar – nicht erst nach Stunden.

Schritt 1

Den Container bereitstellen

Laden Sie das Image von Docker Hub oder GitHub herunter, legen Sie Ihre Zeitzone fest und binden Sie ein Daten-Volume ein. Die Web-UI lauscht auf 9666. Schema-Migrationen werden beim Start automatisch angewendet. 

wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
docker compose -f duplistatus.yml up -d
Installationsanleitung
Schritt 2

Duplicati auf duplistatus ausrichten

Konfigurieren Sie jeden Duplicati-Server so, dass JSON-Berichte per POST an /api/upload gesendet werden. Sammeln Sie anschließend historische Protokolle, damit Überwachungsintervalle automatisch ausgefüllt werden. 

--send-http-json-urls=http://host:9666/api/upload
--send-http-log-level=Information
--send-http-max-log-lines=500
Duplicati-Konfiguration
Schritt 3

Benachrichtigungen konfigurieren

Legen Sie Benachrichtigungsfilter pro Auftrag fest (Aus / Alle / Warnungen / Fehler), aktivieren Sie Überprüfungen auf überfällige Sicherungen und wählen Sie NTFY-Push oder SMTP-E-Mail. Die Tägliche Zusammenfassung ist optional und pausiert nur E-Mails an den Standardempfänger. 

Notifications:
  ntfy:   enabled
  email:  enabled
  filter: warnings + errors
  overdue: every 5 minutes
Benachrichtigungseinstellungen
Schritt 4

Überwachen und Fehler beheben

Beobachten Sie das Dashboard auf Statusänderungen, analysieren Sie beliebige Sicherungsprotokolle und nutzen Sie interaktive Trenddiagramme, um Anomalien zu erkennen. Der Cron-Dienst übernimmt Überprüfungen auf überfällige Sicherungen, Versionsaktualisierungen und die Protokollbereinigung im Hintergrund. 

Dashboard:  all servers · all jobs

Overdue:    0
Failures:   0

Externe API-Schlüssel

Feingranulare Schlüssel für Duplicati-Uploads und schreibgeschützte externe Dashboards mit Beschränkungen für Upload-Größe und Rate.

Netzwerkbeschränkungen

Zwei unabhängige CIDR-Allowlists – eine für das Administrationsinterface, eine weitere für externe APIs. Trusted-Proxy-Anti-Spoofing enthalten.

CSRF-Schutz

Alle sitzungsbasierten Routen sind vor Cross-Site-Request-Forgery geschützt.

Audit-Protokollierung

Jede Konfigurationsänderung und Benutzeraktion wird erfasst, mit erweiterten Filterfunktionen, Export und konfigurierbarer Aufbewahrungsdauer.

Anwendungsprotokolle-Viewer

Interface nur für Admins zum Anzeigen, Durchsuchen und Exportieren von Anwendungsprotokollen mit Echtzeitüberwachung.

In wenigen Minuten loslegen

Image abrufen, ein Daten-Volume einbinden und Port 9666 öffnen. Schema-Migrationen werden beim Start automatisch ausgeführt. 

# download the compose file
wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
# start the container
docker compose -f duplistatus.yml up -d
# duplistatus production compose.yml
services:
  duplistatus:
    image: ghcr.io/wsj-br/duplistatus:latest
    container_name: duplistatus
    restart: unless-stopped
    environment:
      - TZ=Europe/London
      - PWD_ENFORCE=true
      - PWD_MIN_LEN=8
    ports:
      - "9666:9666"
    volumes:
      - duplistatus_data:/app/data
    networks:
      - duplistatus_network

networks:
  duplistatus_network:
    driver: bridge

volumes:
  duplistatus_data:
    name: duplistatus_data
# Create the volume
docker volume create duplistatus_data

# Start the container
docker run -d \
  --name duplistatus \
  -p 9666:9666 \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -v duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest
mkdir -p ~/duplistatus_data
# Start the container (standalone)
podman run -d \
  --name duplistatus \
  --userns=keep-id \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -p 9666:9666 \
  -v ~/duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest

Nachdem der Container gestartet wurde:

  1. 1 Öffnen Sie http://localhost:9666 in Ihrem Browser
  2. 2 Melden Sie sich mit dem im Installationsleitfaden beschriebenen Standard-Admin-Konto an
  3. 3 Konfigurieren Sie Ihre Duplicati-Server so, dass Sicherungsberichte an /api/upload gesendet werden
  4. 4 Verwenden Sie Backup-Protokolle sammeln, um den Verlauf zu importieren, und konfigurieren Sie anschließend NTFY oder SMTP, falls Sie Benachrichtigungen wünschen
  5. 5 Aktivieren Sie optional API-Schlüssel und IP-Zulassungslisten für öffentlich zugängliche Installationen
