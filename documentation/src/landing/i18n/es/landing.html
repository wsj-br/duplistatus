La única pregunta que importa

¿Están bien todas mis copias de seguridad? Una sola pantalla le da la respuesta: en cada servidor, cada tarea y cada ejecución.

localhost:9666

Diseñado para quienes ejecutan Duplicati en más de una máquina

Ya sea un NAS, un portátil, un VPS y dos servidores domésticos: duplistatus le ofrece un único lugar para responder a la única pregunta que importa.

De cero a monitorizado en cuatro pasos

El despliegue en contenedores significa que estará en funcionamiento en minutos, no en horas.

Paso 1

Desplegar el contenedor

Descargue la imagen desde Docker Hub o GitHub, configure su zona horaria y monte un volumen de datos. La interfaz web escucha en el puerto 9666. Las migraciones de esquema se aplican automáticamente al inicio. 

wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
docker compose -f duplistatus.yml up -d
Guía de instalación
Paso 2

Apuntar Duplicati a duplistatus

Configure cada servidor Duplicati para enviar informes JSON mediante POST a /api/upload. A continuación, recopile los registros históricos para que los intervalos de monitorización se completen automáticamente. 

--send-http-json-urls=http://host:9666/api/upload
--send-http-log-level=Information
--send-http-max-log-lines=500
Configuración de Duplicati
Paso 3

Configurar alertas

Establezca filtros de notificación por tarea (desactivado / todos / advertencias / errores), active las comprobaciones de vencimiento y elija notificaciones push de NTFY o correo electrónico por SMTP. El Resumen Diario es opcional y solo pausa los correos electrónicos al destinatario predeterminado. 

Notifications:
  ntfy:   enabled
  email:  enabled
  filter: warnings + errors
  overdue: every 5 minutes
Configuración de notificaciones
Paso 4

Monitorizar y solucionar problemas

Supervise los cambios de estado en el panel de control, examine en detalle cualquier registro de copia de seguridad y utilice gráficos interactivos de tendencias para detectar anomalías. El servicio cron gestiona las comprobaciones de vencimiento, las actualizaciones de versión y la limpieza de registros en segundo plano. 

Dashboard:  all servers · all jobs
Last check: 2 min ago
Overdue:    0
Failures:   0
Guía del usuario

El inicio de sesión siempre está activado. El refuerzo de seguridad es opcional.

Configuración sencilla en un homelab privado, con controles sólidos listos para cuando los necesite en una instalación accesible públicamente.

Inicio de sesión con roles

Inicios de sesión autenticados con roles de Administrador y Usuario. La visibilidad del Servidor se puede restringir por usuario.

Claves de API externas

Claves detalladas para subidas de Duplicati y paneles externos de solo lectura, con límites de tamaño de subida y frecuencia.

Restricciones de red

Dos listas de permitidos CIDR independientes: una para la interfaz de administración y otra para APIs externas. Protección contra falsificación mediante proxies de confianza incluida.

Protección CSRF

Todas las rutas basadas en sesiones están protegidas contra falsificación de peticiones en sitios cruzados (CSRF).

Registro de auditoría

Se registra cada cambio de configuración y acción de usuario, con filtrado avanzado, exportación y retención configurable.

Visor de Registros de Aplicación

Interfaz exclusiva para administradores para ver, buscar y exportar registros de la aplicación con monitorización en tiempo real.

Compatibilidad con múltiples idiomas

Interfaz y documentación en inglés, francés, alemán, español, portugués de Brasil, hindi y chino simplificado.

API de solo lectura

Empieza en cuestión de minutos

Descarga la imagen, monta un volumen de datos y abre el puerto 9666. Las migraciones de esquema se ejecutan automáticamente al inicio. 

# download the compose file
wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
# start the container
docker compose -f duplistatus.yml up -d
# duplistatus production compose.yml
services:
  duplistatus:
    image: ghcr.io/wsj-br/duplistatus:latest
    container_name: duplistatus
    restart: unless-stopped
    environment:
      - TZ=Europe/London
      - PWD_ENFORCE=true
      - PWD_MIN_LEN=8
    ports:
      - "9666:9666"
    volumes:
      - duplistatus_data:/app/data
    networks:
      - duplistatus_network

networks:
  duplistatus_network:
    driver: bridge

volumes:
  duplistatus_data:
    name: duplistatus_data
# Create the volume
docker volume create duplistatus_data

# Start the container
docker run -d \
  --name duplistatus \
  -p 9666:9666 \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -v duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest
mkdir -p ~/duplistatus_data
# Start the container (standalone)
podman run -d \
  --name duplistatus \
  --userns=keep-id \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -p 9666:9666 \
  -v ~/duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest

Después de que se inicie el contenedor:

  1. 1 Abra http://localhost:9666 en su navegador
  2. 2 Inicie sesión con la cuenta de administrador predeterminada descrita en la guía de instalación
  3. 3 Configure sus servidores de Duplicati para enviar informes de copias de seguridad a /api/upload
  4. 4 Utilice Recopilar registros de copias de seguridad para importar el historial y luego configure ntfy o SMTP si desea recibir alertas
  5. 5 Opcionalmente, active las claves de API y las listas de IP permitidas para instalaciones con acceso público
