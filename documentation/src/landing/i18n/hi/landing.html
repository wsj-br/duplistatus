प्रत्येक बैकअप। एक डैशबोर्ड।

प्रत्येक Duplicati वेब इंटरफ़ेस में एक-एक करके लॉग इन करना बंद करें। duplistatus एक ही स्क्रीन से प्रत्येक सर्वर और जॉब की निगरानी करता है — ताकि डेटा हानि से पहले ही आपको पता चल सके कि आपके बैकअप ठीक हैं।

duplistatus इंस्टॉल करें डैशबोर्ड देखें
मल्टी-सर्वर निगरानी ntfy और ईमेल अलर्ट लॉगिन आवश्यक, अतिरिक्त हार्डनिंग वैकल्पिक

एकमात्र सवाल जो मायने रखता है

क्या मेरे सभी बैकअप ठीक हैं? एक स्क्रीन इसका उत्तर देती है — प्रत्येक सर्वर, प्रत्येक जॉब, प्रत्येक रन में।

localhost:9666

उन लोगों के लिए निर्मित जो एक से अधिक मशीनों पर Duplicati चलाते हैं

चाहे वह NAS हो, कोई लैपटॉप, VPS, और दो होम सर्वर — duplistatus आपको एकमात्र महत्वपूर्ण सवाल का जवाब देने के लिए एक स्थान प्रदान करता है।

01

एक नज़र में प्रत्येक बैकअप देखें

एक ही डैशबोर्ड से प्रत्येक Duplicati सर्वर और जॉब की निगरानी करें। स्पष्ट स्थिति संकेतक, 10-रन स्थिति पट्टी वाले प्रति-सर्वर कार्ड, क्रमबद्ध करने योग्य तालिका दृश्य, और चेतावनियाँ और त्रुटियाँ के साथ व्यक्तिगत बैकअप लॉग का विवरण।

  • 10-रन स्थिति पट्टियों के साथ प्रति-सर्वर कार्ड
  • सभी सर्वर पर क्रमबद्ध करने योग्य तालिका दृश्य
  • व्यक्तिगत बैकअप लॉग का विस्तृत विवरण
  • नवीनतम GitHub रिलीज़ के साथ संस्करण तुलना
डैशबोर्ड गाइड पढ़ें
02

डेटा हानि बनने से पहले ही समस्याओं का पता लगाएं

अतिदेय, चेतावनी और विफल बैकअप का स्वचालित रूप से पता लगाएं। ntfy पुश या SMTP ईमेल के माध्यम से समय पर अलर्ट प्राप्त करें — प्रति-जॉब सूचना फ़िल्टर और एक निश्चित स्थानीय समय पर एक वैकल्पिक दैनिक सारांश ईमेल के साथ।

  • डिफ़ॉल्ट रूप से हर 5 मिनट में अतिदेय जाँच
  • प्रति-जॉब फ़िल्टर: बंद / सभी / चेतावनियाँ / त्रुटियाँ
  • ntfy पुश सूचनाएं और SMTP ईमेल
  • दैनिक सारांश केवल डिफ़ॉल्ट प्राप्तकर्ता को भेजे जाने वाले ईमेल को रोकता है
बैकअप निगरानी के बारे में पढ़ें
03

आत्मविश्वास के साथ समस्या निवारण करें

विफलताओं को समझने, पुनर्प्राप्ति बिंदुओं को सत्यापित करने और समय के साथ बैकअप को दुरुस्त रखने के लिए विस्तृत लॉग और इंटरैक्टिव प्रदर्शन रुझानों का उपयोग करें। चार्ट में अवधि, फ़ाइल गणना, फ़ाइल आकार, संग्रहण, अपलोड किया गया आकार और उपलब्ध संस्करण शामिल हैं।

  • इंटरैक्टिव चार्ट: अवधि, फ़ाइल गणना, आकार, संग्रहण
  • समान-दिन समेकन के साथ 1 सप्ताह से 3 महीने के रुझान
  • Duplicati सर्वर से स्वचालित लॉग संग्रह
  • पुनर्प्राप्ति बिंदुओं को सत्यापित करें और बैकअप स्थिति को ट्रैक करें
बैकअप मेट्रिक्स के बारे में पढ़ें

शून्य से निगरानी तक चार चरणों में

कंटेनरीकृत परिनियोजन का मतलब है कि आप मिनटों में तैयार और चालू हो जाते हैं — घंटों में नहीं।

चरण 1

कंटेनर परिनियोजित करें

Docker Hub या GitHub से इमेज पुल करें, अपना टाइमज़ोन सेट करें, और डेटा वॉल्यूम माउंट करें। वेब UI 9666 पर सुनता है। स्कीमा माइग्रेशन स्टार्टअप पर स्वचालित रूप से लागू होते हैं। 

wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
docker compose -f duplistatus.yml up -d
इंस्टॉलेशन गाइड
चरण 2

Duplicati को duplistatus पर इंगित करें

प्रत्येक Duplicati सर्वर को /api/upload पर JSON रिपोर्ट POST करने के लिए कॉन्फ़िगर करें। फिर ऐतिहासिक लॉग एकत्र करें ताकि निगरानी अंतराल स्वचालित रूप से भर जाएं। 

--send-http-json-urls=http://host:9666/api/upload
--send-http-log-level=Information
--send-http-max-log-lines=500
Duplicati कॉन्फ़िगरेशन
चरण 3

अलर्ट कॉन्फ़िगर करें

प्रति-कार्य सूचना फ़िल्टर (बंद / सभी / चेतावनियाँ / त्रुटियाँ) सेट करें, अतिदेय जाँच सक्षम करें, और NTFY पुश या SMTP ईमेल चुनें। दैनिक सारांश वैकल्पिक है और केवल डिफ़ॉल्ट प्राप्तकर्ता को ईमेल रोकता है। 

Notifications:
  ntfy:   enabled
  email:  enabled
  filter: warnings + errors
  overdue: every 5 minutes
सूचना सेटिंग्स
चरण 4

निगरानी करें और समस्या निवारण करें

स्थिति में परिवर्तनों के लिए डैशबोर्ड देखें, किसी भी बैकअप लॉग की विस्तृत जाँच करें, और विसंगतियों को पहचानने के लिए इंटरैक्टिव ट्रेंड चार्ट का उपयोग करें। cron सेवा बैकग्राउंड में अतिदेय जाँच, संस्करण रीफ़्रेश और लॉग सफ़ाई को संभालती है।

उपयोगकर्ता गाइड

लॉगिन हमेशा चालू रहता है। हार्डनिंग वैकल्पिक है।

निजी होमलैब में आसान सेटअप, सार्वजनिक इंस्टॉलेशन के लिए ज़रूरत पड़ने पर मज़बूत नियंत्रण तैयार हैं।

भूमिकाओं के साथ लॉगिन

एडमिन और उपयोगकर्ता भूमिकाओं के साथ प्रमाणित लॉगिन। सर्वर दृश्यता को प्रति उपयोगकर्ता सीमित किया जा सकता है।

बाहरी API कुंजियाँ

Duplicati अपलोड और केवल-पढ़ने योग्य बाहरी डैशबोर्ड के लिए फ़ाइन-ग्रेन्ड कुंजियाँ, अपलोड आकार और दर सीमाओं के साथ।

नेटवर्क प्रतिबंध

दो स्वतंत्र CIDR अनुमत सूचियाँ — एक एडमिन इंटरफ़ेस के लिए, दूसरी बाहरी API के लिए। ट्रस्टेड-प्रॉक्सी एंटी-स्पूफ़िंग शामिल।

CSRF सुरक्षा

सभी सेशन-आधारित रूट क्रॉस-साइट रिक्वेस्ट फ़ॉर्जरे (CSRF) से सुरक्षित हैं।

ऑडिट लॉगिंग

प्रत्येक कॉन्फ़िगरेशन परिवर्तन और उपयोगकर्ता कार्रवाई रिकॉर्ड की जाती है, उन्नत फ़िल्टरिंग, निर्यात और कॉन्फ़िगर करने योग्य अवधारण के साथ।

एप्लिकेशन लॉग व्यूअर

रीयल-टाइम मॉनिटरिंग के साथ एप्लिकेशन लॉग देखने, खोजने और निर्यात करने के लिए केवल-एडमिन इंटरफ़ेस।

बहुभाषी समर्थन

अंग्रेज़ी, फ़्रेंच, जर्मन, स्पैनिश, ब्राज़ीलियाई पुर्तगाली, हिंदी और सरलीकृत चीनी में इंटरफ़ेस और दस्तावेज़।

रीड-ओनली API

बाहरी डैशबोर्ड और विजेट रीड-ओनली API के माध्यम से समान बैकअप स्थिति जानकारी प्रदर्शित कर सकते हैं।

सेल्फ़-होस्टिंग समुदाय के लिए निर्मित

duplistatus ओपन सोर्स, सेल्फ़-होस्टेड है, और इसे होमलैब स्वामियों और छोटी टीम के सिस्टम एडमिनिस्ट्रेटर के वास्तविक काम करने के तरीके के अनुसार डिज़ाइन किया गया है।

GitHub पर ओपन सोर्स

पूर्ण स्रोत कोड, समस्याएँ (issues) और रिलीज़। बिना किसी वेंडर लॉक-इन के योगदान दें, फ़ॉर्क करें या सेल्फ़-होस्ट करें।

GitHub पर देखें

विस्तृत दस्तावेज़

सेटअप गाइड, कॉन्फ़िगरेशन संदर्भ, और सुरक्षा सुदृढ़ीकरण — सात भाषाओं में उपलब्ध।

क्रॉन सेवा संभालती है

अतिदेय जाँचें संस्करण रीफ्रेश करें दैनिक सारांश प्रेषण ऑडिट-लॉग क्लीनअप साप्ताहिक DB कॉम्पैक्ट

duplistatus एक स्वतंत्र प्रोजेक्ट है और Duplicati टीम से संबद्ध नहीं है।

कुछ ही मिनटों में शुरू करें

इमेज पुल करें, डेटा वॉल्यूम माउंट करें, और पोर्ट 9666 खोलें। स्कीमा माइग्रेशन स्टार्टअप पर स्वचालित रूप से चलते हैं। 

# download the compose file
wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
# start the container
docker compose -f duplistatus.yml up -d
# duplistatus production compose.yml
services:
  duplistatus:
    image: ghcr.io/wsj-br/duplistatus:latest
    container_name: duplistatus
    restart: unless-stopped
    environment:
      - TZ=Europe/London
      - PWD_ENFORCE=true
      - PWD_MIN_LEN=8
    ports:
      - "9666:9666"
    volumes:
      - duplistatus_data:/app/data
    networks:
      - duplistatus_network

networks:
  duplistatus_network:
    driver: bridge

volumes:
  duplistatus_data:
    name: duplistatus_data
# Create the volume
docker volume create duplistatus_data

# Start the container
docker run -d \
  --name duplistatus \
  -p 9666:9666 \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -v duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest
mkdir -p ~/duplistatus_data
# Start the container (standalone)
podman run -d \
  --name duplistatus \
  --userns=keep-id \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -p 9666:9666 \
  -v ~/duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest

कंटेनर शुरू होने के बाद:

  1. 1 अपने ब्राउज़र में http://localhost:9666 खोलें
  2. 2 इंस्टॉलेशन गाइड में बताए गए डिफ़ॉल्ट एडमिन खाते से लॉग इन करें
  3. 3 बैकअप रिपोर्ट /api/upload पर भेजने के लिए अपने Duplicati सर्वर कॉन्फ़िगर करें
  4. 4 इतिहास आयात करने के लिए बैकअप लॉग एकत्र करें का उपयोग करें, फिर यदि आप अलर्ट चाहते हैं तो ntfy या SMTP कॉन्फ़िगर करें
  5. 5 पब्लिक-फ़ेसिंग इंस्टॉलेशन के लिए वैकल्पिक रूप से API कुंजियाँ और IP allowlists सक्षम करें
