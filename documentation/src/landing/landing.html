From zero to monitored in four steps

Containerised deployment means you are up and running in minutes — not hours.

Step 1

Deploy the container

Pull the image from Docker Hub or GitHub, set your timezone, and mount a data volume. The web UI listens on port 9666. Schema migrations apply automatically on startup.

Get Started
Installation guide
Step 2

Point Duplicati at duplistatus

Configure each Duplicati server to POST JSON reports to /api/upload. Then collect historical logs so monitoring intervals are filled in automatically. 

--send-http-json-urls=http://host:9666/api/upload
--send-http-log-level=Information
--send-http-max-log-lines=500

Configure alerts

Let duplistatus watch your backups

User guide

Secure by default. Add more protection when you need it.

Login is on from the first start, so a private homelab is protected out of the box. Add API keys and IP allowlists when you expose it to the internet.

Login with roles

Sign in as Admin or User. Limit which servers each user can see.

API keys

Separate keys for Duplicati uploads and for read-only dashboards or widgets, with upload size and rate limits.

IP allowlists

Two independent allowlists: one for the admin interface, one for external APIs. They protect against spoofed client IPs when duplistatus runs behind a reverse proxy.

CSRF protection

Session-based routes are protected against cross-site request forgery.

Audit logging

Every configuration change and user action is recorded. Filter, export and set how long records are kept.

Application logs

An admin-only viewer lets you search, filter, and export application logs, with live updates.

Get started in minutes

Pull the image, mount a data volume, and open port 9666. 

# download the compose file
wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
# start the container
docker compose -f duplistatus.yml up -d
# duplistatus production compose.yml
services:
  duplistatus:
    image: ghcr.io/wsj-br/duplistatus:latest
    container_name: duplistatus
    restart: unless-stopped
    environment:
      - TZ=Europe/London
      - PWD_ENFORCE=true
      - PWD_MIN_LEN=8
    ports:
      - "9666:9666"
    volumes:
      - duplistatus_data:/app/data
    networks:
      - duplistatus_network

networks:
  duplistatus_network:
    driver: bridge

volumes:
  duplistatus_data:
    name: duplistatus_data
# Create the volume
docker volume create duplistatus_data

# Start the container
docker run -d \
  --name duplistatus \
  -p 9666:9666 \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -v duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest
mkdir -p ~/duplistatus_data
# Start the container (standalone)
podman run -d \
  --name duplistatus \
  --userns=keep-id \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -p 9666:9666 \
  -v ~/duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest

After the container starts:

  1. 1 Open http://localhost:9666 in your browser
  2. 2 Log in with the default admin account. You are asked to change the default admin password at first login.
  3. 3 Connect your Duplicati servers following these instructions, then use Collect Backup Logs to import history
  4. 4 Exposing it to the internet? Add more protection by enabling API keys and IP allowlists, and put it behind a reverse proxy with HTTPS.
