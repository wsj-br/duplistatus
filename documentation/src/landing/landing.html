From zero to monitored in four steps

Containerised deployment means you are up and running in minutes — not hours.

Step 1

Deploy the container

Pull the image from Docker Hub or GitHub, set your timezone, and mount a data volume. The web UI listens on 9666. Schema migrations apply automatically on startup. 

wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
docker compose -f duplistatus.yml up -d
Installation guide
Step 2

Point Duplicati at duplistatus

Configure each Duplicati server to POST JSON reports to /api/upload. Then collect historical logs so monitoring intervals are filled in automatically. 

--send-http-json-urls=http://host:9666/api/upload
--send-http-log-level=Information
--send-http-max-log-lines=500
Duplicati configuration
Step 3

Configure alerts

Set per-job notification filters (off / all / warnings / errors), enable overdue checks, and choose ntfy push or SMTP email. Daily Summary is optional and only pauses emails to the default recipient. 

Notifications:
  ntfy:   enabled
  email:  enabled
  filter: warnings + errors
  overdue: every 5 minutes
Notification settings
Step 4

Monitor and troubleshoot

Watch the dashboard for status changes, drill into any backup log, and use interactive trend charts to spot anomalies. The cron service handles overdue checks, version refreshes, and log cleanup in the background. 

Dashboard:  all servers · all jobs
Last check: 2 min ago
Overdue:    0
Failures:   0
User guide

Login is always on. Hardening is opt-in.

Easy setup in a private homelab, with strong controls ready when you need them for a public-facing installation.

Login with roles

Authenticated logins with Admin and User roles. Server visibility can be restricted per user.

External API keys

Fine-grained keys for Duplicati uploads and read-only external dashboards, with upload size and rate limits.

Network restrictions

Two independent CIDR allowlists — one for the admin interface, another for external APIs. Trusted-proxy anti-spoofing included.

CSRF protection

All session-based routes are protected against cross-site request forgery.

Audit logging

Every configuration change and user action is recorded, with advanced filtering, export, and configurable retention.

Application logs viewer

Admin-only interface to view, search, and export application logs with real-time monitoring.

Multi-language support

Interface and documentation in English, French, German, Spanish, Brazilian Portuguese, Hindi, and Simplified Chinese.

Read-only API

External dashboards and widgets can display the same backup status information via a read-only API.

Get started in minutes

Pull the image, mount a data volume, and open port 9666. Schema migrations run automatically on startup. 

# download the compose file
wget https://github.com/wsj-br/duplistatus/raw/refs/heads/master/production.yml -O duplistatus.yml
# start the container
docker compose -f duplistatus.yml up -d
# duplistatus production compose.yml
services:
  duplistatus:
    image: ghcr.io/wsj-br/duplistatus:latest
    container_name: duplistatus
    restart: unless-stopped
    environment:
      - TZ=Europe/London
      - PWD_ENFORCE=true
      - PWD_MIN_LEN=8
    ports:
      - "9666:9666"
    volumes:
      - duplistatus_data:/app/data
    networks:
      - duplistatus_network

networks:
  duplistatus_network:
    driver: bridge

volumes:
  duplistatus_data:
    name: duplistatus_data
# Create the volume
docker volume create duplistatus_data

# Start the container
docker run -d \
  --name duplistatus \
  -p 9666:9666 \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -v duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest
mkdir -p ~/duplistatus_data
# Start the container (standalone)
podman run -d \
  --name duplistatus \
  --userns=keep-id \
  -e TZ=Europe/London \
  -e LANG=en_GB \
  -p 9666:9666 \
  -v ~/duplistatus_data:/app/data \
  ghcr.io/wsj-br/duplistatus:latest

After the container starts:

  1. 1 Open http://localhost:9666 in your browser
  2. 2 Log in with the default admin account described in the installation guide
  3. 3 Configure your Duplicati servers to send backup reports to /api/upload
  4. 4 Use Collect Backup Logs to import history, then configure ntfy or SMTP if you want alerts
  5. 5 Optionally enable API keys and IP allowlists for public-facing installs
