**Instructions:** don't create new sections, be concise and only record user facing changes.

## Unreleased

### Fixed
- **Cron reload after settings save**: Browser `cronClient.reloadConfig()` now sends the session CSRF token, so `POST /api/cron/reload-config` no longer returns 403 when cron is running (`src/lib/cron-client.ts`).
- **Independent plural counts**: Split multi-count / multi-interpolation UI strings so each plural `t()` call uses only `{{count}}` (connection tests, collect-backups / collect-all toasts, truncated log message counts). See `documentation/docs/development/translation-workflow.md`.

### Added
- **IP allowlist deny logging**: Denied allowlist requests emit a rate-limited `console.warn` to application stdout (one per client IP and surface per minute, ten per hour) so Docker/container logs show probes without audit-log spam (`src/proxy.ts`, `documentation/docs/user-guide/settings/ip-allowlist-settings.md`).
- **Daily Summary public dashboard URL**: Optional **Public dashboard URL** on Settings → Daily Summary feeds `{duplistatus_link}` in summary emails. `DUPLISTATUS_PUBLIC_URL` overrides the saved value when set (`src/lib/public-url-utils.ts`, `src/lib/duplistatus-public-url.ts`, `src/components/settings/daily-summary-form.tsx`, `documentation/docs/user-guide/settings/daily-summary-settings.md`).
- **Daily Summary notifications**: Optional Settings → Daily Summary mode (off by default) sends one localized current-status snapshot by email at a saved `HH:mm` time and IANA timezone. While enabled, individual backup and overdue email messages (including additional email destinations) are suppressed; per-job NTFY continues. Per-job settings stay stored and resume when the mode is off. Schema **4.2** adds the `daily_summary_deliveries` ledger (`src/lib/db-migrations.ts`, `src/lib/daily-summary.ts`, `src/components/settings/daily-summary-form.tsx`, `documentation/docs/user-guide/settings/daily-summary-settings.md`).

### Added
- **API keys and IP allowlists for external APIs (issue #79)**: Administrators can create scoped `upload` / `read` API keys (optional, off by default) and two independent CIDR allowlists (admin UI vs `/api/upload`, `/api/summary`, `/api/lastbackup*`). Keys are SHA-256 hashed; the secret is shown once and later identified by a `Qk7v…3xTa` fingerprint in Settings and the audit log. `/api/upload` also has a configurable body-size cap (default 5 MB) and per-IP rate limits. TCP peer addresses come from `scripts/peer-ip.cjs` so `X-Forwarded-For` cannot be spoofed unless the peer is a trusted proxy. Credits [henmohr](https://github.com/henmohr) / LibreCodeCoop ([`1c5d46a`](https://github.com/LibreCodeCoop/duplistatus/commit/1c5d46ab0c9c7e2224714a7aa9dfed37cc3d2555)), rewritten for 1.5.0 rather than cherry-picked.
- **Keep relative time in the UI language (issue #74)**: Display Settings → Format Locale has an opt-in checkbox (off by default) so relative-time phrases stay in the UI language when Format Locale is overridden. The live preview includes a Relative sample. Dates, times, and numbers still follow Format Locale (`src/contexts/config-context.tsx`, `src/components/settings/display-settings-form.tsx`).
- **Dependabot ignores for override-managed transitives**: Added `.github/dependabot.yml` so GitHub Dependabot skips doomed security-update jobs for `browserslist`, `dompurify`, `fast-uri`, `js-yaml`, `nanoid`, `postcss`, and `qs` (already floored via `pnpm-workspace.yaml` overrides). Scheduled version-update PRs stay off (`open-pull-requests-limit: 0`); security alerts can still appear.
- **Duplicati version settings**: Settings includes a **Duplicati Versions** tab that shows the cached latest release for each channel (`stable`, `beta`, `experimental`, `canary`) and the last successful GitHub update. Administrators can choose a daily, 12-hour, or 6-hour check interval and a start hour displayed in the browser timezone (stored and executed in UTC). A force-update button refreshes the cache immediately without requiring the cron service. Regular users can view the cache; only administrators can change the schedule or force a refresh. Schedule changes write `duplicati_version_check_updated` to the audit log; GitHub refreshes continue to write `duplicati_version_refresh` with `startup`, `cron`, or `manual`. The Settings → Servers table now shows the same Version badge and tooltip as the dashboard, immediately before the web interface address (`src/components/settings/duplicati-version-settings-form.tsx`, `src/app/api/configuration/duplicati-versions/`).

The dashboard table Version column is always shown (`src/contexts/config-context.tsx`, `src/components/settings/display-settings-form.tsx`).
- **Duplicati server version tracking**: Dashboard cards and the table view now show the Duplicati version from each server’s latest backup (`backend_version`). The version is compared to the latest release for that channel (`stable`, `beta`, `experimental`, `canary`) using the GitHub Releases API. Current versions use muted text; outdated versions use warning yellow. A tooltip shows the channel, server version, and latest available channel version. Latest channel versions are cached in the `configurations` table (`duplicati_versions`), refreshed daily at 3 AM UTC by the `duplicati-version-refresh` cron task, and refreshed on startup when the cache is older than 24 hours. Failed refreshes keep the last cached versions (`src/lib/duplicati-version.ts`, `src/lib/duplicati-version-service.ts`, `src/cron-service/service.ts`, `src/instrumentation-node.server.ts`). Successful and failed GitHub updates write a `duplicati_version_refresh` system audit log with `trigger` `startup` or `cron`. English docs cover the feature in `documentation/docs/user-guide/dashboard.md` (including that the dashboard version updates only when a new backup log is received or collected), `documentation/docs/user-guide/collect-backup-logs.md`, `documentation/docs/user-guide/overview.md`, and `documentation/docs/intro.md`.

- **Cron service crash on startup (production Docker)**: The bundled cron service (`dist/cron-service.cjs`) exited immediately with `TypeError [ERR_INVALID_ARG_TYPE]: The "path" argument must be of type string ... Received undefined` at `fileURLToPath`. `node-cron`'s ESM build evaluates `fileURLToPath(import.meta.url)` at module top level, but esbuild's CJS output replaces `import.meta` with `{}`, leaving `import.meta.url` undefined. `scripts/bundle-cron-service.cjs` now defines `import.meta.url` (via an esbuild `define` + `banner`) to the bundle's own file URL, so this and any similar dependency resolve to a valid path.

### Security
- **Cron service bind and secret**: The dispatcher that can send email binds to `127.0.0.1` by default. Mutating cron-service routes check `X-Cron-Service-Secret` when `CRON_SERVICE_SECRET` is set (`src/cron-service/service.ts`).
- **Notification template HTML**: Email bodies no longer pass through unsanitized HTML. Markdown is parsed with raw HTML disabled and sanitized before sending (`src/lib/notification-template-renderer.ts`).
- **External API threat model (issue #79)**: Anyone who can reach `POST /api/upload` can inject fake backups or flood the server. The new optional keys, IP allowlists, upload size cap, and rate limits close that gap without breaking existing Duplicati jobs (all controls default off). `/api/health` and `/api/ping` stay reachable for Docker health checks.
- **pnpm audit (documentation workspace)**: Cleared 8 findings (4 high, 4 moderate). Forced `undici@8.10.1` and `svgo@4.1.0` because range overrides were not rematching lockfile pins (`cheerio` → `undici@8.5.0`, `postcss-svgo` / `@svgr/plugin-svgo` → `svgo@4.0.1`). ## [1.4.2] - 2026-06-24

### Changed
- **Backup collection server identity**: When collecting backup logs (`src/app/api/backups/collect/route.ts`), the server is now identified by matching the Duplicati `MachineName` against existing records in the `servers` table and reusing that record's id, instead of always using the `machine-id` from `/api/v1/systeminfo`. The `machine-id` is only used as a fallback when no server with that name exists. When several servers share a name, the most recently created one is used. This keeps backup history attached to the same server even if Duplicati's `machine-id` changes (e.g. after a reinstall).
- **Documentation (duplicate servers)**: Expanded the duplicated-servers guidance in the user guide. `documentation/docs/user-guide/troubleshooting.md` now documents the second cause (a Duplicati API bug where some endpoints mix the `identity` id and `machine_id`) alongside the existing `machine_id`-change cause, and adds the Duplicati-side workaround (align `identity.txt`/`machineid.txt` or set Settings → Advanced Options → Machine-id, then restart) plus the duplistatus merge step. Added a cross-referencing note in `documentation/docs/user-guide/collect-backup-logs.md`.
- **Docker build pnpm version + CI checkout**: `Dockerfile` now installs `pnpm@latest-11` (both `deps` and `builder` stages) to match the `packageManager` pin (`pnpm@11.8.0`) instead of the older `pnpm@latest-10`. Bumped `actions/checkout` from `v6` to `v7` in `.github/workflows/docker-image.yml`.
- **Screenshot automation now uses Playwright (`pnpm take-screenshots`)**: Replaced Puppeteer with Playwright's Chromium in `scripts/take-screenshots.ts`. The browser binary is no longer downloaded automatically on `pnpm install`; install it once with the new `pnpm take-screenshots:install` script (runs `playwright install chromium`).
